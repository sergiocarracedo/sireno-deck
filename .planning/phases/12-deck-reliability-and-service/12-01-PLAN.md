# Plan 12-01: System-status migration to generic button

<objective>
Port the legacy `builtinSystemStatusButton.tsx` generic button to sireno-deck-2's current addon API, fold the four split metric topics (CPU/RAM/disk/net) into one channel, and remove the legacy split registrations. After this plan, a user-deck `button: { type: "system-status", config: { metrics: ["cpu", "ram", "battery"] } }` renders three live rows on the emulator and the unavailable caption for any metric the host cannot probe.
</objective>

</files>
<action>
1. Replace `frontend.tsx` with a renderer that:
   - Subscribes to `runtime:system-status:<metricId>` events for each metric in `config.metrics`.
   - For each metric row, displays the metric label (Title-Case of the metric id) and the formatted value using either `display === 'text'` (label + formatted value on one line) or `display === 'bars'` (label + horizontal bar of value/max with width derived from container width).
   - When the event payload has `value === null`, renders the legacy unavailable caption `'—'` followed by the `unavailableReason`.
   - Uses the per-metric formatter override from `config.formatters[metricId]` if present, else falls back to the catalog default formatter.
   - Re-renders on a `setInterval(config.renderInterval)` ticker AND on incoming events.
2. Add `// ponytail: renderInterval is the only manual poll — event-driven push wins when it arrives sooner` comment near the timer.
</action>

# Plan 71-01: Real-hardware profile + fix for system back button delay (BUG-01)

## Context

v1.6 PERF-01 measured the back-pop transition at 12.35ms in-process and called the requirement satisfied. The user reports the **settings-deck → previous-deck landing** still feels delayed, and source review confirms the in-process number never measured this transition. The root cause is in the same gesture handler that BUG-02 lives in: `createSystemBackHandlers` always wires an `onDblTap` (to handle the dismiss-overlay case), which forces the dispatcher at runtime.ts:1739-1754 to debounce every back press for DOUBLE_TAP_DELAY_MS=400ms before firing onTap. The fix is to skip the dbltap debounce when there is no overlay context to dismiss, but we need a real-hardware profile trace first to (a) confirm this is the actual bottleneck and (b) set the per-direction target from data rather than guessing. The same profile instrumentation will catch any other latent bottleneck in the path.

## Tasks

### Task 1: Add env-var-gated profile helper

**file:** packages/cli/src/util/profile.ts (new) + packages/cli/src/config/env.ts
**action:**
- Create `packages/cli/src/util/profile.ts` exporting a `profileBackTransition(direction: 'back-from-settings' | 'settings-deck-landing', label: string)` helper that no-ops unless BOTH `process.env.SIRENO_PROFILE === '1'` AND `process.env.SIRENO_PROFILE_BACK_TRANSITIONS === '1'`. The sub-flag pattern matches the opt-in-env-var-instrumentation-pattern solution: a single `SIRENO_PROFILE` gate shared with the existing `browser-renderer.ts:76` user, plus per-concern sub-flags.
- When enabled, the helper uses `process.hrtime.bigint()` (nanosecond precision, matches the solution) to record hop timestamps, writing JSON lines to stdout in the form `{"dir":"back-from-settings","hop":"onTap-fired","t_ns":123456789}`. The user redirects to a log file when capturing.
- The helper exposes a `hop(name: string)` method that the dispatcher can call at each known boundary (e.g. `keyReleased`, `onTap-fired`, `navigateToDeck-invoke`, `activateDeckSurface-invoke`, `browser-capture-invoke`, `screen-flush-done`).
- Register `SIRENO_PROFILE_BACK_TRANSITIONS` in `packages/cli/src/config/env.ts` as a boolean sub-flag.
- Confirm zero perf cost when env vars are not set (no allocation in hot path; helper is a single boolean check).
**verify:** `SIRENO_PROFILE=1 SIRENO_PROFILE_BACK_TRANSITIONS=1 pnpm --filter @sireno-deck/cli run start -- --emulator 2>&1 | tee /tmp/sireno-back.log` — pressing back from the settings deck writes JSON lines to stdout. Default run (env vars unset) writes nothing and `top` shows no measurable CPU increase.
**done:** Helper module + env var registration + zero-overhead default path.

### Task 4: Implement the fix in createSystemBackHandlers

**file:** packages/cli/src/deck/runtime.ts (createSystemBackHandlers at lines 1124-1186, with `onDblTap` default at 1176-1184)
**action:**
- Modify `createSystemBackHandlers` to omit the `onDblTap` return when BOTH `pendingOverlayDeck` is null AND `lastDismissedOverlayDeckId` is null. In that "no overlay context" case, the gesture dispatcher will not debounce, and `onTap` will fire immediately.
- The dbltap debounce is preserved in two cases: (a) `pendingOverlayDeck !== null` (active overlay) and (b) `lastDismissedOverlayDeckId !== null` (overlay was just dismissed, user might want to re-summon).
- Verify the dbltap still fires correctly in the overlay case by re-reading the `handleDblTap` and `dismissOverlay` paths.
- After Plan 71-02's refactor, the new `dispatchGestureEnd` helper handles the "no onDblTap" case (case 3 in the helper) by scheduling onTap after `DOUBLE_TAP_DELAY_MS` and suppressing the second-press-onTap firing — but the system back button still does NOT need that delay when there's no overlay context, so the conditional omission in `createSystemBackHandlers` is the right fix.
**verify:** Reading the updated function: when no overlay context, the returned handlers object has no `onDblTap` property. With overlay context, it does.
**done:** Conditional onDblTap wiring — system back is no longer debounced when there is no overlay context.

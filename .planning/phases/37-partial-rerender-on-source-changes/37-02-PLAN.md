## Tasks

### 37-02-01: Implement CSS-only reload path

- **file**: `packages/cli/src/cli/commands/start.ts`
- **action**: |
    Modify `watchAddonSources` to classify changes by file extension before triggering the registry-diff path:
    1. Accept a `onNonConfigChange: () => void` callback alongside `onChange`
    2. Inside the watch callback (before debounce scheduling), check the changed file extension:
       - If `.css` file changed: call `reloadStylesheet()` instead of scheduling `scheduleAddonReload()`
       - Otherwise: schedule `scheduleAddonReload()` as normal
    3. Add `reloadStylesheet(): void` that calls `runtime.reloadStylesheet()` (new method — see 37-02-02)
    The CSS classification happens before debounce to keep CSS handling fast.
- **verify**: `grep -n '\.css' packages/cli/src/cli/commands/start.ts`
- **done**: When CSS file changes skip the 100ms debounce and call `reloadStylesheet()` directly.

### 37-02-02: Add reloadStylesheet to DeckRuntime

- **file**: `packages/cli/src/deck/runtime.ts`
- **action**: |
    Add `reloadStylesheet(): void` to `DeckRuntime` interface and implement it in `createDeckRuntime`. This method should call the browser transport's stylesheet reload seam:
    1. If a browser renderer is active: call `browserRenderer.reloadStylesheet()` (or post a reload message to the browser page)
    2. If no browser renderer (headless or emulator-only): no-op, log at `debug` level
    3. Do NOT call `invalidateMountedStore()` — CSS changes don't require a deck re-render
    Inspect `browserRenderer` in `runtime.ts` to find the appropriate reload message seam. Use the same message-passing approach already used for `showTemporaryErrorDeck`.
- **verify**: `grep -n 'reloadStylesheet' packages/cli/src/deck/runtime.ts packages/cli/src/render/browser-renderer.ts`
- **done**: When `reloadStylesheet()` exists, calls the browser transport reload seam, and does not trigger `invalidateMountedStore()`.

### 37-02-03: Wire structural fallback to reloadRuntime

- **file**: `packages/cli/src/deck/runtime.ts`
- **action**: |
    In `updateAddonRegistry`, when a structural change is detected:
    1. Call `logger.warn({ added, removed }, 'addon registry structural change — falling back to full reloadRuntime')`
    2. Instead of directly calling `reloadRuntime()` here (which is owned by start.ts), emit a `runtime:reload-required` event or call a new `runtime.requestFullReload()` method that signals to start.ts that a full reload is needed
    3. In `start.ts`, add a handler for `runtime:reload-required` that calls `void reloadRuntime()` (the same debounced reload path used for config changes)
    This preserves the existing reload-in-flight/queued semantics rather than bypassing them.
- **verify**: `grep -n 'requestFullReload\|reload-required\|structural' packages/cli/src/deck/runtime.ts packages/cli/src/cli/commands/start.ts`
- **done**: When structural changes trigger `requestFullReload()` and start.ts handles it via `reloadRuntime()`.

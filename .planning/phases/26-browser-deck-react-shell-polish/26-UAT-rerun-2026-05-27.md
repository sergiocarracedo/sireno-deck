So the user is seeing exactly what the code intentionally builds, not an unexpected crop or handoff artifact.
**Code path:** `start.ts:writePlaceholderDeckSurface(...)` -> `startup-placeholder.ts:createStartupPlaceholderBuffers(...)` -> `createStartupPlaceholderDeckBuffer(...)` -> composite overlay SVG + logo + accent bar -> per-key crops written to device
**Root cause:** `packages/cli/src/render/startup-placeholder.ts` still encodes extra branded shell/card/label overlay elements in `createStartupPlaceholderOverlaySvg(...)` and the accent-bar composite, which contradicts the stricter rerun expectation that startup should show only the full-deck `logoFull.png` image and nothing else.
**Evidence:**

## Root Cause

**Location:** `packages/cli/src/render/startup-placeholder.ts:12-45` and `packages/cli/src/render/startup-placeholder.ts:81-99`
**Cause:** The startup placeholder composition still intentionally draws additional shell/card/accent/`STARTING` overlay artwork on top of the deck-wide `logoFull.png` image.
**Why it produces the symptom:** The pre-browser placeholder path writes exactly the buffers produced by `createStartupPlaceholderBuffers(...)`. Because those buffers are built from `logoFull.png` plus extra overlay graphics, the user sees a branded composition with other elements instead of only the full-deck logo image.
**Confidence:** high

## Proposed Fix

**Approach:** Keep the existing pre-browser placeholder seam and deck-wide cropping logic, but simplify the placeholder composition so the generated deck buffer is only the full-deck `logoFull.png` treatment against the background, with no extra shell/card/label/accent overlay artwork.
**Files to change:**
- `packages/cli/src/render/startup-placeholder.ts`: remove the overlay SVG and accent-bar composition, leaving only deck-wide `logoFull.png` placement and per-key cropping.
- `packages/cli/src/render/startup-placeholder.test.ts`: extend focused coverage so the placeholder proves deck-wide non-repeating output while no longer depending on extra overlay markers.

**Risk:** low. The seam ownership should remain unchanged; the main risk is making the logo too small or too low-contrast once the overlay artwork is removed, so sizing/fit should be verified against the actual hardware/browser-visible result.

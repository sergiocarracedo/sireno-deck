# Phase 08 Plan 02: `light` theme as thin override

**Wave:** 2
**Depends on:** Plan 01
**Goal:** Ship the `light` built-in theme as a thin override of the `default` theme, plus CLI wiring to send the active theme name over the `deck-config` WS message.

---

## Tasks

### Task 1: Built-in `light` theme — manifest

- File: `packages/cli/src/themes/light/manifest.yml` (new)
- Fields: `name: light`, `kind: theme`, `apiVersion: 3`, `frontend: ./index.tsx`, `css: ./theme.css`.

### Task 2: Built-in `light` theme — `theme.css`

- File: `packages/cli/src/themes/light/theme.css` (new)
- Two blocks (inverse of `default`):
  - `@media (prefers-color-scheme: light) { :root { @theme { --color-bg: #fafafa; --color-fg: #0a0a0a; --color-accent: #0284c7; --color-ring: #0a0a0a; --color-tap: #0284c7; --color-muted: #525252; --color-bar: #e5e5e5; --color-bar-accent: #0284c7; --font-mono: 'JetBrains Mono', monospace; } } }`
  - `@media (prefers-color-scheme: dark) { :root { @theme { --color-bg: #0a0a0a; --color-fg: #fafafa; --color-accent: #38bdf8; --color-ring: #fafafa; --color-tap: #38bdf8; --color-muted: #737373; --color-bar: #262626; --color-bar-accent: #38bdf8; --font-mono: 'JetBrains Mono', monospace; } } }`
- Same `@keyframes` and class definitions as the `default` theme (tap-pulse, hold-fill).

### Task 3: Built-in `light` theme — `ButtonFrame.tsx`

- File: `packages/cli/src/themes/light/ButtonFrame.tsx` (new)
- Re-exports the `default` theme's `ButtonFrame` (the visuals are identical; only the tokens change). This is the user's "thin override" approach.
- ```ts
  export { ButtonFrame as default } from "../default/ButtonFrame";
  export * from "../default/ButtonFrame";
  ```
- Acceptance: unit test in `packages/cli/src/themes/light/__tests__/ButtonFrame.test.tsx` imports both names and verifies they're the same reference.

### Task 7: CLI wiring — send theme name on `deck-config`

- File: `packages/cli/src/runtime/ws-server.ts` (or wherever `deck-config` is sent — locate it)
- Include `theme: { name, version }` in the `deck-config` message payload. The `version` is the addon's `apiVersion`.
- Acceptance: a unit test in `packages/cli/src/runtime/__tests__/ws-server.test.ts` sends a `deck-config` and verifies the payload includes `theme.name`.

- Acceptance: a smoke test in `packages/cli/frontend/src/__tests__/App.test.tsx` (jsdom) renders the app with a mock `deck-config` and verifies the provider receives the right theme.

### Task 9: Integration test — theme switching

---

## Must-Haves

A user can configure `theme: light` in their config and:

1. The CLI loads the `light` theme and ships it to Vite.
2. The frontend's `ThemeProvider` resolves the `light` theme and renders its components.
3. The page now shows the light token set (when the OS prefers light).
4. Shared components (IconLabel, Bars, etc.) render correctly under both themes — same code, different colors.
5. The CLI sends the active theme name on `deck-config`.
6. All previous tests still pass.

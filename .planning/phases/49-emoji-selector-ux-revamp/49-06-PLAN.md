## Context

CONTEXT amendment A3 (2026-06-06) locks an additive signature change. The current `navigateToDeck` (and the internal `DeckController.navigateTo`) always push to the history stack, so a paginated emoji subdeck that walks 5 pages pushes 5 entries; pressing back from page 5 returns to page 4 instead of the parent deck. The user wants page-to-page navigation to be transparent to the back stack — only the entry point (e.g. main deck → first page) is recorded.

The change is intentionally minimal and backward-compatible: an optional `options` arg with a `addToHistory` boolean, defaulting to `true`. Internally, the controller's `navigateTo` gains a `push` option with the same default. `goBack` is untouched — it has its own semantic and is not a forward navigation.

All four existing call sites (`core-buttons/change-deck.tsx:62,66`, `emoji-launcher`, `category.tsx`, the inline `buildPageNavButton` output) keep their current behavior. The new `definePagedCategoryButton` and `buildPageNavButton` helpers added in 49-07 will be the only opt-in callers (using `addToHistory: false`).

# Phase 07 Plan 03 — macOS Implementations

## Context

macOS is the second-priority platform after Linux. All four capabilities are implemented via `osascript` (built-in), the AppleScript bridge. No new npm dependencies — all logic is in shell-out + JSON parsing.

The Plan 01 interfaces are stable: `ActiveAppProvider.getActive()`, `SessionProvider.getState()`, `KeyMacroProvider.sendKey()`, `MediaProvider` (transport + getCurrent + onChange). Each macOS implementation returns `null` provider (or throws) on failure rather than crashing.

`get-windows` and `dbus-next` are not used here — those are Linux-only. macOS uses its own primitives.

<file>packages/cli/src/system/session-monitor/darwin.ts</file>
<action>Implement `createDarwinSessionProvider({ executor, logger })`. Logic:
1. Locked state via osascript: `tell application "System Events" to get running of loginwindow process`. If process is running → screen is locked. Otherwise → unlocked.
2. Idle: `ioreg -c IOHIDSystem | awk '/HIDIdleTime/ {print $NF}'` — returns nanoseconds of idle time. Threshold 5 min (300e9 ns).
3. Combined state: `'locked' | 'unlocked' | 'unknown'`. Locked takes precedence (locked implies idle).
4. Poll every 5s (session changes are rare).
5. `osascript` non-zero → null provider.
6. `stop()` clears interval.</action>

## Notes for executor

- All osascript calls via the `executor` (testable; production uses `execa`).
- AppleScript record output is comma-separated. Use a small parser (split on `,` respecting quoting).
- `ctrl` modifier on macOS maps to `command`. Other modifiers: `alt` → `option`, `shift` → `shift`, `meta` → `control`, `super` → `command` (alias).
- All native calls mocked in tests via `vi.mock` of nothing — just inject the executor.
- DO NOT add comments unless user asks.

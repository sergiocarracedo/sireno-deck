# Plan 08-01: Ship The Analog Clock Button End-To-End

<objective>
Land the first complete Phase 8 tracer bullet: a user can declare an `analog-clock` button in the bundled date/time addon, the runtime refreshes it through the existing core scheduler, and the renderer produces a real analog face without widening the render model beyond one new variant branch.
</objective>

## Tasks

<task id="08-01-01">
<title>Add a separate bundled analog-clock button definition with the agreed live cadence</title>
<files>
- builtin-addons/date-time/src/index.ts
- builtin-addons/date-time/src/index.test.ts
</files>
<action>
Extend `builtin-addons/date-time/src/index.ts` so the bundled addon exports both the existing digital `date-time` button and a new `analog-clock` button definition. Keep the analog type separate rather than overloading the existing digital variant enum. Give the new definition its own strict config schema, keep Phase 8 text-free by rendering a `deck-button` without `label` or `subtitle`, and declare `defaultIntervalMs: 1000` so the runtime can drive the second hand through the existing scheduler contract. Update `builtin-addons/date-time/src/index.test.ts` to prove the addon now exposes the separate type, preserves the digital contract, and creates a renderable analog instance with the expected variant and cadence.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run ../../builtin-addons/date-time/src/index.test.ts`.
</verify>
<done>
The bundled addon exposes `analog-clock` as a real second button type with its own default cadence and render shape, while the existing digital button contract remains intact.
</done>
</task>

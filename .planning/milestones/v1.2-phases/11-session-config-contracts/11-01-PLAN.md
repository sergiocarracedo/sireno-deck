# Plan 11-01: Harden Phase 11 Security Without Rewidening Scope

<objective>
Ship one merged Phase 11 security-hardening tracer bullet that closes the current open threats without turning the fix into a new milestone. A completed plan should leave users with the same core Phase 11 behaviors — host-aware render/config/command paths, lock-aware deck switching, implicit lock fallback, and unlock restore — but with shell-safe host interpolation, honest Linux lock support claims, and a bundled-addon-backed implicit fallback instead of a runtime-only special case. The result must be demoable through the existing Phase 11 fixtures and auditable through an updated `11-SECURITY.md`.
</objective>

## Tasks

<task id="11-01-01">
<title>Harden host-context command interpolation at the shell boundary</title>
<files>
- packages/cli/src/action/executor.ts
- packages/cli/src/action/executor.test.ts
- packages/cli/src/config/loader.test.ts
- packages/cli/src/deck/runtime.test.ts
</files>
<action>
Keep the narrow `{{host.*}}` contract, but stop inserting raw host-derived values directly into shell commands. Add the minimal POSIX-safe escaping needed at the command-execution boundary so host-context values are safe when they flow into `/bin/sh -c`, while leaving config/render-time interpolation readable and leaving unresolved placeholders intact. Update focused executor/runtime coverage so the hardened command path is explicit and the non-command interpolation path does not regress into shell-quoted label text.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/action/executor.test.ts src/config/loader.test.ts src/deck/runtime.test.ts`.
</verify>
<done>
Host-derived command interpolation is shell-safe where commands actually execute, and Phase 11 labels/config text still use human-readable host interpolation rather than shell-escaped output.
</done>
</task>

<task id="11-01-02">
<title>Replace fake Linux support with a real detector-or-unsupported startup contract</title>
<files>
- packages/cli/package.json
- packages/cli/src/system/session-monitor.ts
- packages/cli/src/system/session-monitor.test.ts
- packages/cli/src/cli/commands/start.ts
- packages/cli/src/cli/commands/start.test.ts
</files>
<action>
Implement one real long-lived Linux lock/unlock detector seam instead of claiming support from platform alone. Use a concrete supported path only if it can initialize successfully; otherwise downgrade to `unsupported` and preserve the existing non-blocking startup warning. Keep the scope limited to lock/unlock semantics, and add focused tests that prove the startup contract distinguishes real supported detection from unsupported fallback honestly. If a small dependency is required for the detector, add only the one that directly serves this seam.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/system/session-monitor.test.ts src/cli/commands/start.test.ts`.
</verify>
<done>
Linux support claims are now earned by a real detector startup path rather than a platform guess, and failed detector initialization degrades honestly without blocking runtime startup.
</done>
</task>

Update runtime coverage and the committed lock-session fixture/UAT path so they still prove useful implicit fallback behavior plus exact unlock restore.

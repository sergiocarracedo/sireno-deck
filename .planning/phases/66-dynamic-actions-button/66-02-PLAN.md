# Plan 66-02: System Button Migration to SplitActionSurface

<objective>
Wire SplitActionSurface into the system button dispatcher and runtime. Replace the current system-back, system-back-with-pending-overlay, and system-settings branches in the dispatcher with a unified SPLIT_ACTION_TYPE. In runtime.ts, map SPLIT_ACTION_TYPE to SplitActionSurface with correct primary/secondary sub-surfaces. Delete SystemBackButton.tsx and SystemBackWithPendingOverlayButton.tsx. Simplify SystemSettingsEntryButton.tsx to use SplitActionSurface instead of bespoke badge layout. Update the 5 overlay lifecycle tests in runtime.test.ts.
</objective>

## Tasks

<task id="66-02-01">
<title>Add SPLIT_ACTION_TYPE constant + refactor dispatcher</title>
<files>
- packages/cli/src/deck/system-buttons/system-buttons.ts
</files>
<action>
1. Add a new constant: `export const SPLIT_ACTION_TYPE = 'split-action' as const`
2. Add a type helper for config that describes which sub-surfaces to render:

```typescript
export interface SplitActionConfig {
  /** What the primary surface should show: 'back' or 'settings' */
  primary: 'back' | 'settings'
  /** Optional secondary surface showing overlay info */
  secondary?: { overlayDeckName: string }
}
```

3. Refactor `getLastPositionSystemButton`:
- **Branch 1 (overlay toggle)**: Keep unchanged — when viewing overlay/paged deck of overlay
- **Branch 2 (settings on main deck)**: When on main deck and settings deck exists, inject `SPLIT_ACTION_TYPE` with `config: { primary: 'settings', secondary: pendingOverlayDeckId ? { overlayDeckName: runtimeDecks[pendingOverlayDeckId].name } : undefined }` instead of SYSTEM_SETTINGS_TYPE
- **Branch 3 (pending overlay on sub-deck)**: When pendingOverlayDeckId is non-null and differs from overlayDeckId, inject `SPLIT_ACTION_TYPE` with `config: { primary: 'back', secondary: { overlayDeckName: runtimeDecks[pendingOverlayDeckId].name } }` instead of SYSTEM_BACK_WITH_PENDING_OVERLAY_TYPE
- **Branch 4 (plain back)**: When `shouldInjectSystemBack` is true, inject `SPLIT_ACTION_TYPE` with `config: { primary: 'back' }` instead of `system-back`
- Remove unused OLD type constants if no longer referenced externally (keep them if used in tests, but they can transition)
</action>
<verify>
- Constant `SPLIT_ACTION_TYPE` is exported
- Config schema produces `SplitActionConfig` shape
- Dispatcher returns `SPLIT_ACTION_TYPE` in all three branches
- TypeScript compiles without errors
</verify>
<done>When system-buttons.ts exports SPLIT_ACTION_TYPE and dispatcher returns it for all three back/settings branches</done>
</task>

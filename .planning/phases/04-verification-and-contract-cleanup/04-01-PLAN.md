# Plan 04-01: Close The Unmatched-Angle Date-Time Contract Gap

<objective>
Close the one active runtime defect still left in the v1.3 contract: malformed unmatched-angle rich markup currently suppresses the useful Day.js-expanded values instead of keeping the broken literal text while still showing the formatted time/date content. This slice matters because Phase 4 is supposed to lock the shipped single-field `format` contract honestly, and right now one real invalid-markup path still breaks that promise.
</objective>

## Tasks

<task id="04-01-01">
<title>Make unmatched-angle markup preserve literal text without suppressing Day.js expansion</title>
<files>
- packages/cli/src/builtin-addons/date-time/format.ts
</files>
<action>
Adjust the date-time formatting seam in `packages/cli/src/builtin-addons/date-time/format.ts` so malformed unmatched-angle input such as `Broken <accent HH:mm` no longer turns the whole suffix into an unformatted literal segment. Keep the one-field `format` contract and the locked Phase 3 parse order intact: Day.js token expansion still happens before shared `Text` parsing, and the shared `Text` layer still owns literal fallback for malformed markup. The formatter should preserve the broken `<...` text literally in the returned string while still allowing the date/time tokens in that malformed suffix to expand, so the user sees the bad markup as text plus the useful formatted values.
</action>

</verify>
<done>

</done>
</task>

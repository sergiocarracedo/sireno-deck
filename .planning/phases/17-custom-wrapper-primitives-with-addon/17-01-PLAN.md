# Plan 17-01: Establish The Base-Shape Contract And Compatibility Boundary

<objective>
Deliver the first Phase 17 tracer bullet as one demoable user-facing behavior: shared/default button rendering is re-described as one default base-shape contract with an explicit full-surface escape hatch, while already-shipped `wrapper_id` config continues to validate and still render through the correct default-shape path on the real CLI/device seam.
</objective>

## Tasks

<task id="17-01-01">
<title>Define the explicit base-shape vs full-surface render contract</title>
<files>
- packages/cli/src/addon/api.ts
- packages/cli/src/render/types.ts
- packages/cli/src/render/reconciler.ts
- packages/cli/src/render/reconciler.test.tsx
</files>
<action>
Extend the addon-facing and reconciler-facing render contract so ordinary text-oriented buttons can explicitly mean "render content inside the default base shape" while custom buttons can explicitly mean "render the whole surface myself." Keep the transport narrow and explicit; do not add a public `shape_id`, do not introduce a nested scene graph, and do not rely on arbitrary child inspection. Update reconciler tests so helper-authored and JSX-authored output stay in parity for both the default base-shape path and the explicit full-surface path.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/render/reconciler.test.tsx`.
</verify>
<done>
The public render seam can carry the new shape/content boundary without widening the renderer model.
</done>
</task>

<files>

<action>

</task>

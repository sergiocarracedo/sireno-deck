# Plan 16-03: Surface Invalid Reloads On-Device With A Temporary Error Deck

<objective>
Ship the failure-path tracer bullet: config hot-reload does not just log errors, it visibly switches the device into a temporary built-in error state until the config is fixed. A completed plan should prove users can see that their live edit broke config and can recover automatically by fixing the file.
</objective>

## Tasks

<task id="16-03-01">
<title>Introduce a runtime-owned temporary error deck for invalid reloads</title>
<files>
- packages/cli/src/cli/commands/start.ts
- packages/cli/src/deck/runtime.ts
</files>
<action>
Add the smallest runtime-owned error-surface mechanism that honors the Phase 16 decision: when a reload attempt fails with `ConfigValidationError`, keep the daemon alive but switch the device into a built-in temporary error deck that is not loaded from user config. The fallback should carry only the latest config error summary needed to make the failure understandable and should remain isolated from normal config-authored deck activation.
</action>
<verify>
Run `grep -n "ConfigValidationError\|error deck\|reload" packages/cli/src/cli/commands/start.ts packages/cli/src/deck/runtime.ts`.
</verify>
<done>
Invalid reloads produce a real runtime fallback state instead of silent logs or daemon shutdown.
</done>
</task>

<task id="16-03-02">
<title>Render the temporary error deck clearly and prove auto-recovery on the next valid reload</title>
<files>
- packages/cli/src/render/text-image.ts
- packages/cli/src/render/text-image.test.ts
- packages/cli/src/deck/runtime.test.ts
- packages/cli/src/cli/commands/start.ts
</files>
<action>
Use the existing render path to give the temporary error deck a clear readable presentation that can fit a short config error summary on-device without inventing a second rendering system. Add focused tests proving two end-to-end states: an invalid watched edit enters the temporary error deck, and a later valid watched edit exits that state automatically and resumes ordinary runtime rendering with the new config.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli test -- src/render/text-image.test.ts src/deck/runtime.test.ts`.
</verify>
<done>
The error fallback is visible, understandable, and self-healing once config validity returns.
</done>
</task>

<must_haves>
- Invalid reload handling remains runtime-owned and does not depend on user-authored fallback config.
- The temporary error deck uses the real render path rather than a console-only fallback.
- Valid reload recovery is automatic; users do not need to restart the daemon to leave the error state.
</must_haves>

# Plan 31-01: Restore The Runtime Watch Launcher Contract

<objective>
Fix the actual runtime seam first. Phase 31 exists because `cli:dev` no longer truthfully launches the real CLI watch path after the root script drifted. This slice should restore the runtime contract with the smallest honest mechanism: keep `tsx watch`, keep the watched include graph, and make one narrow launcher decide between the documented default `start --config config.yml` argv and explicitly forwarded argv such as `emulate --port 8912`.
</objective>

## Tasks

<task id="31-01-01">
<title>Add one narrow `cli:dev` launcher that restores default-start and forwarded-args truth</title>
<files>
- package.json
- packages/cli/src/cli/dev-watch.ts
</files>
<action>
Create a small launcher module at `packages/cli/src/cli/dev-watch.ts` and repoint the root `package.json#scripts.cli:dev` script at it. The launcher should preserve the existing `tsx watch` include globs and real CLI entrypoint, but resolve argv honestly: with no forwarded args it must run the real `start --config config.yml` path; with forwarded args it must pass those args through untouched to `packages/cli/src/cli/index.ts`. Keep this launcher narrow and transparent. Do not add a new developer-facing command surface, a bundler watch seam, or custom hot-reload behavior.
</action>
<verify>
Run `grep -n 'cli:dev' package.json && grep -n 'start --config config.yml\|emulate\|tsx watch' packages/cli/src/cli/dev-watch.ts`.
</verify>
<done>
The workspace-root `cli:dev` command once again has one truthful runtime seam for both bare invocation and explicit forwarded-args invocation.
</done>
</task>

<must_haves>
- Keep `tsx watch` as the external full-process restart seam.
- Keep the existing include graph unless implementation proves it is the bug.
- Do not swallow forwarded args behind the default `start --config config.yml` path.
</must_haves>

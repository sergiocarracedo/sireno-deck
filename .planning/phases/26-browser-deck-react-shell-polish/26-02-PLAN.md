# Plan 26-02: Usable Undersized Device Warning Path

<objective>
Replace the current Phase 22 hard-failure emulator mismatch policy with the new Phase 26 contract: when the selected virtual device is smaller than the configured deck, Sireno still renders the keys that fit and shows a persistent inline warning inside the same shared deck document.
</objective>

## Tasks

<task id="26-02-01">
<title>Thread undersized-device warning state through the shared deck document instead of an error-only HTML swap</title>
<files>
- packages/cli/src/cli/commands/start.ts
- packages/cli/src/render/dom-host.tsx
</files>
<action>
Refactor the undersized-device path in `packages/cli/src/cli/commands/start.ts` so it no longer writes a special `Emulator Layout Error` page and returns early. Instead, pass enough warning/mismatch state into the shared deck document path so `renderDomDeck(...)` can render the visible subset for the selected key count and display a persistent inline shell banner that explains the mismatch. Preserve honesty: keep selected-vs-required key counts explicit, keep the warning persistent, and do not silently auto-switch devices or hide the mismatch behind clipping. Keep warning ownership in the browser shell rather than pushing it into themes or browser-renderer internals.
</action>
<verify>
`grep -n "emulator_layout_mismatch\|Selected virtual device exposes\|warning" packages/cli/src/cli/commands/start.ts packages/cli/src/render/dom-host.tsx` shows the mismatch state now feeds the shared deck shell instead of producing a separate error-only page.
</verify>
<done>
Undersized virtual devices render a truthful subset-plus-warning surface on the same deck document seam used by the normal browser/emulator path.
</done>
</task>

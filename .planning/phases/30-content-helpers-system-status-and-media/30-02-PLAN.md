# Plan 30-02: Ship The Template-Driven System-Status Addon

<objective>
Deliver the first user-facing built-in addon family on top of the new helpers: configurable system-status buttons that expose canonical host metrics honestly across operating systems. This slice needs to be end-to-end because the phase goal is not just “metric adapters exist”; it is that users can configure helper-backed buttons with stable metric ids, metadata overrides, and truthful unavailable states.
</objective>

## Tasks

<task id="30-02-01">
<title>Turn the existing live-metrics seam into a canonical system-status metric service</title>
<files>
- packages/cli/package.json
- packages/cli/src/system/live-metrics.ts
- packages/cli/src/system/system-status.ts
</files>
<action>
Extend `packages/cli/src/system/live-metrics.ts` from its current CPU/memory/fan helpers into the canonical metric-catalog seam Phase 30 discussed. Keep `systeminformation` as the first data source and define explicit metric ids and normalized return shapes that can express current value, optional max, units, percentage, label-ready raw data, and honest unavailability without faking unsupported fields. Add `numbro` to `packages/cli/package.json` and introduce a nearby support module such as `packages/cli/src/system/system-status.ts` that maps canonical metric snapshots plus metadata overrides into the display-ready values the helper-backed built-ins will consume. Keep formatter policy outside the shared UI helpers and inside this system-status support layer.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec node -e "import pkg from './package.json' with { type: 'json' }; if (!pkg.dependencies?.numbro) throw new Error('missing numbro'); console.log(pkg.dependencies.numbro)" && grep -n "available\|metric\|systeminformation" packages/cli/src/system/live-metrics.ts packages/cli/src/system/system-status.ts`.
</verify>
<done>
The repo has one explicit system-status metric seam, `numbro` is declared for formatting, and unavailable metrics can be represented honestly before any button rendering happens.
</done>
</task>

<must_haves>
- Do not let per-OS adapters leak raw OS-shaped blobs into button config; keep one canonical metric catalog.
- Do not collapse missing metrics out of the layout; the unavailable state must stay visible in-place.
- Do not broaden configuration into arbitrary nested layout structure or free-form rendering rules.
</must_haves>

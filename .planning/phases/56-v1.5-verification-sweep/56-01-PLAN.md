# 56-01 — High-priority overlay lifecycle tests

> The Phase 55 verification was manual/code-review based. The runtime overlay integration path (processNamesMatch → overlay activation → toggle injection → double-tap dismiss → navigation isolation → multi-addon collision warning) has **no end-to-end test**. This is the highest-risk gap to close.

## Context

Research found these specific gaps in the active-app overlay test coverage:

1. **`processNamesMatch()`** (runtime.ts:173) — the core matching function has **zero direct unit tests**
2. **Overlay lifecycle integration** — no test simulates the full flow: monitor emits ownerName → runtime detects match → overlay deck activates → toggle appears → double-tap dismisses overlay
3. **Multi-addon collision** — the startup warning for two addons with the same `process_names` (`runtime.ts:1410+`) is untested
4. **Overlay pagination + toggle persistence** — only a single overlay deck toggle is tested in system-buttons-dispatcher, not across paginated overlay pages
5. **`dismissOverlay()` within the 350ms double-tap window** — the `lastBackActionAt` path is untested end-to-end

# 57-01 — Pipeline profile (RES-01)

> The back button has a perceived ~1s delay. The runtime hop chain is async, mounted-deck React, and goes through the browser capture loop. The Phase 57 research needs real measurements to point Phase 58 at the right fix.

## Context

Phase 57 decision (CONTEXT.md): **instrumented runs only**. Add pino debug logs at runtime.ts hop boundaries, run back-button scenario in emulator + real hardware if available, measure ms per hop. No static analysis, no CPU profile.

Phase 57 decision (RESEARCH.md): Guard instrumentation with `SIRENO_PROFILE=1` or `logging.level=debug` to keep default overhead near-zero. Use `process.hrtime.bigint()` for high-precision per-hop timing.

The runtime hop chain to instrument (from CONTEXT.md):
`handleTap` → `onTap` → `navigateToDeck` / `goBack` → `activateDeckSurface` → `renderDeckSurface` → `renderMountedDeckButtons` → `emitRenderedDeck` → browser capture loop (if applicable)

Gesture FSM hops (also relevant for press/release/hold/dbl-tap timing):
- `onKeyEvent` (entry)
- `handlePress` (down)
- `handleRelease` (up)
- `handleTap` (debounced tap)
- `handleHold` (long press)
- `handleDblTap` (fast double-tap)

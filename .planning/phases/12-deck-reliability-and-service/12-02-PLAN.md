# Plan 12-02: Deterministic deck positions

<objective>
Make `positionButtons` authoritative for any active keyCount by recomputing from the original config on every device swap. Switch the deck-config serializer to sparse arrays so empty slots stay empty rather than being filled with placeholder surfaces. After this plan, an explicit `position: 11` in user config is honored on a 15-key device and silently dropped on a 6-key device, and duplicate explicit positions reflow the later duplicates in config order.
</objective>

<title>Rewrite positionButtons to accept keyCount and emit sparse output</title>
<files>
- packages/cli/src/deck/position-buttons.ts
- packages/cli/src/deck/__tests__/position-buttons.test.ts (new)
</files>
<action>
1. Update the exported signature to `positionButtons(config, keyCount: number): Array<{ button: ConfigButton; position: number }>` (the sparse output — at most `keyCount` entries, no padding).
2. Algorithm:
   - Walk `config.buttons` once to collect explicit-position reservations; keep the first occurrence of each position, mark later occurrences as "reflow".
   - Build an `occupied: Set<number>` from explicit positions that are `>= 0 && < keyCount`.
   - For each button in config order: if it has an explicit position in range, place at that position; if its position is a duplicate (later occurrence) or out of range, treat as unpositioned.
   - Unpositioned buttons are placed into the lowest empty slot `0..keyCount-1` in config order.
   - Buttons with explicit positions `>= keyCount` are dropped (debug log: `{ deckId, position, keyCount, reason: 'overflow' }`).
   - Buttons with explicit positions `< 0` are dropped with reason `'invalid-position'`.
3. Preserve existing duplicate-warning logs (demoted to debug per Phase 12 logging decision).
4. Write `position-buttons.test.ts` covering:
   - All-unpositioned, keyCount=5 → first 5 buttons in config order, overflow dropped.
   - Explicit positions `0, 3, 7` with keyCount=5 → slots 0 and 3 filled, slot 7 dropped (overflow).
   - Duplicates `0, 0, 1` with keyCount=3 → first wins slot 0, second reflows into slot 2 (next empty).
   - Sparse output: returned array length equals assigned count (≤ keyCount), not `keyCount`.
</action>

# Plan 52-01: Lock deck back-button gate depends on session state

<objective>
After this plan, the lock deck's back button is gated by both deck identity AND session state. The v1.4 behavior (no back button when on the lock deck) is preserved when the session is `locked`. The new v1.5 behavior is: when the session is `unlocked` (or `unknown` or `unsupported`), the lock deck gets the back button like any other subdeck, so users can navigate to the lock deck to pre-warm and inspect it before locking the computer. The change is a one-line refactor of the gate, a new third argument to the function, the runtime's call site update, and unit + integration tests.
</objective>

# Phase 11 Plan 02 — `addons[i].config` schema + per-deck overrides

## Goal

After this plan, a user can write:

```yaml
addons:
  - src: ~/works/opensource/sireno-deck-addons/chrome-overlay
    config:
      hideTabs: false              # addon-wide config, merged into createDecks({config})
      decks:
        chrome-overlay:shortcuts:  # per-deck overrides keyed by addon deck id
          autoShow: false
          config:                   # inner config merged into createDecks({config})
            hiddenTabIds: [0, 1]
```

and:

1. The `config` block reaches the addon's `createDeck(s)({config})` as `{...defaultButtonConfig, hideTabs: false, hiddenTabIds: [0, 1]}`.
2. The `autoShow: false` override flips chrome-overlay's default `autoShow: true` on the resulting RuntimeDeck.
3. `name`, `icon`, `trigger` overrides apply on top of the generated deck; `isOverlay: true` is forced when `trigger` is overridden.

   with:
   ```ts
   export const AddonConfigSchema = z.object({
     decks: z.record(z.string(), z.object({
       autoShow: z.boolean().optional(),
       name: z.string().min(1).optional(),
       icon: IconSourceSchema.optional(),
       trigger: TriggerSchema.optional(),
       config: z.record(z.string(), z.unknown()).optional(),
     }).strict()).optional(),
   }).strict().optional()

   export const AddonEntrySchema = z.union([
     z.string().min(1),
     z.object({
       source: z.string().min(1),
       enabled: z.boolean().optional(),
       config: AddonConfigSchema,
     }).strict(),
   ])
   ```
2. Note: the host-level addon-wide config (sibling to `decks`) is NOT in this schema — it's the literal extra keys (e.g. `hideTabs`). The `AddonConfigSchema` only types the `decks` sub-record; the addon-wide extras are opaque `z.record(z.string(), z.unknown())` merged into `addonConfig` at materialization time. We accept any keys at the top level of `addons[i].config` so we don't constrain addons that need extra config.
3. Drop `OverlayConfigSchema`, `OverlayDeckEntrySchema`, `AddonOverlayOverrideSchema`, `AddonOverlayDeckOverridesSchema` — these are quick-006 leftovers and the user wants top-level `overlay:` reverted.

## Task 2.2 — Wire `addons[i].config` into addon-deck materialization

<files>
- packages/cli/src/cli/commands/run.ts
- packages/cli/src/cli/commands/addon-decks.ts
</files>

<action>
1. In `run.ts:buildRuntime`, build two maps from the parsed config:
   - `addonConfigOverrides: Map<addonName, Record<string, unknown>>` — keyed by addon name; the value is the user-provided `addons[i].config` (everything under `config` except the `decks` sub-record).
   - `addonDeckOverrides: Map<addonName, Map<deckId, AddonDeckOverride>>` — keyed by addon name, then by deck id. Each entry is the per-deck override shape from 2.1.
2. Pass both to `materializeAddonDecks`:
   ```ts
   materializeAddonDecks(registry, effectiveDecks, logger, keyCount, config.lock?.buttons, addonConfigOverrides, addonDeckOverrides)
   ```
3. In `materializeAddonDecks`:
   - Merge order for the config passed to `createDeck(s)({config})`: `{...defaultButtonConfig, ...addonConfigOverrides.get(addon.name) ?? {}}`. User wins.
   - For multi-dynamic entries: the inner per-deck `config` (under `addons[i].config.decks.<deckId>.config`) needs to be merged into `addonConfig` BEFORE `createDecks` runs — but we don't know which deck ids will be returned. Solution: aggregate all per-deck `config` overrides for this addon into the addonConfig pass-through (additive merge). For single-dynamic / static: same merge (it's idempotent).
   - After `createDeck(s)` returns, apply per-deck overrides: for each generated deck id, look up `addonDeckOverrides.get(addon.name)?.get(deckId)` and merge the field-level overrides (`autoShow`, `name`, `icon`, `trigger`, force `isOverlay: true` when `trigger` is set).
4. Drop the `addonOverrides` parameter from `materializeAddonDecks` (added in quick-006; superseded by the two new maps).
5. Drop `materializeDeckFromConfig` helper (added in quick-006; the user overlay decks revert to living in `decks:` with `trigger` — back to the pre-quick-006 logic).
6. Restore `effectiveDecks` to just `decks` (no user-overlay prefix).

</action>

# Phase 1: Theme-Relative Typography Contract — Research

**Researched:** 2026-05-28
**Phase goal:** Make typography-role base sizes and shared `Text` size variants line up so `md` means the active theme base and the other sizes scale honestly from it.

## Don't Hand-Roll

| Problem | Recommended solution | Why | Provenance |
|---------|----------------------|-----|------------|
| Publish per-role typography bases without duplicating sizing logic everywhere | Use CSS custom properties plus `var()` in the shared utility stylesheet and `Text` classes | Custom properties are the browser-native token mechanism, they cascade/inherit naturally, and they let role classes publish base values while `Text` resolves final size centrally instead of re-stamping absolute values per caller | [CITED: https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_cascading_variables/Using_CSS_custom_properties] [CITED: https://developer.mozilla.org/en-US/docs/Web/CSS/var] |
| Make size tokens relative to the active typography role instead of the root document | Resolve `Text` size classes from the inherited/computed role base using font-relative sizing, not root-relative `rem` | `font-size` inherits, `em`/percent scale from the parent/computed font size, and `rem` would bypass the role-local base that this phase is explicitly trying to honor | [CITED: https://developer.mozilla.org/en-US/docs/Web/CSS/font-size] |
| Prove typography changes in review paths without relying on fragile font-family-only differences | Make the visible contract testable through size, weight, and tracking differences on real render paths | This repo already learned that host font fallback can hide `font_family` changes, while size/weight/tracking survive fallback better and are observable in real review fixtures | [VERIFIED: .planning/solutions/ui-bugs/theme-typography-difference-hidden-by-font-fallback-2026-05-15.md] |
| Keep this phase narrow instead of turning it into fluid/container typography work | Treat container-query fluid scaling as out of scope background guidance, not the core Phase 1 solution | Modern guidance shows fluid/container scaling is for container-responsive typography, while Phase 1 is specifically about truthful role-relative token semantics inside the existing text contract | [VERIFIED: modern-web-guidance search results for `css custom properties typography scale relative font size utility classes 2026`, `css font size relative em custom properties component scale pitfalls 2026`, `design system typography tokens css variables relative text sizes 2026`] [VERIFIED: modern-web-guidance retrieve `fluid-scaling`] |

## Common Pitfalls

### Leaving `.font-main` / `.font-aux` / `.font-mono` in charge of final `font-size`
**What goes wrong:** Shared `Text` size tokens like `text-sm` and `text-xl` become cosmetic or misleading because the role class has already fixed the final size. [VERIFIED: `packages/cli/src/render/theme-utilities.ts`]  
**Why:** The current utility stylesheet emits role classes that set `font-family`, `font-size`, `font-weight`, and `letter-spacing` together, so the role and size layers fight each other instead of composing. [VERIFIED: `packages/cli/src/render/theme-utilities.ts`]  
**How to avoid:** Move role classes to base-token publication plus family/weight/tracking ownership, and make shared `Text` classes the only place that resolves final size tokens. [VERIFIED: `.planning/phases/01-theme-relative-typography-contract/01-CONTEXT.md`] [CITED: https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_cascading_variables/Using_CSS_custom_properties]

### Using `rem` or another root-relative scale for Phase 1 size tokens
**What goes wrong:** `main`, `aux`, and `mono` stop behaving relative to their own theme bases, which directly violates the locked Phase 1 contract. [VERIFIED: `.planning/phases/01-theme-relative-typography-contract/01-CONTEXT.md`]  
**Why:** `rem` is tied to the root element, not the current role-local base size; it bypasses the typography-role contract rather than composing with it. [CITED: https://developer.mozilla.org/en-US/docs/Web/CSS/font-size]  
**How to avoid:** Keep role bases on inherited custom properties and apply moderate shared multipliers via parent-relative sizing semantics in the text layer. [CITED: https://developer.mozilla.org/en-US/docs/Web/CSS/font-size] [CITED: https://developer.mozilla.org/en-US/docs/Web/CSS/var]

### Letting theme wrappers become a second sizing engine
**What goes wrong:** Themes can silently redefine what `size="lg"` means, causing per-theme behavior drift and breaking the Phase 28 contract that `Text` semantics stay core-owned. [VERIFIED: `.planning/phases/28-component-first-tsx-theme-ui-kit-cli/28-CONTEXT.md`]  
**Why:** The default theme wrapper currently only decorates text metadata; if sizing logic moves there, the semantic contract stops being shared across themes. [VERIFIED: `packages/cli/src/themes/default/ButtonFrame.tsx`]  
**How to avoid:** Thread `size` through theme presentation props and data attributes for observability only; keep the actual sizing math in `Text` and shared utility CSS. [VERIFIED: `packages/cli/src/config/theme.ts`] [VERIFIED: `packages/cli/src/themes/default/ButtonFrame.tsx`] [VERIFIED: `.planning/phases/01-theme-relative-typography-contract/01-CONTEXT.md`]

### Planning only for `Text.tsx` and missing raw typography callers
**What goes wrong:** The shared contract is fixed on paper, but built-ins and browser shell markup keep depending on implicit typography sizing, so the old seam survives in production code. [VERIFIED: `packages/cli/src/builtin-addons/date-time/buttons/date-time.tsx`] [VERIFIED: `packages/cli/src/render/dom-host-deck-document.tsx`] [VERIFIED: `packages/cli/src/ui/Chip.tsx`]  
**Why:** The sweep surface is broader than the first discussion list: several built-ins wrap `Text` inside raw `font-*` spans, `Chip` still hardcodes `font-aux`, and the browser document body still uses `font-main`. [VERIFIED: `packages/cli/src/builtin-addons/date-time/buttons/analog-clock.tsx`] [VERIFIED: `packages/cli/src/builtin-addons/date-time/buttons/calendar-sheet.tsx`] [VERIFIED: `packages/cli/src/builtin-addons/date-time/buttons/locked-time-tile.tsx`] [VERIFIED: `packages/cli/src/builtin-addons/core-buttons/buttons/action.tsx`] [VERIFIED: `packages/cli/src/builtin-addons/emoji-selector/support.tsx`] [VERIFIED: `packages/cli/src/ui/Chip.tsx`] [VERIFIED: `packages/cli/src/render/dom-host-deck-document.tsx`]  
**How to avoid:** Plan a real sweep slice that migrates text-node callers onto `Text`, updates tightly owned non-`Text` components like `Chip`, and closes browser-shell inheritance seams explicitly. [VERIFIED: `.planning/phases/01-theme-relative-typography-contract/01-CONTEXT.md`]

### Forgetting to update tests that still assert raw typography class output
**What goes wrong:** Either the new contract breaks existing tests for the wrong reason, or stale tests preserve the old raw-class behavior and block the contract cut. [VERIFIED: `packages/cli/src/render/dom-host.test.tsx`] [VERIFIED: `packages/cli/src/builtin-addons/date-time/index.test.ts`] [VERIFIED: `packages/cli/src/builtin-addons/core-buttons/index.test.ts`] [VERIFIED: `packages/cli/src/builtin-addons/emoji-selector/index.test.ts`]  
**Why:** Current tests explicitly assert `.font-main` stylesheet output and raw class strings like `font-main text-primary`, but they do not yet assert `size` metadata on theme wrappers or role-relative size behavior across typography roles. [VERIFIED: `packages/cli/src/render/dom-host.test.tsx`]  
**How to avoid:** Treat regression coverage as a first-class deliverable: update theme-utility expectations, add theme-wrapper size metadata assertions, and verify the same size token behaves relatively across `main`, `aux`, and `mono`. [VERIFIED: `.planning/phases/01-theme-relative-typography-contract/01-CONTEXT.md`]

## Existing Patterns in This Codebase

- **`Text` is already the canonical text seam:** `packages/cli/src/ui/Text.tsx` already owns `typography`, `size`, `fit`, theme-presentation threading, and `data-sireno-ui-text`. Reuse that API instead of creating a second text contract. [VERIFIED: `packages/cli/src/ui/Text.tsx`]
- **Theme typography tokens already exist, but composition is wrong:** `packages/cli/src/render/theme-utilities.ts` already exports `--sireno-font-*-size` variables alongside family/weight/tracking, so Phase 1 can fix composition without inventing a new theme model. [VERIFIED: `packages/cli/src/render/theme-utilities.ts`]
- **Theme text metadata seam is already present:** `packages/cli/src/config/theme.ts` includes `ThemeTextPresentationProps.size`, which means the theme API already expects size metadata even though the default theme does not expose it yet. [VERIFIED: `packages/cli/src/config/theme.ts`] [VERIFIED: `packages/cli/src/themes/default/ButtonFrame.tsx`]
- **Past phases prefer narrow explicit contracts:** Phase 12 locked text behavior as a narrow render contract, and Phase 28 locked theme customization as presentation-only. Phase 1 should deepen those seams rather than widen into fluid typography or a broader layout rewrite. [VERIFIED: `.planning/phases/12-backgrounds-text-fitting/12-CONTEXT.md`] [VERIFIED: `.planning/phases/28-component-first-tsx-theme-ui-kit-cli/28-CONTEXT.md`]
- **Review-proof tests already live near the browser theme seam:** `packages/cli/src/render/dom-host.test.tsx` is the current regression surface for theme utility CSS and default-theme metadata wrappers, so it is the right place to prove the contract cut. [VERIFIED: `packages/cli/src/render/dom-host.test.tsx`]
- **Raw typography sweep is mechanically discoverable:** `grep` across `packages/cli/src` found the concrete migration targets: `date-time.tsx`, `analog-clock.tsx`, `calendar-sheet.tsx`, `locked-time-tile.tsx`, `action.tsx`, `emoji-selector/support.tsx`, `Chip.tsx`, and `dom-host-deck-document.tsx`. [VERIFIED: grep results in this session]

## Recommended Approach

Start Phase 1 by fixing the shared typography contract at the source: keep role classes responsible for family, weight, tracking, and publishing a base-size token, but stop letting them stamp the final `font-size`. [VERIFIED: `.planning/phases/01-theme-relative-typography-contract/01-CONTEXT.md`] [VERIFIED: `packages/cli/src/render/theme-utilities.ts`] Then update `Text` plus the default theme presentation seam so size semantics remain core-owned, `md` equals the active role base, and tests can observe size metadata explicitly. [VERIFIED: `packages/cli/src/ui/Text.tsx`] [VERIFIED: `packages/cli/src/config/theme.ts`] [VERIFIED: `packages/cli/src/themes/default/ButtonFrame.tsx`]

After the core contract is truthful, do one explicit sweep over the known raw typography callers and browser-shell inheritance seams so the old implicit sizing path no longer survives in shipped surfaces or tests. [VERIFIED: `packages/cli/src/builtin-addons/date-time/buttons/analog-clock.tsx`] [VERIFIED: `packages/cli/src/builtin-addons/core-buttons/buttons/action.tsx`] [VERIFIED: `packages/cli/src/render/dom-host-deck-document.tsx`] Keep the phase narrow: no fluid/container typography, no theme-configurable multipliers, and no Phase 2 shrink-fit work mixed in. [VERIFIED: `.planning/phases/01-theme-relative-typography-contract/01-CONTEXT.md`] [VERIFIED: `.planning/research/SUMMARY.md`]

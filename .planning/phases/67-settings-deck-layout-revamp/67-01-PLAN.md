# Plan 67-01: Settings Deck Layout Revamp

## Context

The current settings deck is a static `DeckConfig` with 4 buttons at hard-coded
positions 0-3. It does not scale with `keyCount`. The brightness buttons
hand-roll `<Icon>` + `<Text>` JSX instead of using the existing
`IconLabelSurface` primitive. This plan delivers the layout described in
`67-CONTEXT.md` (decisions D-01..D-08): position 0 = logo+version,
n-3 = darker, n-2 = brighter, n-1 = percent, with `IconLabelSurface` for the
brightness buttons and `<Label>` for the current-brightness subtitle.

### Task 5: Convert `INTERNAL_SETTINGS_DECK` into a keyCount-driven builder

**file:** `packages/cli/src/deck/runtime.ts`
**action:** Replace the static `INTERNAL_SETTINGS_DECK` const with a
function:

```ts
function createInternalSettingsDeck(keyCount: number): DeckConfig {
  if (keyCount < 4) {
    throw new Error(
      `internal settings deck requires keyCount >= 4 (got ${keyCount})`,
    )
  }
  const position = {
    logo: 0,
    darker: keyCount - 3,
    brighter: keyCount - 2,
    percent: keyCount - 1,
  } as const
  const buttonSpecs = [
    { position: position.logo, type: '__sireno_internal_settings_logo_version' },
    { position: position.darker, type: '__sireno_internal_settings_brightness_down' },
    { position: position.brighter, type: '__sireno_internal_settings_brightness_up' },
    { position: position.percent, type: '__sireno_internal_settings_current_brightness' },
  ] as const
  return {
    id: SETTINGS_DECK_ID,
    name: 'Settings',
    system: true,
    buttons: buttonSpecs.map(({ position, type }) => {
      const definition = internalSettingsButtonDefinitions.get(type)
      if (!definition) {
        throw new Error(
          `Bundled internal-settings button definition is missing for type '${type}'`,
        )
      }
      return { config: {}, definition, position, type }
    }),
  }
}
```

Update `createInternalDecks(keyCount)` to call `createInternalSettingsDeck(keyCount)` instead of returning the static const. The locked-time deck builder
(`createInternalLockedDeck`) is untouched.

**verify:** TypeScript compiles. No remaining references to the old
`INTERNAL_SETTINGS_DECK` constant (rg confirms).

**done:** `createInternalDecks(keyCount)` produces a settings deck whose 4
buttons are placed at positions {0, keyCount-3, keyCount-2, keyCount-1}, and
throws on `keyCount < 4`.

## Vertical Slice Check

After this plan completes, the demoable end-to-end behavior is:
- `pnpm cli:dev start --config config.yml` boots, navigate to the main deck,
  open the settings deck (position-0 reserved slot on main deck, see
  Phase 66).
- On a 15-key grid: settings deck shows logo+version at top-left,
  "Dimmer" at position 12, "Brighter" at position 13, "N%" + "Brightness"
  at position 14.
- On a 6-key grid: logo at 0, dimmer at 3, brighter at 4, percent at 5.
- Tapping Dimmer/Brighter adjusts brightness; tapping the percent position
  has no effect (no onTap handler); the logo+version position is display-only.
- The per-button unit tests prove the JSX structure; the new matrix test
  proves the layout is n-aware.

This is a single vertical slice: rendering pipeline change end-to-end
(render functions use IconLabelSurface, deck builder is n-aware, test
matrix proves positions) without leaking into other decks.

# Plan 10-03: Chrome overlay addon

<objective>
Create a new external addon `chrome-overlay` at `~/works/opensource/sireno-deck-addons/chrome-overlay/` mirroring the structure of `vscode-overlay` and `opencode-overlay`. Register it in `config.yml`. The addon provides a paginated, `autoShow: true`, `isOverlay: true` deck with a fresh curated button set of Chrome shortcuts. The trigger matches the Chrome family of browsers by `process_name`.
</objective>

<task id="10-03-02">
<title>Implement createDecks with curated chrome buttons</title>
<files>
- /works/opensource/sireno-deck-addons/chrome-overlay/index.js
</files>
<action>
Write `/works/opensource/sireno-deck-addons/chrome-overlay/index.js` exporting `{ manifest }` with one deck `chrome-overlay:shortcuts` modeled after `vscode-overlay/index.js:9-46`. Trigger:

```js
trigger: {
  process_name: ['chromium', 'chrome', 'chromium-browser', 'google-chrome', 'google-chrome-stable', 'Brave'],
}
```

(no `window_name` — chrome-family process names are sufficient for the chrome overlay's UX goal; window_name is for TUI apps like OpenCode where the terminal owns the X window.)

Curated buttons (each `core:action` with a `type://` keystroke):
- New Tab — `ctrl+t`
- Close Tab — `ctrl+w`
- Reopen Closed Tab — `ctrl+shift+t`
- New Window — `ctrl+n`
- New Incognito Window — `ctrl+shift+n`
- Switch to Next Tab — `ctrl+alt+right` (or `ctrl+page_down` on Linux)
- Switch to Previous Tab — `ctrl+alt+left` (or `ctrl+page_up` on Linux)
- Find — `ctrl+f`
- Find Next — `ctrl+g` (or `f3` on Linux)
- DevTools — `ctrl+shift+i` (or `f12`)
- Reload — `ctrl+r` (or `f5`)
- Hard Reload — `ctrl+shift+r` (or `ctrl+f5`)
- Focus Address Bar — `ctrl+l` (or `alt+d`)
- Bookmarks — `ctrl+shift+o`
- History — `ctrl+h`
- Downloads — `ctrl+j`
- Print — `ctrl+p`
- Zoom In — `ctrl+plus`
- Zoom Out — `ctrl+minus`
- Zoom Reset — `ctrl+0`
- Toggle Fullscreen — `f11`

Use icon names from the existing icon set: `icon://plus`, `icon://x`, `icon://rotate-ccw`, `icon://copy`, `icon://eye-off`, etc. If unsure of the exact icon name, use `icon://square` as a fallback (the user can refine later).

The deck:
```js
{
  name: 'Chrome',
  icon: 'addon://chrome-overlay/assets/icon.png',
  paginated: true,
  autoShow: true,
  isOverlay: true,
  trigger: { process_name: [...] },
  buttons: [ /* ~20 entries */ ],
}
```

`buttonTypes: {}` (reuse core:action — no custom React/backend).

`module.exports = { manifest }`.
</action>
<verify>
`node -e "const m = require('/works/opensource/sireno-deck-addons/chrome-overlay/index.js'); console.log(m.manifest.decks['chrome-overlay:shortcuts'].type.createDecks().shortcuts.buttons.length)"` returns ≥ 15.
</verify>
<done>
Addon exports a working manifest with curated button set.
</done>
</task>

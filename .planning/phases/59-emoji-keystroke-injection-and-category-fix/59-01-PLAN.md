# 59-01 — pasteText keystroke extension

> EMO-15 and EMO-16 are the user-visible bug "tap emoji does nothing." The fix: after `clipboardy.write(text)`, also send the platform's paste keystroke so the text actually appears in the active input field. Phase 57 already shipped the cross-platform `keyMacroProvider` (linux/darwin/windows/unsupported) — this plan wires it into the existing `methods.pasteText` so all current callers (emoji tap, emoji double-tap, `select_command` substitution) get the fix transparently.

## Context

Phase 59 decisions (CONTEXT.md):
- Extend `methods.pasteText(text)` in place. No new `sendText` method. Single API, transparent to existing callers.
- Throw if `keyMacroProvider.send` fails — let the runtime error UX (warning triangle + 4-digit code from Phase 5) surface the failure.
- Mock `keyMacroProvider` in unit tests; defer real-platform integration to manual UAT.

Existing wiring (runtime.ts:978-981):
```typescript
pasteText: async (text: string) => {
  const { pasteText: doPaste } = await import('../util/clipboard.js')
  await doPaste(text)
},
```

Existing `keyMacro` pattern (runtime.ts:983-986) and `keyMacroProvider` construction (runtime.ts:390-392) are the model to follow.

## Tasks

### Task 1: Extend methods.pasteText to send platform paste keystroke

**File:** `packages/cli/src/deck/runtime.ts`

Replace the existing `pasteText` method body (line 978-981) with one that:
1. Calls `doPaste(text)` first (existing behavior — writes to clipboard).
2. Looks up the platform paste key from a helper that maps `hostContext.os.type` to the keystroke sequence:
   - `linux` / `win32` → `'ctrl+v'`
   - `darwin` → `'cmd+v'`
   - `unsupported` → null (skip the keystroke)
3. If `pasteKeystrokeEnabled` is `false` (from config), skip the keystroke.
4. If a paste key is set (not null), call `keyMacroProvider.send(parseKeyMacro(pasteKey))` after the clipboard write.
5. Let any error from `keyMacroProvider.send` propagate (CONTEXT decision: throw, don't swallow).

The `pasteKeystrokeEnabled` flag is read from the runtime options / SirenoConfig. The cleanest wiring is to add it as an optional field on the existing `SirenoConfig` schema (Plan 59-02) and read it via a new `paste` field in the runtime options. For Plan 59-01, treat the flag as a local closure variable defaulting to `true`; Plan 59-02 wires the config field through.

Use a small helper at the top of the file (next to `markHop` from Phase 58):

```typescript
function getPlatformPasteKey(osType: HostContextOsType): string | null {
  switch (osType) {
    case "linux":
    case "win32":
      return "ctrl+v"
    case "darwin":
      return "cmd+v"
    case "unsupported":
    default:
      return null
  }
}
```

(Or inline the ternary — agent's discretion. Helper is cleaner; inline is fewer files touched.)

The new `methods.pasteText` body:

```typescript
pasteText: async (text: string) => {
  const { pasteText: doPaste } = await import("../util/clipboard.js")
  await doPaste(text)

  if (!pasteKeystrokeEnabled) return

  const pasteKey = getPlatformPasteKey(hostContext.os.type)
  if (pasteKey === null) return

  const steps = parseKeyMacro(pasteKey)
  await keyMacroProvider.send(steps)
},
```

Add a closure variable at the top of `createDeckRuntime`:
```typescript
const pasteKeystrokeEnabled = options.pasteKeystrokeEnabled ?? true
```

And extend the `DeckRuntimeOptions` interface (around line 80-104) to add:
```typescript
pasteKeystrokeEnabled?: boolean
```

# Plan 14-02: Ship Authoritative Get-Set Command Toggles

<objective>
Deliver the second Phase 14 tracer bullet as one demoable user-facing behavior: a user can declare a built-in `toggle` in `get-set` mode, see it start in a visibly pending state until the first command read succeeds, tap it to run the correct `set_on` or `set_off` command, and trust that the button reconciles to authoritative command output instead of lying about external state.
</objective>

## Tasks

<task id="14-02-01">
<title>Add the strict `get-set` schema branch and loader coverage</title>
<files>
- packages/cli/src/core/schemas.ts
- packages/cli/src/config/loader.test.ts
</files>
<action>
Extend the discriminated `toggle` schema with a `mode: "get-set"` branch that requires `get_state_command`, `set_on_command`, and `set_off_command`; accepts optional `on_values` and `off_values` string arrays; and reuses the same shared presentation plus optional `on` / `off` overrides from Plan 14-01. Reject `toggle_command` and `status_command` in this branch so miswired command models fail early with path-aware diagnostics. Add loader coverage for valid `get-set` config, missing required commands, wrong-branch fields, and token-list validation.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/config/loader.test.ts`.
</verify>
<done>
The loader accepts only the exact `get-set` contract and points users at the right branch-specific fix when config is wrong.
</done>
</task>

<task id="14-02-02">
<title>Implement authoritative get-set reads, writes, and failure handling</title>
<files>
- builtin-addons/core-buttons/src/index.ts
- builtin-addons/core-buttons/src/index.test.ts
- packages/cli/src/deck/runtime.ts
- packages/cli/src/deck/runtime.test.ts
</files>
<action>
Extend the bundled toggle instance so `get-set` mode performs an authoritative read on activation and on each refresh, tracks `pending`, `known-on`, `known-off`, and `error` display states in closure state, and maps stdout by trimming, case-folding, and checking either explicit `on_values` / `off_values` or the fallback canonical tokens `on/off`, `true/false`, and `1/0`. When the state is still unknown, taps must not guess which write command to run. When the state is known, taps choose `set_on_command` or `set_off_command` from the last authoritative value, show a temporary pending write state, and then reconcile back through the next authoritative read. If a write fails, preserve the last authoritative state and mark the button as errored until a later successful read clears it. Pin this with focused addon and runtime tests.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/deck/runtime.test.ts ../../builtin-addons/core-buttons/src/index.test.ts`.
</verify>
<done>
The shipped `get-set` toggle behaves as an externally authoritative control instead of a local optimistic switch.
</done>
</task>

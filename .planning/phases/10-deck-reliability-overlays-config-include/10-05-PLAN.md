# Plan 10-05: Nested YAML config includes

<objective>
Implement `!include path/to/file.yml` as a YAML custom tag handler in the config loader. After parse, walk the JSON tree and replace each `!include` node with the included file's content. Resolve paths relative to the defining file. Recurse with cycle detection. Deep-merge for objects, concat-with-last-wins for arrays. Update `loader.ts` to call the resolver. Maintain backward compatibility (existing configs without `!include` work unchanged).
</objective>

<task id="10-05-01">
<title>Implement include-resolver module</title>
<files>
- packages/cli/src/config/include-resolver.ts
</files>
<action>
Create `packages/cli/src/config/include-resolver.ts` exporting:

```ts
export interface ResolveIncludesOptions {
  rootPath: string  // absolute path of the root config file (for cycle-detection seed)
}

export class IncludeResolutionError extends Error {
  readonly issues: { message: string; path?: string }[]
  constructor(message: string, issues: { message: string; path?: string }[] = []) {
    super(message)
    this.name = "IncludeResolutionError"
    this.issues = issues
  }
}

export function resolveIncludes(value: unknown, definingFilePath: string, visited: Set<string>): unknown
```

Algorithm:
1. If `value` is a string `!include <path>` (the marker we set during parse via customTag), read the file at `<definingFileDir>/<path>` (or `<path>` if absolute), parse it with `parseDocument(raw, { keepSourceTokens: true })`, recursively resolve includes inside it (passing the visited set, adding the new file's absolute path), and return the result.
2. If `value` is an object, recurse over each key, merge results. For deep-merge:
   - If both existing and incoming are objects → recursively merge.
   - If existing is an array and incoming is an array → concat-with-last-wins-on-id: iterate incoming; if an element has `id` and an element with that id exists in existing, replace the existing one; else append.
   - Otherwise, incoming overwrites existing.
3. If `value` is an array, recurse over each element (apply step 1 to each).
4. Cycle detection: if `definingFilePath` is already in `visited`, throw `IncludeResolutionError` with message `Circular include detected: ${cyclePath}` and the cycle path in `issues[0].path`.
5. Mark the file as visited before recursing; unmark after (so siblings can include the same file).

Use `readFileSync` (already used in `loader.ts:76`). Use `parseDocument` + `doc.toJSON()` (same pattern as `loader.ts:83-91`).

The marker `!include` is set via parseDocument's `customTags`:
```ts
parseDocument(raw, {
  keepSourceTokens: true,
  customTags: [{
    identify: (value) => typeof value === "string" && value.startsWith("!include "),
    resolve: (doc, cstNode) => ({ __include: cstNode.source.slice("!include ".length).trim() }),
  }],
})
```

Then `resolveIncludes` checks for the `__include` key in objects.

Alternative: use `parseDocument`'s `customTags` with `createNode: true` and a `resolve` that returns the resolved content directly. Pick the simplest working approach.

<title>Tests for include resolver</title>

<action>
Write tests covering:

1. **Single include, top-level**:
   - Root file: `decks: !include decks.yml`
   - decks.yml: `- { id: a, type: ... }`
   - Expected: `result.decks` equals the array from decks.yml.

2. **Recursive include**:
   - root: `decks: !include a.yml`
   - a.yml: `decks: !include b.yml`
   - b.yml: `- { id: b, type: ... }`
   - Expected: `result.decks` equals `[{ id: 'b' }]`.

3. **Object deep-merge**:
   - root: `theme: !include theme.yml` (but theme.yml is an object, not an array — handled by the merge path)
   - Wait, an `!include` at top level replaces the whole subtree. The deep-merge only happens when both files define the same key at the same level.
   - Better test: root has `theme: { color: red }` AND `theme: !include theme.yml`, where theme.yml is `{ color: blue, font: arial }`. Expected: `theme` is `{ color: blue, font: arial }` (incoming overwrites for non-conflicting keys; for conflicting keys, last-wins).
   - Actually wait — `!include` replaces the subtree, not merges. To get deep-merge, the user writes:
     ```yaml
     theme:
       color: red
       layout: !include layouts.yml
     ```
     where layouts.yml is `{ spacing: 4 }`. The deep-merge happens at the parent level, not inside the include resolution.
   - The actual deep-merge behavior is: if two files both define `theme:` at the top level, the included file's theme is merged with the root file's theme.

4. **Array concat + last-wins on id**:
   - root: `decks: [{ id: 'a', label: 'A from root' }]`
   - root: `decks: !include decks.yml`
   - decks.yml: `- { id: 'a', label: 'A from included' }` AND `- { id: 'b' }`
   - Expected: `decks` is `[{ id: 'a', label: 'A from included' }, { id: 'b' }]`.

5. **Cycle detection**:
   - a.yml: `decks: !include b.yml`
   - b.yml: `decks: !include a.yml`
   - Expected: throws IncludeResolutionError with message containing "Circular include".

6. **Missing file**:
   - root: `decks: !include nonexistent.yml`
   - Expected: throws IncludeResolutionError with message containing "not found".

7. **Absolute path allowed**:
   - root: `decks: !include /tmp/absolute-decks.yml`
   - Expected: works without throwing.

8. **Sibling re-include** (same file included twice from different keys):
   - root: `decks: !include common.yml` AND `buttons: !include common.yml`
   - Expected: both keys get a fresh copy (deep-cloned) of common.yml's content.

Use `os.tmpdir()` for fixture files; write small YAML files inline; clean up in `afterEach`.

# Plan 12-03: Persistent error surfaces

<objective>
Wire the existing `core:temporary-error` button plumbing into the config-replacement pipeline so invalid buttons leave a red surface at their slot until the next successful config emission, and missing navigation targets do not change the active deck but show the error at the source slot.
</objective>

</files>
<action>

<title>Replace invalid buttons with core:temporary-error at assigned slots</title>
<files>
- packages/cli/src/cli/commands/run.ts
- packages/cli/src/deck/runtime.ts
</files>
<action>
1. In `run.ts:buildRuntime` (around lines 550-669), after `positionButtons(config, keyCount)` returns the assigned slots, build a map `Map<deckId, Set<position>>` of invalid button slots from `validateFull`. Walk the assigned slots; if a button's `(deckId, position)` is in the invalid set, replace it with a stub button object of type `core:temporary-error` carrying `config: { reason, deckId, position }`.
2. Do NOT re-run validation on the stub (it short-circuits the recursive validation chain).
3. Reuse `applyConfigErrorReplacements` (lines ~740-829 in current `run.ts`); refactor it to take the assigned-slot list instead of a fresh deck walk so it works with the deterministic output of `positionButtons`.
4. Drop the current `error`-level log of the full broken config; keep a `warn` log per invalid button with `{ deckId, position, reason }`. Full config dump is only at debug level.
5. Add `// ponytail: invalid buttons keep their assigned slot — the user sees exactly which slot is broken` comment.
</action>

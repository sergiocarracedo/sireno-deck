# Phase 05 Plan 01 — Device Models + Emulator Server + Virtual Stream Deck

## Context

Phase 05 builds the emulator. Before we can show a deck in a browser, we need three small, testable modules:

1. **`src/device/models.ts`** — maps `--device-model` flag values to `{ keyCount, columns, rows }`. The legacy code hardcoded layouts for 1/2/3/6/8/15/32 keys; we go to named models (mk2, plus, mini, xl) per the Phase 03 plan.
2. **`src/render/emulator-server.ts`** — vite spawn manager for emulator mode. Sibling of `vite-server.ts` (Phase 04) but with different child entry point and no auto-restart on crash (the shell user will see errors directly).
3. **`src/system/virtual-stream-deck.ts`** — `VirtualStreamDeckLifecycle` for emulator mode. No-op device that emits button events when the shell calls `injectKeyEvent(keyIndex, type)`.

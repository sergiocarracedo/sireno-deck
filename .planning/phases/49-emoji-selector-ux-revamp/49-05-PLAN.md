## Context

CONTEXT amendment A1 (2026-06-06) supersedes the original Phase 49 "HID output mechanism (Per-OS shim)" decision. The post-ship feedback reports the existing `pasteText` fallback (clipboard + Cmd/Ctrl+V) is the intended delivery path, but it is silently failing in environments where the underlying clipboard tool is missing or misconfigured — the `execa`-spawned `xclip` / `pbcopy` / PowerShell call swallows stderr in subtle ways. The decision is to keep the clipboard-paste model but switch the write step to the `clipboardy` npm package, which surfaces clear errors when the host tool is unavailable.

`clipboardy` is actively maintained and used internally by `execa`. It detects the host platform and routes to the right tool automatically. The paste keystroke (`xdotool ctrl+v` / `osascript cmd-v` / `SendKeys ^v`) stays per-OS — there is no cross-platform alternative for the keystroke step, and execa remains a dep for that.

With the HID shim gone, the `select_command_shortcode` config field is dead weight. Double-tap falls back to `methods.pasteText(shortcode)` (the same path tap uses when no `select_command` is set). If a user supplies `select_command` for tap, double-tap becomes a no-op (matches the original CONTEXT contract for the `select_command_shortcode` unset case).

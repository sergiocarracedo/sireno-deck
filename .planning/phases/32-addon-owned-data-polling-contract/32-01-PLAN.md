# Plan 32-01: Land The Core-Agnostic Payload And Split-Cadence Runtime Contract

<objective>
Establish the core runtime contract Phase 32 depends on before migrating capability domains. This slice delivers one end-to-end behavior: mounted addons can provide a polling callback that returns data payloads, core stores and forwards the latest payload into render props, and polling cadence is decoupled from render cadence. The runtime stays capability-agnostic; it does not learn system-metric or media-specific data models.
</objective>

## Tasks

<task id="32-01-01">
<title>Add payload-oriented mounted button polling contract and generic cadence resolution</title>
<files>
- packages/cli/src/addon/api.ts
- packages/cli/src/deck/runtime.ts
- packages/cli/src/core/schemas.ts
</files>
<action>
Extend mounted button contract types in `packages/cli/src/addon/api.ts` so addon polling callbacks return payload data and render props receive the latest payload snapshot through a generic field. In `packages/cli/src/deck/runtime.ts`, replace the single `refresh + render` scheduler path with two generic loops per button: polling loop (collect payload) and render loop (render/publish current state), each reading resolved cadence values from addon definition/config inputs. Keep runtime internals typed as `unknown` for payload storage so core stays capability-agnostic. Update `packages/cli/src/core/schemas.ts` so interval field ownership is addon-local (addon schema/config), while core only keeps generic envelope validation.
</action>

</verify>
<done>
The public addon API and runtime scheduling path now implement callback-payload handoff and split cadence without widening core into capability-owned domain contracts.
</done>
</task>

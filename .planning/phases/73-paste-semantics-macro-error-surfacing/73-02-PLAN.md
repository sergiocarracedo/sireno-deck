# Plan 73-02: keyMacroProvider error surfacing

<objective>
BUG-06: All 3 platform key-macro providers currently swallow failures (linux.ts: // Non-fatal, darwin.ts: warn, windows.ts: warn). Fix: make them throw on failure. Add `"key-macro"` to `RuntimeButtonErrorKind`. The runtime `keyMacro` handler at line 1013 catches the throw and calls `showRuntimeButtonError` so the failure appears on the button with button context.
</objective>

<task id="73-02-05">
<title>Wire keyMacro handler in runtime.ts with try/catch error surfacing</title>
<files>
- packages/cli/src/deck/runtime.ts
</files>
<action>
Modify the `keyMacro` handler at lines 1013-1016. Wrap the provider call in try/catch and call `showRuntimeButtonError` on failure:

Current code (lines 1013-1016):
```ts
      keyMacro: async (sequence: string) => {
        const steps = parseKeyMacro(sequence)
        await keyMacroProvider.send(steps)
      },
```

Replace with:
```ts
      keyMacro: async (sequence: string) => {
        const steps = parseKeyMacro(sequence)
        try {
          await keyMacroProvider.send(steps)
        } catch (error) {
          await showRuntimeButtonError(button, deckId, 'key-macro', error)
        }
      },
```

The `keyMacroProvider`, `button`, `deckId`, and `showRuntimeButtonError` are all in the closure scope of `createInternalButtonHandler` where this handler is defined.

This ensures that any throw from the platform provider (including the new throws from linux/darwin/windows) is caught and surfaced on the button, matching the same error pattern used for `navigateToDeck` (lines 1002-1004) and `pasteText` (Plan 73-01).
</action>

</verify>
<done>
runtime.ts keyMacro handler catches provider throws and calls showRuntimeButtonError with 'key-macro' kind.
</done>

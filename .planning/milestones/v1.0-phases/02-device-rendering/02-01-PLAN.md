# Plan 02-01: Device detection and reconnect lifecycle

<objective>
Implement the first end-to-end hardware slice for Phase 2: the daemon can detect attached Stream Deck devices on Linux, choose the right one using the discussed selection rules, report model and serial, and keep trying to reconnect when the device disappears. This plan proves the hardware lifecycle before any rendering complexity is added.
</objective>

<action>
Create `packages/cli/src/device/stream-deck.ts` with a small device abstraction tailored to Phase 2: enumerate attached devices, choose a device using the locked rules (auto-pick one, serial selector, fail-and-list for ambiguous matches), connect to the chosen device, subscribe to disconnect events, and expose a reconnect loop capped at 5 minutes with sparse progress logging. Add `packages/cli/src/device/linux-udev.ts` to detect Linux-specific permission/access failures and format the clear udev guidance required by `INFRA-02`; keep it separate from generic selection logic so the Linux path is testable. Add tests covering single-device success, multi-device ambiguity, serial selection, reconnect state behavior, and Linux permission diagnostics with mocked device/library failures.
</action>

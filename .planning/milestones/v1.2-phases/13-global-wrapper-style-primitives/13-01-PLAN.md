# Plan 13-01: Ship Registry-Backed Primitive Contracts And Early Config Validation

<objective>
Deliver the first Phase 13 tracer bullet as one demoable user-facing behavior: addons and bundled addons can register global wrapper/style primitives through the public addon contract, users can reference those primitives directly in config with `wrapper_id` and `style_id`, and the loader rejects unknown or wrong-kind refs with the same readable diagnostics the repo already uses for bad addon types.
</objective>

## Tasks

<task id="13-01-01">
<title>Add separate wrapper/style primitive definitions to the addon API and registry</title>
<files>
- packages/cli/src/addon/api.ts
- packages/cli/src/addon/registry.ts
- packages/cli/src/addon/registry.test.ts
</files>
<action>
Extend `packages/cli/src/addon/api.ts` so addons can declare separate wrapper and style primitive definitions instead of one combined visual blob. Then extend `packages/cli/src/addon/registry.ts` with registry-backed lookup and duplicate detection for those primitives using global namespaced ids, matching the user-approved direction and the repo's existing asset-key pattern. Keep the API narrow and explicit: this phase needs primitive existence and kind tracking, not a universal compatibility engine. Update `packages/cli/src/addon/registry.test.ts` so duplicate primitive ids and primitive lookups are pinned by focused tests.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/addon/registry.test.ts`.
</verify>
<done>
The public addon contract and live registry can register and resolve separate wrapper/style primitives by global id without creating a second extension store.
</done>
</task>

<task id="13-01-02">
<title>Validate config-authored primitive references on the existing loader seam</title>
<files>
- packages/cli/src/core/schemas.ts
- packages/cli/src/config/loader.test.ts
</files>
<action>
Add direct `wrapper_id` and `style_id` support to the approved config-authored button surface in `packages/cli/src/core/schemas.ts`, then validate those references against the loaded addon registry during config validation. Keep the failure boundary exactly where the phase context requires it: config-authored refs must fail before runtime start, with the repo's existing `ConfigValidationError` path and line metadata preserved through the loader. Reject unknown refs and kind mismatches explicitly, but do not widen this phase into a full primitive compatibility matrix. Update `packages/cli/src/config/loader.test.ts` with focused cases for valid primitive refs, unknown primitive ids, and wrong-kind refs so the early-failure contract stays pinned.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/config/loader.test.ts`.
</verify>
<done>
Users can reference registered wrapper/style primitives from config, and bad refs fail early with readable diagnostics instead of becoming renderer surprises.
</done>
</task>

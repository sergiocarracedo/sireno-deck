# Plan 04-03: Fan and media rich built-in buttons

<objective>
Deliver the remaining Phase 4 behaviors for fan and media buttons. This plan closes the live-data loop by handling unreliable sensor availability explicitly and adds the approved command-driven media model without introducing a new media integration subsystem.
</objective>

## Tasks

<task id="04-03-01">
<title>Add fan and media button schemas with example config coverage</title>
<files>
- config.yml
- packages/cli/src/core/schemas.ts
</files>
<action>
Extend `packages/cli/src/core/schemas.ts` with built-in `fan` and `media` button schemas. `fan` must validate the fields needed for the rich built-in sensor layout and its stable unavailable fallback. `media` must validate the approved Phase 4 contract: one authoritative `status_command`, one multiline `display_command`, and one tap action command for play/pause control. Update `config.yml` with representative fan and media examples that match those contracts.
</action>
<verify>
grep 'type: z.literal("fan")\|type: z.literal("media")' packages/cli/src/core/schemas.ts && grep 'type: fan\|type: media' config.yml
</verify>
<done>
The config layer supports the last two Phase 4 built-in button types, and the example config demonstrates both contracts concretely.
</done>
</task>

<task id="04-03-02">
<title>Implement fan fallback and authoritative media runtime behavior</title>
<files>
- packages/cli/src/system/live-metrics.ts
- packages/cli/src/deck/runtime.ts
- packages/cli/src/render/reconciler.ts
- packages/cli/src/render/text-image.ts
</files>
<action>
Extend `packages/cli/src/system/live-metrics.ts` so fan reads return a normalized result that can represent either sensor data or the locked stable unavailable state when sensors are missing or unreadable. Extend `packages/cli/src/deck/runtime.ts` so media buttons execute their play/pause action through the existing command executor but keep rendered state authoritative from `status_command` and multiline `display_command` polling. Update `packages/cli/src/render/reconciler.ts` and `packages/cli/src/render/text-image.ts` so both fan and media buttons render dedicated rich built-in layouts, including multiline media content and the stable fan unavailable view.
</action>
<verify>
grep 'fan' packages/cli/src/system/live-metrics.ts && grep 'display_command' packages/cli/src/deck/runtime.ts && grep 'media' packages/cli/src/render/text-image.ts
</verify>
<done>
Fan buttons degrade gracefully when sensors are unavailable, and media buttons control play/pause while rendering authoritative multiline track state.
</done>
</task>

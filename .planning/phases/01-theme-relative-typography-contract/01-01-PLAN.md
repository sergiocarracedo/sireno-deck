# Plan 01-01: Ship The Shared Typography Size Contract

<objective>
Land the first tracer bullet for Phase 1 by making one shared `Text` node truthful again: typography roles publish the active base, `Text` owns the final size ladder, and the default theme surfaces size metadata without taking over sizing behavior. This slice matters because every later raw-caller migration depends on the shared contract being correct first; otherwise the sweep would just spread the wrong semantics further.
</objective>

## Tasks

<task id="01-01-01">
<title>Refactor typography utilities and `Text` so role base and size token responsibilities stop fighting each other</title>
<files>
- packages/cli/src/render/theme-utilities.ts
- packages/cli/src/ui/Text.tsx
</files>
<action>
Update `packages/cli/src/render/theme-utilities.ts` so `.font-main`, `.font-aux`, and `.font-mono` stop assigning the final `font-size` directly and instead publish the active typography-role base through explicit CSS custom properties while still owning family, weight, and tracking. Then adjust `packages/cli/src/ui/Text.tsx` so the existing `size` tokens (`xs`, `sm`, `md`, `lg`, `xl`, `2xl`) resolve from that role-local base with one moderate shared ladder and `md` equal to the exact role base. Keep the public `Text` API unchanged, keep the fit-mode behavior untouched, and do not introduce theme-configurable per-size multipliers or any shrink-fit work.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/render/dom-host.test.tsx src/cli/commands/start.test.ts`.
</verify>
<done>
The shared browser utility stylesheet and `Text` component now compose into one truthful role-relative size contract instead of two competing font-size sources.
</done>
</task>

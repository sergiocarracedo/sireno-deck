### 37-01-01: Add watchAddonSources to start.ts

- **file**: `packages/cli/src/cli/commands/start.ts`
- **action**: |
    After `createRuntime(initialLoad)` returns and `runtime.start()` is called, add a new exported function `watchAddonSources(rootDir: string, runtime: DeckRuntime, registry: AddonRegistry): () => void` that:
    1. Calls `watch(addonSourcesGlob(rootDir), { persistent: false, recursive: true }, scheduleAddonReload)` — where `addonSourcesGlob` returns the path to the `addons/` directory (Node's `fs.watch` recursive mode is natively available in Node.js v20+)
    2. Maintains its own `addonReloadTimer: NodeJS.Timeout | undefined` with a 100ms trailing-edge debounce (same pattern as `CONFIG_RELOAD_DEBOUNCE_MS` for config)
    3. On debounce fire: calls `runtime.updateAddonRegistry(registry)` (new method — see 37-01-02)
    4. Returns a cleanup function that clears the timer and closes all watchers
    Wire the watcher into `startDaemon()` after `runtime.start()`, storing the cleanup returned by `watchAddonSources` alongside `stopWatchingConfig` so both can be closed on daemon shutdown.
- **verify**: `node -e "require('./packages/cli/src/cli/commands/start.ts')" && echo "compile ok"`
- **done**: When `watchAddonSources` is exported and called in `startDaemon()`, and the 100ms debounce pattern matches the existing `watchConfigFiles` pattern.

### 37-01-02: Add updateAddonRegistry to DeckRuntime

- **file**: `packages/cli/src/deck/runtime.ts`
- **action**: |
    Add `updateAddonRegistry(registry: AddonRegistry): void` to `DeckRuntime` interface and implement it in `createDeckRuntime`. The method:
    1. Calls `registry.listButtons()` to get the new button type set
    2. Diff this set against the `runningButtonTypes: Set<string>` stored at startup (initialize this set in `startDaemon` from the initial `registry.listButtons()` call)
    3. If the diff is non-structural (same type set, only internal state/instance data changed): calls `invalidateMountedStore()` to trigger a full deck surface re-render while preserving the runtime instance and hardware transport
    4. If the diff is structural (types added/removed): logs a warning and does NOT fall back to `reloadRuntime()` — structural changes require a full restart; document this in the method comments
    Store `runningButtonTypes` as a module-level Set inside the runtime closure, populated on first `start()` call.
- **verify**: `grep -n 'updateAddonRegistry\|runningButtonTypes' packages/cli/src/deck/runtime.ts`
- **done**: When `updateAddonRegistry` diffs registry state and calls `invalidateMountedStore()` for non-structural changes.

### 37-01-03: Add structural-change detection

- **file**: `packages/cli/src/deck/runtime.ts`
- **action**: |
    In `updateAddonRegistry`, implement the structural vs. non-structural diff:
    1. Non-structural: `nextButtonTypes ⊆ runningButtonTypes && runningButtonTypes ⊆ nextButtonTypes` — all types identical, only content changed
    2. Structural: any type added or removed from the running set
    For structural changes: log at `warn` level: `"addon registry structural change detected — full restart required for addon additions/removals"`. Do NOT call `invalidateMountedStore()` or `reloadRuntime()`.
- **verify**: `grep -n 'structural change detected' packages/cli/src/deck/runtime.ts`
- **done**: When structural changes are detected and warned about without triggering `invalidateMountedStore()`.

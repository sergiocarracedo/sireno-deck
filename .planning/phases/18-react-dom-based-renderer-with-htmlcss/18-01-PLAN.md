# Plan 18-01: Browser-Only Tracer Bullet

<objective>
Build the first real browser-only tracer bullet for Phase 18. This plan introduces the persistent Chromium deck page, the react-dom host, the shared `buttonFrame`, and the first built-in action/change-deck fixture, but unlike the stale Phase 18 version it also removes browserless startup fallback from the live daemon path immediately.
</objective>

## Tasks

<task id="18-01-01">
<title>Create the persistent browser renderer and shared render preset seam</title>
<files>
- packages/cli/package.json
- packages/cli/src/render/browser-renderer.ts
- packages/cli/src/render/browser-renderer.test.ts
- packages/cli/src/render/render-preset.ts
</files>
<action>
Add the Playwright dependency needed for a Chromium-backed renderer host. Create `packages/cli/src/render/browser-renderer.ts` with a long-lived browser/context/page lifecycle that can start once, keep one active deck page alive, update deck HTML, capture the full deck, and crop per-key raw buffers using a shared preset imported from a new browser-neutral `packages/cli/src/render/render-preset.ts` module. Move Stream Deck key geometry/preset types needed by browser rendering into that new module so later plans can delete `text-image.ts` cleanly.
</action>
<verify>
Run `grep -n "playwright" packages/cli/package.json && ls packages/cli/src/render/browser-renderer.ts packages/cli/src/render/render-preset.ts && pnpm --filter sireno-deck-cli exec vitest run src/render/browser-renderer.test.ts`.
</verify>
<done>
The repo declares the browser dependency, exposes a persistent browser renderer seam, and no longer depends on `text-image.ts` for shared key geometry.
</done>
</task>

# Plan 19-01: Theme CSS Variables and First Utility-Backed Button

<objective>
Introduce the actual browser-surface theme bridge for Phase 19. This plan exports Sireno theme tokens as namespaced CSS variables on the deck root, ships a narrow core-owned utility stylesheet for theme-token classes, and proves the contract end-to-end with a builtin browser-rendered button and committed review fixture.
</objective>

## Tasks

<task id="19-01-01">
<title>Export resolved Sireno theme tokens as browser-surface CSS variables</title>
<files>
- packages/cli/src/config/theme.ts
- packages/cli/src/config/theme.test.ts
- packages/cli/src/render/theme-utilities.ts
- packages/cli/src/render/dom-host.tsx
- packages/cli/src/render/dom-host.test.tsx
</files>
<action>
Create a browser-facing theme utility module that derives a namespaced CSS-variable map from the resolved Sireno theme contract, including the existing color tokens and typography roles. Wire `dom-host.tsx` to emit those variables on the browser deck root and include the generated utility stylesheet in the rendered HTML shell. Keep the theme loader as the single source of truth rather than introducing a second theme schema or token registry.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/config/theme.test.ts src/render/dom-host.test.tsx` and confirm the rendered deck HTML contains `--sireno-` variables plus the utility stylesheet.
</verify>
<done>
The browser-rendered deck surface publishes the active Sireno theme through namespaced CSS variables and exposes a narrow utility layer that the rest of the phase can consume.
</done>
</task>

# Plan 03-01: Ship The Shared Text Markup Contract

<objective>
Land the first honest Phase 3 tracer bullet by teaching shared `Text` to parse and render the new strict-whitelist mini markup language without involving date-time yet. This slice matters because the phase was explicitly re-scoped from a widget-local formatter into a shared text contract, so the parser/render seam, whitelist rules, and literal fallback behavior have to be truthful before date-time starts depending on them.
</objective>

## Tasks

<task id="03-01-01">
<title>Implement the shared `Text` parser/render seam with strict whitelist rules and literal fallback</title>
<files>
- packages/cli/src/ui/Text.tsx
- packages/cli/src/ui/index.ts
- packages/cli/src/render/theme-utilities.ts
</files>
<action>
Extend `packages/cli/src/ui/Text.tsx` so string children are parsed through one strict-whitelist nested mini markup language owned by shared `Text`. The grammar must support structural `|` line breaks, `*...*` accent-bold shorthand, existing tone-token tags (`foreground`, `primary`, `accent`, `success`, `danger`), shared size tags (`xs`, `sm`, `md`, `lg`, `xl`, `2xl`), and `<blink>...</blink>` composition. Implement one small internal AST or equivalent explicit intermediate structure before rendering nested output, keep parsing limited to string children, and make any malformed structure, unknown tag, or unsupported tag combination fall back to the original literal source text with no partial recovery. Reuse the existing shared tone/size vocabulary instead of inventing parallel semantics, and add only the narrow utility/CSS support needed for rendered line stacks or blink presentation. Keep `Text` as the public API owner; do not add a separate `RichText` component or theme-owned inner parser seam.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/render/dom-host.test.tsx`.
</verify>
<done>
Shared `Text` can render the whitelist markup language through the real DOM/theme seam, and invalid markup deterministically falls back to the original literal text.
</done>
</task>

<task id="03-01-02">
<title>Prove themes stay outer observers while shared rich text semantics remain core-owned</title>
<files>
- packages/cli/src/themes/default/ButtonFrame.tsx
- packages/cli/src/config/theme.ts
- packages/cli/src/render/dom-host.test.tsx
</files>
<action>
Keep the theme presentation contract limited to the same outer text metadata (`align`, `fit`, `size`, `tone`, `typography`) even after rich markup lands. If helper types or metadata assertions need minor updates, make them here, but do not expose inner AST or per-tag hooks to themes. Extend focused DOM-host coverage so the real browser/theme render seam proves nested rich text still flows through the default theme wrapper as ordinary outer `Text` content while the inner rich semantics remain core-owned inside `Text`. Include coverage for line breaks, nested tone/size composition, literal fallback, and the fact that theme wrappers do not become markup owners.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/render/dom-host.test.tsx`.
</verify>
<done>
The shared rich text contract is visible through the real theme seam without giving themes ownership of inner parsing or markup rendering semantics.
</done>
</task>

<must_haves>
- Do not widen into arbitrary HTML/Markdown or open-ended tag extensibility.
- Do not add an opt-in prop or separate component; this slice follows the locked `Text`-always-parses-strings decision.
- Do not let widget code or themes own inner parsing behavior.
- Keep invalid-markup behavior binary: full literal fallback or valid render, nothing in between.
</must_haves>

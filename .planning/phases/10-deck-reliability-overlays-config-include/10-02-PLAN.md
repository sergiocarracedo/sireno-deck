# Plan 10-02: Wayland+GNOME window title via D-Bus

<objective>
Extend the existing `wayland-gnome.ts` provider to ALSO call `FocusTitle` on the same `org.gnome.Shell.Extensions.WindowsExt` D-Bus interface, in parallel with `FocusClass`. Populate `snapshot.windowTitle` so VS Code and OpenCode overlays' `window_name` triggers match. Fall back gracefully when the extension doesn't expose `FocusTitle`.
</objective>

<action>
Modify the `poll` function in `wayland-gnome.ts:152-179`:

Replace the single `await probe.focusClass()` with:
```ts
const [rawClass, rawTitle] = await Promise.all([
  probe.focusClass(),
  probe.focusTitle ? probe.focusTitle() : Promise.resolve(""),
])
```

Then build the snapshot:
```ts
const name = typeof rawClass === "string" && rawClass.length > 0 ? rawClass : null
const title = typeof rawTitle === "string" && rawTitle.length > 0 ? rawTitle : null
emit(name, title)
```

Update `emit(name)` to `emit(name: string | null, title: string | null)`:
```ts
const emit = (name: string | null, title: string | null): void => {
  if (name === lastName && title === lastTitle) return
  lastName = name
  lastTitle = title
  const snapshot: ActiveAppSnapshot | null =
    name === null ? null : { name, windowTitle: title, processId: null }
  for (const handler of subscribers) handler(snapshot)
}
```

Add `let lastTitle: string | null = null` alongside `lastName`.

Update `getActive` and `subscribe` similarly to return the last title.

The snapshot type already has `windowTitle: string | null` — no interface change needed.

Failure handling: if `Promise.all` rejects, the existing `consecutiveFailures` counter catches it. A partial rejection (one of the two fails) still throws the whole `Promise.all`, which is correct behavior — it indicates a real extension issue.
</action>

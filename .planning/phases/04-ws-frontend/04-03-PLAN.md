# Phase 04 Plan 03 — React Hooks + WS Client + Integration

## Context

Plan 01 built the data plane (API types, protocol, bridge, vite spawn). Plan 02 built the vite plugin + frontend React shell with mock data. This plan wires them together: the frontend connects to the bridge over WS, the bridge feeds pub-sub state into `state` messages, React hooks subscribe to channels, and button clicks dispatch `button-action` gestures that the CLI runtime receives.

Locked decisions from CONTEXT.md:

- **State sync**: per-channel pub-sub (debounced 100ms).
- **Reconnect strategy**: auto-reconnect with exponential backoff (1s → 30s cap).

Tracer bullet: run `sireno run --dev`, browser opens the frontend, click a `core:action` button, observe the action's effect (e.g., stdout log).

## Notes for executor

- `useAddonChannel` uses a module-level `ChannelRegistry` singleton so the bridge client can publish into it without prop drilling. Same pattern as the CLI's pub-sub.
- WS client reconnect: use `setTimeout` with exponential backoff. Track attempt count. After 10 attempts, emit `failed` and stop retrying.
- App.tsx uses React 19 `createRoot` + `<StrictMode>` wrapper (helps catch double-mount bugs in dev).
- `run` command: keep it foreground (don't daemonize yet). Phase 10 handles the daemon lifecycle.
- The integration test uses jsdom. Add `/** @vitest-environment jsdom */` at top.

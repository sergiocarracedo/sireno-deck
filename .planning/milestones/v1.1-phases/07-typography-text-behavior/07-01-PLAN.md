# Plan 07-01: Theme-Driven Typography And Clip Behavior

<objective>
Replace the shared renderer's hardcoded text styling with the narrow theme typography contract approved in `07-CONTEXT.md`. This plan is a single-layer-justified renderer/config slice because Phase 7 is explicitly a renderer/theme pass, but it still delivers a demoable result: the same button visuals render from theme tokens with deliberate clip-only behavior rather than accidental overflow.
</objective>

## Tasks

<task id="07-01-01">
<title>Extend theme loading with the approved typography roles</title>
<files>
- packages/cli/src/config/theme.ts
- packages/cli/src/config/theme.test.ts
- themes/dark.yml
- themes/light.yml
</files>
<action>
Update the strict theme schema in `packages/cli/src/config/theme.ts` to require a nested `typography` object with exactly three roles: `main_text`, `auxiliary_text`, and `monospace`. Give each role only the fields needed by the current SVG renderer, such as `font_family`, `font_size`, `font_weight`, and optional `letter_spacing`, while keeping the existing color contract untouched. Update `packages/cli/src/config/theme.test.ts` to cover both built-in and file-path theme loading with the expanded shape, then add matching typography blocks to `themes/dark.yml` and `themes/light.yml` so shipped themes satisfy the new schema.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/config/theme.test.ts`.
</verify>
<done>
`resolveTheme()` rejects themes without the required typography roles, and the shipped light/dark themes load successfully with the new nested typography contract.
</done>
</task>

<task id="07-01-02">
<title>Route shared SVG text through theme typography slots</title>
<files>
- packages/cli/src/render/text-image.ts
- packages/cli/src/render/text-image.test.ts
</files>
<action>
Refactor `packages/cli/src/render/text-image.ts` so repeated inline text attributes are replaced by a small helper or slot map that reads from `theme.typography`. Map the existing shared text uses onto the approved roles: primary labels/value text to `main_text`, secondary labels/detail text to `auxiliary_text`, and any explicitly monospace-style output to `monospace` if applicable. At the same time, make clip-only overflow explicit for shared text slots by rendering text inside bounded SVG regions or clip paths instead of relying on the outer raster crop. Preserve the existing visual variants and keep the phase scoped to clip only; do not implement ellipsis or marquee.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/render/text-image.test.ts`.
</verify>
<done>
`renderTextImage()` no longer hardcodes shared font stacks/metrics inline for the main text slots, and tests cover theme-driven output plus deliberate clip-only rendering.
</done>
</task>

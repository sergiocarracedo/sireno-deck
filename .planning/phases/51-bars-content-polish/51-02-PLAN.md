# Plan 51-02: system-status consumer — populate displayValue, drop value grid, pass theme primary

<objective>
After Plan 51-01, the `Bars` component can render the value as rotated in-bar text with the negative color. This plan updates the system-status addon's bars button to actually use that capability: populate `displayValue` from `displayMetric.formattedValue` so the value text reads `"12.3 GB"`, `"67%"`, etc., and drop the now-redundant separate value grid below the bars. The bars button becomes a single `Bars` component with formatted values inside each bar. The DOM blend path is the default; the sharp path takes an explicit precomputed color (the Bars component already handles both paths).
</objective>

<action>
In `packages/cli/src/builtin-addons/system-status/buttons/bars.tsx`:

1. Inside the `barsItems` map (lines 104-117), add `displayValue: displayMetric.formattedValue` to each returned object:
```ts
return {
  color: displayMetric.color,
  displayValue: displayMetric.formattedValue,
  maxValue: barValue.maxValue,
  title: displayMetric.label,
  value: barValue.value,
}
```

2. Remove the separate value grid (lines 125-138). The `<div className="grid gap-1" style={{ gridTemplateColumns: `repeat(${displayMetrics.length}, minmax(0, 1fr))` }}>` block and the `<Text>` map inside it are deleted. The bars now own the value display.

3. Simplify the outer container. Before:
```tsx
<div className="flex h-full w-full min-h-0 flex-col justify-between gap-2">
  <div className="min-h-0 flex-1 overflow-hidden">
    <Bars items={barsItems} />
  </div>
  <div className="grid gap-1" style={{ gridTemplateColumns: ... }}>
    {/* value grid */}
  </div>
</div>
```

After (drop the outer flex column; just wrap Bars in a sized container):
```tsx
<div className="h-full w-full min-h-0 overflow-hidden">
  <Bars items={barsItems} />
</div>
```

The `flex flex-col justify-between` and the two-child layout were needed when there was a separate value grid below the bars. Now there's just one child (`Bars`), so the flex column is unnecessary.

4. Clean up the import: `Text` from `@/ui/index` (line 11) is no longer used after removing the value grid. Remove the `Text` import. `Bars` stays. If any other import becomes unused as a result (e.g. the formatter path), remove it too.

5. Theme primary: for the DOM blend path (the default), the `Bars` component does not need `themePrimaryHex` because `mix-blend-mode: difference` handles the visual inversion at render time. The `useSharpPath` prop defaults to `false`. Leave both as `undefined` for this plan. If the system-status consumer ever needs to render in the sharp path, a follow-up plan can wire the active theme's primary hex through the render-time context.

6. Run typecheck and the full system-status test suite to confirm no regressions. If a system-status test asserts the existence of the removed value grid, update that test to assert the in-bar value instead.

# Plan 28-01: Core TSX UI Kit On One Real Raw-Source Addon

<objective>
Land the first honest Phase 28 tracer bullet: the committed Phase 23 raw-source addon fixture renders through a core-owned `Icon`/`Text`/`Chip` TSX kit from the public root export, and the runtime exposes a real presentation-only theme seam for that kit. This slice matters because the phase goal promises theme-customizable `Icon`/`Chip`/`Text`, but the live theme contract currently only covers `buttonFrame`, so the kit and its first real consumer need to become explicit together.
</objective>

<action>
Create a new `packages/cli/src/ui/` surface that exports one core-owned TSX kit for addon authors: `Icon`, `Text`, and `Chip`. `Text` must become the canonical fit contract for `wrap`, `ellipsis`, `shrink`, and auto-animating overflow marquee rather than another thin wrapper over the old helper logic. `Icon` must expose one public API that can represent both generic and brand icons while staying decorative-by-default; keep the exact Lucide/Simple Icons registry shape explicit enough that later execution does not need to guess. `Chip` should be a real reusable primitive for small status/accent labels, not just a date-time special case. Update `packages/cli/src/addon/api.ts` and `packages/cli/src/index.ts` so this component-first kit becomes part of the public authoring surface while preserving the mounted `render(props)` runtime seam from Phase 24. Then migrate the committed Phase 23 local raw-source addon fixture from helper-based output to the new kit through the root export only, and update its loader/startup tests and fixture README so the first Phase 28 slice already proves one real addon consumer instead of just infrastructure. Extend `packages/cli/src/render/theme-utilities.ts` only with the narrow utility classes the kit honestly needs for overflow, marquee, layout, and chip styling instead of introducing a broader styling system.
</action>
<verify>

</verify>
<done>

</done>
</task>

<must_haves>
- Do not reintroduce a second presentation DSL beside mounted `render(props)`; Phase 24 already locked the real authoring seam.
- Do not add full Tailwind compilation or source scanning; Phase 19 explicitly chose the curated Sireno utility stylesheet instead.
- `Text` behavior stays core-owned even if themes can restyle it.
- The first slice must already exercise one real addon consumer, not just export infrastructure.
</must_haves>

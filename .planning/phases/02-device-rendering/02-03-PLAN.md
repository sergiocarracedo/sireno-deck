# Plan 02-03: Polling updates with jitter across the deck

<objective>
Implement the scheduler slice required to finish Phase 2. This plan takes the first static render path and turns it into a repeated-update demo that drives all 15 keys at roughly 500ms while staggering work with jitter and preserving write dedupe so the device is not hit with synchronous bursts.
</objective>

## Tasks

<task id="02-03-01">
<title>Create polling scheduler with jitter</title>
<files>
- packages/cli/src/render/scheduler.ts
- packages/cli/src/render/scheduler.test.ts
</files>
<action>
Create `packages/cli/src/render/scheduler.ts` with a small polling scheduler tailored to the Phase 2 requirements. It should schedule per-key or per-render polling work around a default 500ms interval, inject jitter so multiple updates do not align into the same burst, and expose start/stop hooks that the daemon can own cleanly. Add `packages/cli/src/render/scheduler.test.ts` covering default interval behavior, jitter distribution boundaries, and cancellation on shutdown.
</action>
<verify>

</verify>
<done>
The codebase has a dedicated polling scheduler with tests proving staggered timing behavior.
</done>
</task>

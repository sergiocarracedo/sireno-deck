### Critical architectural decisions made during execution

1. **Stable default port for WS bridge**: `52937` (overridable via `SIRENO_WS_PORT` or `opts.port`). User said ports must auto-select per session, so this is now OPTIONAL override.

2. **Vite config**:
   - `server.fs.allow = [cliRoot]` — allows reading addon frontends outside frontend root
   - `resolve.alias['@'] = cliRoot + '/src'` — point `@/` at packages/cli/src so addon frontends can use `@/ui`, `@/themes/utils/cn`, etc.

3. **Static imports for built-in addon frontends** (per user choice of option 2):
   - `Deck.tsx` has `BUILTIN_ADDON_FRONTENDS = { 'date-time': DateTimeFrontend }`
   - Vite bundles them at build time
   - Dynamic loading of raw-source addons deferred to later phase (needs Vite plugin work)

4. **Direct relative imports in date-time/frontend.tsx**: `import { Text } from '../../ui/Text'` instead of `import { Text } from '@/ui'`. The `@/ui` barrel loads everything, including `LabelValueListSurface` → `Icon` → `addon/api` → `node:path`. Direct imports avoid Node deps in browser.

### Bugs found and fixed

1. **Path resolution bug** (`01d11a7`): `frontendDir` was `../../../frontend` (3 levels up = `packages/`) instead of `../../frontend` (2 levels up = `packages/cli/frontend/`). Caused silent spawn failure with `cwd` pointing at non-existent dir.

2. **`@/ui` alias pointed at wrong dir** (`d42530c`): Was `frontend/src`, should be `packages/cli/src` so addon files' `@/themes/utils/cn` resolves correctly.

3. **`theme-presentation` pulled in `node:path`** (`abe0bcf`): `import type` from `@/config/theme` triggered whole-file load in dev. Changed to `import type from '@/config/theme/schemas'` (no Node deps).

4. **`@/ui` barrel pulled in `node:path`** (`bc9077d`): Indirect via `Icon → addon/api`. Direct import of `../../ui/Text` from addon frontend breaks the chain.

5. **Race condition** (`f9d6011`): CLI sent `deck-config` before React app connected. Fixed by caching + broadcasting on every `onConnection(true)`.

## Integration Findings

### Cross-Phase Wiring — what works

- Config loading → validation → addon registry → deck runtime → emulator/real-mode all wired end-to-end.
- WS bridge v3 → vite plugin token injection → frontend WS client → ChannelRegistry.
- Frontend Deck reads `virtual:sireno/addons/registry`, renders addon components, subscribes via `useAddonChannel`.
- CLI `StatePublisher` polls OS state, broadcasts via WS, addons re-render.
- Emulator shell: mouse → gesture → WS button-action → CLI dispatch → runtime gesture state machine → addon's `onTap`.

### Cross-Phase Wiring — gaps

1. **`methods.keyMacro` and `methods.pasteText` are stubs** (`packages/cli/src/deck/methods.ts:69,73`). The interfaces exist, and Phase 07 shipped the underlying OS providers (`system/key-macro/linux.ts`, `darwin.ts`, `windows.ts`), but `methods.ts` throws `NotImplementedError` instead of dispatching. No user-facing impact in v0.1 (no built-in button uses `keyMacro` or `pasteText`), but the architecture promise of Phase 03's "methods + provider injection" is unfulfilled.

2. **5 of 6 addon pollers are stubs** (`packages/cli/src/cli/commands/addon-pollers.ts`). `date-time` returns `Date.now()` (real). `weather`, `media-player`, `system-status`, `value-display`, `brightness` return placeholder values. The frontend addons consume these channels; without real data, the buttons show empty states (e.g., "No media", "Configure weather"). The OS providers from Phase 07 exist but aren't wired to the pollers.

## Verdict

**GAPS FOUND** — 0 requirements unsatisfied, but 2 integration gaps and 1 E2E flow gap exist.

**Recommendation:** ship v0.1.0 with these gaps documented as known issues in CHANGELOG.md. The gaps don't block any v0.1 use case (the user's `config.yml` doesn't use `core:key-macro` or `core:paste-text`; the addon stubs are non-functional but visible). The addon poller wiring is a v0.2 / Phase 13+ task.

## Suggested follow-ups

1. **Wire `methods.keyMacro` and `methods.pasteText`** to the Phase 07 OS providers (~1h). Closes the integration gap.
2. **Wire OS providers to addon pollers** (~2h): replace placeholder `poll` functions with calls to `createMediaProvider`, `fetchWeather`, brightness provider, etc. Closes the E2E flow gap (live addon data).
3. **Document** the known follow-ups in `CHANGELOG.md` under a "Deferred to v0.2" section before `/complete-milestone`.

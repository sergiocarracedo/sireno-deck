## Remaining work for 55-02

### Task 1: Extend the dispatcher with the settings branch

**File:** `packages/cli/src/deck/system-buttons/system-buttons.ts`

Add a third branch in `getLastPositionSystemButton`:

```ts
// Settings entry on the main deck's reserved slot — every other deck uses
// the system-back button.
if (deck.id === options.mainDeckId && SETTINGS_DECK_ID in ctx.runtimeDecks) {
  return {
    config: {},
    id: SYSTEM_SETTINGS_TYPE,
    position: lastPosition,
    type: SYSTEM_SETTINGS_TYPE,
  } as unknown as ButtonInstance
}
```

The dispatcher needs access to `mainDeckId` and `runtimeDecks` (to check if
the settings deck exists). Extend `SystemButtonContext`:

```ts
export interface SystemButtonContext {
  config: SirenoConfig
  hostContext: HostContext
  internalLockedDeckId: string
  mainDeckId: string
  overlayDeckId: string | null
  runtimeDecks: Record<string, DeckConfig>
}
```

Order of branches in the dispatcher (priority):

1. **Overlay** — if `overlayDeckId !== null && overlayDeckId === deck.id`,
   return the toggle.
2. **Settings entry** — if `deck.id === mainDeckId` and the settings deck
   exists, return the settings entry button.
3. **System back** — if `shouldInjectSystemBack(...)` returns true, return
   the back button. Otherwise `null`.

> **Important:** the main-deck check must run before `shouldInjectSystemBack`
> (which returns `false` for main by design), so the order above is correct.

Export a new `SYSTEM_SETTINGS_TYPE = 'system-settings'` constant from
`system-buttons.ts` (or from `system-back-injection.ts` for symmetry with
`SYSTEM_BACK_TYPE`).

### Task 3: Hold-back-from-settings returns to overlay

**File:** `packages/cli/src/deck/runtime.ts`

The system-back `onHold` (around line 966) currently does:
`deckController.restoreStack([]); await activateDeckSurface(...)`.

If the user is on the settings deck while an overlay is active, holding the
back button should drop the overlay (not just pop the settings deck from the
stack). Add at the top of `onHold`:

```ts
if (overlayDeckId !== null && getDisplayDeckId() === SETTINGS_DECK_ID) {
  dismissOverlay()
  return
}
```

Use `getDisplayDeckId()` (which already accounts for the temporary error
deck) rather than `deckController.getActiveDeckId()`. Falls through to
existing restore behavior if the user is on the settings deck but no overlay
is active.

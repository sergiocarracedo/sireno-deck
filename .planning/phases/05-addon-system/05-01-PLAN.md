# Plan 05-01: Bootstrap the addon-first runtime with one bundled button

<objective>
Deliver the first real Phase 5 tracer bullet: the CLI boots through the new addon-first architecture and renders a bundled addon-backed button end-to-end. This plan creates the registry, loader bootstrap, runtime host contract, and bundled-addon workspace structure with the smallest demoable built-in button slice.
</objective>

<action>
Create the new core addon contract in `packages/cli/src/addon/api.ts` with the locked Phase 5 decisions: button definitions register a stable type name, addon-owned Zod payload schema, optional schedule metadata, and a stateful instance factory whose render output is a React element and whose lifecycle methods are explicit. Add `packages/cli/src/addon/registry.ts` plus tests for registration, duplicate type rejection, and lookup. Create a real bundled workspace package at `builtin-addons/core-buttons/` that exports at least one simple button type through the same contract the external addon path will use later. Add `packages/cli/src/addon/builtin.ts` to expose bundled registrations without introducing a second runtime contract.
</action>

<done>
The repo has a real bundled-addon workspace package and a tested registry contract that can hold addon-owned button definitions.
</done>
</task>

Refactor `packages/cli/src/deck/runtime.ts` into a generic host that instantiates registry-backed button instances, drives their explicit lifecycle, owns scheduling/invalidation/navigation, and renders their React output through the existing pipeline. Update `packages/cli/src/cli/commands/start.ts` to load bundled definitions before validation and runtime startup.
</action>

# Phase 10 Plan 01: daemon lifecycle + prod HTTP server

## Tasks

### Task 1: Extend `daemon.ts` with token + children file helpers

- File: `packages/cli/src/util/daemon.ts`
- Add `tokenFile` to `DaemonPaths` (alongside `pidFile`).
- Add `readToken`, `writeToken`, `removeTokenFile` — same pattern as PID file. Token is 32 random bytes from `node:crypto.randomBytes`, base64url-encoded. File written with mode `0600` (`writeFileSync(path, content, { encoding: "utf8", mode: 0o600 })`).
- Add `readChildren`, `writeChildren`, `removeChildrenFile`. JSON file: `{ pids: number[] }`. Plain `writeFileSync` (no mode spec) — these are operational metadata, not secrets.
- Tests: `packages/cli/src/util/daemon.test.ts` — verify token round-trip, mode 0600, missing-file returns null, children round-trip.

### Task 2: Add `http-server.ts` (Node http static server with token injection)

- File: `packages/cli/src/cli/http-server.ts` (new)
- Exports `startHttpServer({ port, distDir, getToken, logger }): { port: number; stop(): Promise<void> }`.
- Reads `distDir/index.html` once on startup (async, via `fs/promises.readFile`). Caches the HTML body as a string.
- Per request to `/`:
  - Read the token via the injected `getToken()` callback (which reads from the daemon token file).
  - If a token exists, inject `<script>window.__SIRENO_TOKEN__ = "..."</script>` before the `<script type="module"` tag. If no token, serve the original HTML.
- Requests to `/assets/*`: stream the file from `distDir/assets/<path>` with content-type from extension (`.js` → `text/javascript`, `.css` → `text/css`, default → `application/octet-stream`).
- `/health` endpoint: `200 { "status": "ok" }`.
- 404 for anything else.
- Binds to `127.0.0.1:<port>`. If port is in use, throws.
- Tests: `packages/cli/src/cli/http-server.test.ts` — start server on port 0 (let OS pick), fetch `/` and verify token injection (or absence), fetch `/health`, fetch `/assets/test.js`, fetch a 404. Use `node:http` directly (no test framework fetch).

### Task 3: Rewrite `start.ts` (track children, write token, start HTTP server)

- File: `packages/cli/src/cli/commands/start.ts`
- Extend `StartOptions` with optional `httpPort?: number` (default `3939`), `frontendDist?: string` (default `<cli>/frontend/dist`).
- After `preflight(runOptions)` and `writePid(process.pid)`:
  - Generate a token (32 random bytes, base64url) and `writeToken(token)`.
  - The background pipeline (`runRealModePipeline`) now records its spawned children. Refactor: the pipeline accepts a callback `onChildSpawn: (pid: number) => void` that `start.ts` wires to `writeChildren([...current, pid])`. (Or: pass a `children: number[]` mutable array; append from inside the pipeline. Simpler.)
  - After the pipeline is launched, call `startHttpServer({ port, distDir, getToken, logger })`. The HTTP server is part of the same process — its lifecycle is tied to the daemon.
- On the daemon's shutdown (`.finally(() => removePidFile())`), also `removeTokenFile()` and `removeChildrenFile()`. Stop the HTTP server too.
- Tests: `packages/cli/src/cli/commands/start.test.ts` — verify token + children files are written; verify they're removed on shutdown.

### Task 4: Rewrite `stop.ts` (SIGTERM each child with 5s timeout)

- File: `packages/cli/src/cli/commands/stop.ts`
- After `checkStatus`:
  - Read the children file. For each PID, send SIGTERM. Poll every 100ms until the process exits or 5s elapses. After 5s, send SIGKILL.
  - Send SIGTERM to the daemon PID itself. Same polling pattern.
  - Remove `pid`, `token`, `children` files.
- Tests: `packages/cli/src/cli/commands/stop.test.ts` — spawn a real child process (e.g., `node -e "setInterval(()=>{},1000)"`) for each tracked PID; verify SIGTERM kills it within 5s; verify files are removed.

### Task 5: Extend `status.ts` (show token + children)

- File: `packages/cli/src/cli/commands/status.ts`
- After showing PID + alive status, also show: "Token: present (32 chars)" or "Token: missing". If present, optionally show the first 8 chars for debugging (clearly mark as truncated).
- Show tracked children count and PIDs (truncated).
- Tests: `packages/cli/src/cli/commands/status.test.ts` — verify output contains the expected fields when files exist; verify graceful handling when files are missing.

### Task 6: Concurrent-start conflict prompt

- File: `packages/cli/src/cli/commands/start.ts`
- Before `preflight`, check for an existing PID. If `readPid()` is non-null and `isRunning(pid)` is true:
  - Use `@inquirer/prompts` `select({ message, choices: ["Stop and restart", "Cancel"] })`.
  - If "Stop and restart": invoke the stop flow (Task 4) before continuing.
  - If "Cancel": exit 0.
- This makes the test environment tricky — use `process.stdin.isTTY` to skip the prompt in non-interactive contexts and fall back to "Cancel" with an error message.

### Task 7: Wire HTTP server into the daemon's signal handler

- File: `packages/cli/src/cli/commands/start.ts`
- The daemon's signal handler (already registered in `run.ts:defaultSignals`) should also stop the HTTP server. The HTTP server's `stop()` returns a Promise that resolves when the listening socket is closed.

### Task 8: Verify the bundle path exists or skip HTTP server

- File: `packages/cli/src/cli/commands/start.ts`
- If `frontendDist/index.html` doesn't exist (e.g., user ran `sireno start` without `pnpm build`), log a warning and skip starting the HTTP server. The WS bridge + emulator still work via the existing dev path.

### Task 9: Update `main.ts` to add `--http-port` flag

- File: `packages/cli/src/cli/main.ts`
- Add `--http-port <number>` flag (default `3939`). Pass through to `start`.

## Acceptance

- `pnpm build` succeeds (vite build → `frontend/dist/index.html` exists).
- `pnpm dev start --emulator` still works (dev path unchanged).
- `node bin/sireno.js start` writes `~/.cache/sireno-deck-2/.../sireno-deck-2.{pid,token,children}`.
- `node bin/sireno.js status` shows PID + alive + token + children.
- `node bin/sireno.js stop` SIGTERMs each child (5s timeout → SIGKILL), then the daemon, then removes all three files.
- HTTP server starts on `127.0.0.1:3939` (or `--http-port`). `curl http://localhost:3939/` returns `index.html` with `<script>window.__SIRENO_TOKEN__ = "..."</script>` injected (if a token exists). `curl http://localhost:3939/health` returns `{"status":"ok"}`.
- Concurrent-start prompts the user; "Cancel" exits 0; "Stop and restart" kills the old daemon and starts a new one.

# Plan 75.1-01: Foundation — Vite child process + React shell

## Goal

Replace the in-process Node-side React reconciler with a Vite-served React app rendered in headless Chromium. Prove the new pipeline end-to-end on a placeholder deck before adding the WebSocket bridge.

## Context

This is the foundation tracer bullet. It establishes the three-layer boundary (CLI / Frontend Server / Frontend) with the simplest possible plumbing. The WebSocket bridge (Plan 02) and real deck wiring (Plan 02) come after this proves the layers talk to each other.

### Task 2: Vite child process supervisor in CLI

<files>
- packages/cli/src/render/frontend-server.ts (new)
</files>

<action>
1. Create `packages/cli/src/render/frontend-server.ts` exporting:
   ```ts
   export interface FrontendServerHandle {
     port: number;
     url: string;
     restartCount: number;
     close(): Promise<void>;
   }
   export function spawnFrontendServer(opts: {
     logger: pino.Logger;
     viteEntry?: string;  // default: packages/cli/frontend/vite.config.ts
   }): Promise<FrontendServerHandle>;
   ```
2. Implementation:
   - `child_process.spawn('node', ['--import', 'tsx/esm', path.join(frontendDir, 'vite-dev-entry.ts')], { stdio: ['ignore', 'pipe', 'pipe'] })`.
   - Write `packages/cli/frontend/vite-dev-entry.ts` that imports `vite` and starts a server with auto-selected port, then prints `READY <port>` on stdout.
   - Parent parses `READY <port>` from stdout (line-buffered), resolves the handle with `port` and `url = http://127.0.0.1:<port>`.
   - All other stdout/stderr is forwarded to the pino logger as `info` / `warn` / `error` based on level prefix.
   - On `exit` event: if `restartCount < 3`, sleep `1s << restartCount`, spawn again, increment counter. If `restartCount >= 3`, log fatal and exit the CLI process.
   - `close()` kills the child and waits for it to exit.
</action>

<verify>
- Unit test (`packages/cli/src/render/__tests__/frontend-server.test.ts`): spawn with a fake vite entry that prints `READY 5180`; assert `handle.port === 5180` and `handle.url === 'http://127.0.0.1:5180'`. (Use a child entry script that doesn't actually start a server — just prints the line and stays alive.)
- Unit test: spawn with an entry that exits immediately; assert `restartCount` reaches 3 and the supervisor calls `process.exit(1)`. (Mock `process.exit`.)
- Unit test: `close()` kills the child and the handle resolves cleanly.
</verify>

<done>
`spawnFrontendServer()` boots Vite, captures the bound port, supervises the child, and exposes a clean handle. Unit tests cover startup, restart policy, and shutdown.

## Risks

- **Vite child startup race**: if the parent reads stdout before the child prints `READY <port>`, the handle resolves with `port: 0`. Mitigation: line-buffered stdout parser that waits for the exact `READY <port>` prefix.
- **Chromium cold-start latency**: first screenshot takes ~2s. Acceptable for the placeholder; subsequent navigations are sub-100ms.
- **Port clash on auto-select**: Vite auto-selects from 5173; if a stray dev server is running, it picks the next free port. Mitigation: log the bound port explicitly so collisions are obvious.

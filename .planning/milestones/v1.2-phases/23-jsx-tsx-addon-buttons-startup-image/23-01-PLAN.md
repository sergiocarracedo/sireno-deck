# Plan 23-01: Raw-Source Local Addon Startup

<objective>
Make the local-addon contract honest end-to-end: a local addon folder should be able to declare raw `.tsx` source in `sirenoAddon.main`, import sibling source files normally, and still load through the same startup path users already run. This slice keeps the contract narrow on purpose: manifest entry only, fixed Sireno transpile policy, relative imports only, and root-export-only addon authoring.
</objective>

<files>
- packages/cli/src/addon/loader.ts
</files>
<action>
Extend the local-addon branch in `packages/cli/src/addon/loader.ts` so `sirenoAddon.main` may point at `.ts`, `.tsx`, `.js`, or `.jsx` source files for local addons only. Keep manifest ownership intact, preserve the current dynamic-import path for npm addons and already-built JavaScript, and add one Sireno-owned runtime-transpile path for raw source. Mirror the bounded source-graph behavior from `packages/cli/src/config/theme.ts`: resolve only relative imports inside the addon root, use an explicit candidate extension list, and do not honor tsconfig path aliases, project references, or convention-based entry discovery. <done>

# Plan 13-02: Ship Runtime Primitive Transport, Validation, And Reuse Proof

<objective>
Deliver the second Phase 13 tracer bullet as one demoable user-facing behavior: shared/default button renders from bundled and external addons can reference wrapper/style primitives through the public render contract, runtime rejects bad addon-authored refs before pixel generation, and the repo ships tests plus a review path proving the primitive contract is reused across boundaries rather than trapped inside one addon.
</objective>

## Tasks

<task id="13-02-01">
<title>Carry primitive ids through the public render contract and reconciler</title>
<files>
- packages/cli/src/render/types.ts
- packages/cli/src/render/reconciler.ts
- packages/cli/src/render/reconciler.test.tsx
</files>
<action>
Extend the public render contract in `packages/cli/src/render/types.ts` and `packages/cli/src/render/reconciler.ts` so `deck-button` and `deck-surface` buttons can carry direct `wrapper_id` and `style_id` props end-to-end. Keep the transport explicit and narrow; do not replace the current button props with a nested style bag, and do not add `deck-text` support in the first rollout because Phase 13 explicitly scoped it out. Update reconciler tests so helper-authored and JSX-authored button output stay in parity, deck-surface collections preserve primitive ids, and existing bespoke variants remain unaffected.
</action>

</task>

<task id="13-02-02">
<title>Reject bad addon-authored primitive refs before image generation</title>
<files>
- packages/cli/src/deck/runtime.ts
- packages/cli/src/deck/runtime.test.ts
</files>
<action>
Add the minimal runtime validation seam needed to enforce Phase 13's addon-authored failure boundary. When `packages/cli/src/deck/runtime.ts` consumes `renderDeck(instance.render())` output from addon instances, validate any carried `wrapper_id` and `style_id` against the live registry before `renderTextImage()` or device writes happen. Unknown refs, missing providers, and wrapper/style kind mismatches must hard-fail there instead of silently degrading or showing up as renderer surprises. Update runtime tests so addon-authored invalid refs are caught before rendering, while valid refs continue through the normal render path.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/deck/runtime.test.ts`.
</verify>
<done>
Addon-authored primitive references now fail at the required pre-render boundary instead of becoming late renderer failures.
</done>
</task>

# Phase 08 Plan 01: Theme system foundation + `default` theme end-to-end

**Wave:** 1
**Depends on:** —
**Goal:** Ship the theme addon contract, the Vite plugin's virtual theme module, and a fully working `default` theme with 4 surfaces and 5 primitives that the rest of the app can use immediately.

## Tasks

### Task 1: Extend addon manifest with `kind: 'runtime' | 'theme'`

- File: `packages/cli/src/addon/manifest.ts`
- Add `kind?: 'runtime' | 'theme'` to `AddonManifest`; default to `'runtime'` in the parser.
- Update tests in `packages/cli/src/addon/__tests__/manifest.test.ts` to cover both kinds (including a missing-`kind` fixture).
- Acceptance: existing addons still parse; new theme addons parse with `kind: 'theme'`.

### Task 2: Extend `AddonRegistry` with theme support

- File: `packages/cli/src/addon/registry.ts`
- Add `themesByName: Map<string, LoadedTheme>` and `loadTheme()`, `getTheme(name)`, `listThemes()` methods.
- Define `LoadedTheme` type alongside `LoadedAddon` in the same file.
- Acceptance: a unit test in `packages/cli/src/addon/__tests__/registry.test.ts` creates a registry, registers a theme, fetches by name, and lists all themes.

### Task 3: Dispatch on `kind` in `loadAddons()`

- File: `packages/cli/src/addon/loader.ts`
- Change `loadAddons()` to return `{ addons, themes, issues }` (where `themes` is a new field).
- For each candidate, dispatch: `kind === 'theme'` → `loadTheme()`, else → `loadAddon()`.
- Add `registerBuiltInThemes(registry)` to load the embedded themes from `packages/cli/src/themes/{default,light}/` (Plan 01 ships only `default`; Plan 02 adds `light`).
- Acceptance: integration test in `packages/cli/src/addon/__tests__/loader.test.ts` loads a mix of runtime and theme addons and both end up in the right maps.

### Task 4: Theme loader

- File: `packages/cli/src/themes/loader.ts` (new)

- Acceptance: unit test in `packages/cli/src/themes/__tests__/loader.test.ts` covers: name resolves to theme, name missing throws, name empty returns the default `default` theme.

### Task 5: Theme registry module

- File: `packages/cli/src/themes/registry.ts` (new)

### Task 9: Built-in `default` theme — `theme.css`

- File: `packages/cli/src/themes/default/theme.css` (new)
- Two blocks:
  - `@media (prefers-color-scheme: dark) { :root { @theme { --color-bg: #0a0a0a; --color-fg: #fafafa; --color-accent: #38bdf8; --color-ring: #fafafa; --color-tap: #38bdf8; --color-muted: #737373; --color-bar: #262626; --color-bar-accent: #38bdf8; --font-mono: 'JetBrains Mono', monospace; } } }`
  - `@media (prefers-color-scheme: light) { :root { @theme { --color-bg: #fafafa; --color-fg: #0a0a0a; --color-accent: #0284c7; --color-ring: #0a0a0a; --color-tap: #0284c7; --color-muted: #525252; --color-bar: #e5e5e5; --color-bar-accent: #0284c7; --font-mono: 'JetBrains Mono', monospace; } } }`
- Plus `@keyframes tap-pulse { 0%, 100% { opacity: 1 } 50% { opacity: 0.6 } }` and `.__tap { animation: tap-pulse 150ms ease-out; }` plus `.__hold-ring { stroke-dasharray: 0 999; animation: hold-fill 500ms linear forwards; }`.
- Note: `@theme` inside a media query is valid in Tailwind 4; verify with a tiny smoke test in Plan 01.

## Must-Haves

A user can configure `theme: default` in their config and:

1. The default theme loads at startup; no error about missing theme.
2. The Deck renders with the dark token set (because the test environment has `prefers-color-scheme: dark`).
3. Addons can import any of the 4 surfaces and render them; they pick up the theme's tokens via Tailwind utility classes (`bg-bar`, `text-fg`, `border-fg/10`).
4. The tap pulse (150 ms opacity) is visible when a button is clicked.
5. The hold ring grows from 0% to 100% over 500 ms when a button is held.
6. All 4 surfaces and 5 primitives export their components and have tests.
7. The full test suite passes (no regressions).

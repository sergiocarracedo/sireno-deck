# Phase 11 Plan 01 — Manifest array format + addon migration

## Goal

After this plan, the addon manifest declares `decks` as an array. Each entry is one of:
- **Static**: `{ id: "<addon>:<deck>", name, icon, paginated?, autoShow?, isOverlay?, trigger?, buttons }` — a literal deck object.
- **Single-dynamic**: `{ id: "<addon>:<deck>", createDeck: (cfg) => deckObject }` — factory that returns one deck.
- **Multi-dynamic**: `{ createDecks: (cfg) => { "<addon>:<deck1>": deckObject, "<addon>:<deck2>": deckObject } }` — factory that returns multiple decks.

The `type` field goes away — the entry's `id` (or the keys returned from `createDecks`) IS the deck-type key. Hard cutover: the old `Record<key, {type, createDecks}>` shape is rejected at `AddonRegistry.load()` with a clear error.

The 3 Phase-10 addons (`chrome-overlay`, `vscode-overlay`, `opencode-overlay`) migrate to the new array form.

# Phase 12 Plan 01: vite plugin addon registry + Deck wiring

## Tasks

### Task 1: Extend `AddonManifest` with `publishIntervalMs`

- File: `packages/cli/src/addon/api.ts`
- Add `publishIntervalMs?: number` to `AddonManifest` (default 1000ms in code).
- This is read by the CLI's state publisher (Plan 12-02) to set the polling cadence per channel.

### Task 2: Extend the vite plugin to emit the addon registry

- File: `packages/cli/src/vite/virtual-modules.ts`
- Add a new virtual id `ADDONS_REGISTRY_VIRTUAL_ID = "virtual:sireno/addons/registry"`.
- Add `buildAddonsRegistryModule(addons)` that emits:
  ```ts
  import * as <sanitized_name> from "<addon.frontend.main>";
  // ... per addon
  export const addonRegistry = {
    "core:foo": { addonName: "<name>", Component: <sanitized>.default },
    // ... per (addon, type)
  };
  ```
- The registry is built from the `addons: [{ name, frontend: { main }, buttons: [{ type }] }]` shape passed to the plugin.
- Resolve the plugin's `addons` option in `config()` and `configResolved()` to include the frontend paths so the bundler can pick them up.

### Task 3: Extend CLI's `buildDeckConfigMessage`

- File: `packages/cli/src/cli/commands/emulator-mode.ts`
- For each button in the deck, look up the addon's name (from `options.runtime` addons registry) and the `frontend.main` path.
- Include `addonName` and `frontendEntry` on each button object.
- Tests: `emulator-mode.test.ts` asserts the new fields are present.

### Task 4: Pass `addons` list to the vite plugin

- File: `packages/cli/src/cli/commands/run.ts`
- In `runEmulatorLifecycle`, build the `addons` list from the built-in addon manifests (scan `packages/cli/src/builtin-addons/*/index.ts`).
- Pass the list to `spawnFrontendVite({ addons })`.

### Task 5: Extend frontend `Deck.tsx` to render addon components

- File: `packages/cli/frontend/src/components/Deck.tsx`
- Add `import { addonRegistry } from "virtual:sireno/addons/registry"`.
- For each button, look up `addonRegistry[button.type]`.
- If found, render `<RegistryEntry.Component config={button.config} state={state} />` as the children of `<ButtonFrame>`.
- If not found, fall back to the type-name label (current behavior).
- The `state` is passed in from a new `useAddonChannel` per type (channel name = `<addon>:<key>` from the button's addonName).

### Task 6: Tests + typecheck + lint

- All existing 464 tests pass.
- New tests for the vite plugin's `buildAddonsRegistryModule` (registry includes all 7 builtin types).
- New tests for `buildDeckConfigMessage` (addonName + frontendEntry present).
- Run `pnpm --filter sireno-deck typecheck` (clean).
- Run `pnpm --filter sireno-deck lint` (clean).

## Acceptance

- `virtual:sireno/addons/registry` is emitted by the vite plugin.
- `addonRegistry["core:time"]` (and similar) returns `{ addonName, Component }` in tests.
- `buildDeckConfigMessage` includes `addonName` and `frontendEntry` for each button.
- Frontend `Deck.tsx` reads the registry; placeholder rendering until addon frontends ship (Plan 12-03).

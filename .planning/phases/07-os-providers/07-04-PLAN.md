# Phase 07 Plan 04 — Windows Implementations

## Context

Windows is the third-priority platform. All four capabilities are implemented via PowerShell + UIA / SMTC. No new npm dependencies — PowerShell is built-in on Windows.

The Plan 01 interfaces are stable: `ActiveAppProvider.getActive()`, `SessionProvider.getState()`, `KeyMacroProvider.sendKey()`, `MediaProvider` (transport + getCurrent + onChange). Each Windows implementation returns `null` provider (or throws) on failure.

`get-windows` and `dbus-next` are not used here — those are Linux-only. macOS uses `osascript`. Windows uses `powershell.exe`.

## Notes for executor

- All PowerShell calls via the `executor` (testable; production uses `execa`).
- PowerShell is invoked as `powershell.exe` on Windows. The cross-platform call should still work because we never run on Windows in CI — tests mock the executor.
- `SendKeys` syntax: `^` = ctrl, `%` = alt, `+` = shift. Special keys in braces: `{ENTER}`, `{TAB}`, `{F1}`..`{F12}`, `{ESC}`.
- Windows SMTC requires the `Windows.Media.Control` WinRT API. The PowerShell call may need to load the WinRT projection first.
- All native calls mocked in tests via injected executor.

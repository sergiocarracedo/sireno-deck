# Running the Service

Sireno Deck runs as a background daemon that connects to your Stream Deck and serves the frontend.

## Commands

### `sireno run`

Run in the foreground (development mode):

```bash
sireno run [options]
```

Options:

- `--config <path>` — Path to config.yml
- `--port <number>` — Local server port (0 = random)
- `--emulator` — Run with emulator instead of real device
- `--dev` — Enable HMR for development
- `--device-model <model>` — Emulator device model (mk2, plus, mini, xl)

Example:

```bash
# Run with emulator
sireno run --emulator

# Run with custom device
sireno run --emulator --device-model xl

# Development with hot reload
sireno run --dev --emulator
```

### `sireno start`

Install and start the daemon:

```bash
sireno start [options]
```

Options:

- `--config <path>` — Path to config.yml
- `--port <number>` — Local server port
- `--emulator` — Run in emulator mode
- `--remote` — Enable an authenticated HTTPS remote deck interface
- `--device-model <model>` — Device model
- `--http-port <number>` — HTTP server port (default: 3939)
- `--system` — Install as system service (requires root)
- `--logs` — Follow logs after starting

Example:

```bash
# Start in background
sireno start

# Start and follow logs
sireno start --logs

# Start as system service
sudo sireno start --system
```

### Secure remote access

Start with `sireno start --remote` (add `--emulator` to use a virtual device).
The CLI prints an HTTPS address, an access token, the path to a local CA
certificate, and its SHA-256 fingerprint. The internal frontend and WebSocket
servers remain on the host's loopback interface; the remote interface uses
HTTPS and WSS.

Transfer **only the public CA certificate** to the device you will use, using a
trusted channel. Compare its SHA-256 fingerprint with the one printed on the
host before trusting it. For example, on a machine with OpenSSL:

```bash
openssl x509 -in /path/to/ca.pem -noout -fingerprint -sha256
```

OpenSSL separates the hexadecimal pairs with colons; the CLI prints the same
fingerprint without separators.

Install the certificate as a trusted CA using that device's certificate
settings, then open the printed HTTPS address and enter the access token.
Browser and operating-system trust procedures differ; some applications do not
honor user-installed CAs. Do not bypass a certificate warning if the identity
has not been verified. The access token is a password: share it only with
people authorized to control the deck. It changes when the daemon restarts.

The terminal also prints a QR code for the remote address, so a phone can
connect by scanning it. The QR carries the access token; the gateway
exchanges it for a session cookie and redirects to the address without the
token, so it does not stay in the browser's address bar. Scan it only on a
device you trust with the deck.

Trusting a local CA lets it authenticate other sites as well as Sireno Deck.
Keep its private key on the host and do not share or export it. Remove the CA
from each device's trust settings when remote access is no longer needed. If
the host address changes, restart the daemon and use the new HTTPS address;
the existing CA remains the trust anchor. A damaged or unavailable CA key
requires recovery and re-establishing trust, not bypassing verification.
The key is stored as a local file, not encrypted by Sireno Deck. On POSIX
systems the certificate directory and key files use owner-only permissions;
on Windows protection depends on the user's directory access controls.

### `sireno stop`

Stop the running daemon:

```bash
sireno stop
```

### `sireno status`

Check daemon status:

```bash
sireno status
```

Output shows:

- Running/stopped state
- Daemon PID
- Child process IDs
- Token info

### `sireno restart`

Restart the daemon:

```bash
sireno restart [options]
```

Options:

- `--logs` — Follow logs after restart

### `sireno reload`

Send SIGUSR1 for in-place reload (preserves runtime state):

```bash
sireno reload [options]
```

Options:

- `--logs` — Follow logs after reload

### `sireno update-config`

Update the config path the daemon uses:

```bash
sireno update-config --config <path> [options]
```

Options:

- `--reload` — Use in-place reload instead of restart
- `--logs` — Follow logs after update

### `sireno logs`

Tail the service log:

```bash
sireno logs [options]
```

Options:

- `--follow / -f` — Follow log output (default: true)
- `--lines / -n` — Initial lines to show (default: 50)

## Global Options

All commands support:

- `--verbose / -v` — Enable verbose debug logging
- `--dev-mode` — Enable developer mode logging (`info` level)
- `--quiet / -q` — Suppress all logs and the startup banner (`silent` level)
- `--log-level <level>` — Override log level (`trace`, `debug`, `info`, `warn`, `error`, `fatal`, `silent`, `none`)
- `--json` — Emit logs as JSON

By default, the CLI only logs errors. Use `--dev-mode` for normal operational output, `--verbose` for debug output, or `--log-level` for full control. Use `--quiet` (or `--log-level silent` / `--log-level none`) to silence logs and suppress the startup banner.

## Startup Banner

When you run `sireno start`, the CLI prints a structured banner to stderr summarizing the startup state:

```
┌  Starting SirenoDeck
│
◇  Device: Emulator (mk2)
│
│  [✓ keystrokes] [✓ clipboard] [✗ notifications — notify-send]
│  [✓ active-win] [✓ media] [✓ exec] [✗ http — unreachable]
│
└  ✓ SirenoDeck started
```

The banner shows the detected device (or emulator model), a horizontal list of OS features with availability status, and a completion line once the daemon is serving. It is independent of the log level and is suppressed by `--quiet`, `--log-level silent`, `--log-level none`, or non-interactive output (pipes, CI).

## Daemon Lifecycle

The daemon writes runtime files to:

- **Linux**: `$XDG_RUNTIME_DIR` or `$TMPDIR`
- **macOS**: `~/Library/Application Support/sireno-deck`
- **Windows**: `$LOCALAPPDATA/sireno-deck` or `$TMPDIR`

Files created:

- `sireno-deck.pid` — Daemon process ID
- `sireno-deck.token` — WebSocket authentication token
- `sireno-deck.children.json` — Child process IDs
- `sireno-deck.config` — Config file path
- `sireno-deck.flags.json` — Runtime flags

## Service Manager Integration

### Linux (systemd)

User-level:

```bash
systemctl --user status sireno-deck.service
```

System-level (requires root):

```bash
sudo systemctl status sireno-deck.service
```

### macOS (launchd)

```bash
launchctl list | grep sireno
```

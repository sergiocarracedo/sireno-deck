# Phase 06 Plan 02 — Browser Renderer

## Context

The browser renderer is the headless-chromium pipeline that drives real hardware in real mode. In Phase 04 we already have `vite-server.ts` spawning vite as a child process; this plan builds the consumer that talks to that vite via Playwright, takes screenshots, crops with sharp, and writes to the device.

**Per Phase 06 CONTEXT.md decisions**:
- **Write strategy: delta only** — hash each cropped buffer (sha1 truncated to 16 hex); skip write if hash unchanged for that key since last cycle.
- **Screenshot trigger: hybrid** — timer at `intervalMs` (default 500ms) + 50ms-debounced re-renders on `runtime:activeDeck` and `runtime:invalidate` pub-sub events from `@/core/pub-sub` (Phase 03).

The architecture is: CLI → vite-server (Phase 04) → frontend vite URL → Playwright headless browser → `page.screenshot()` → sharp crop per key → buffer-hash skip → `device.fillKeyBuffer(i, buf)`.

## Notes for executor

- Playwright + sharp downloads add ~150MB to node_modules. Run `pnpm install` once after adding deps; verify lockfile updated.
- `sharp` is CommonJS-only; default import works but be careful with tree-shaking.
- `page.screenshot()` returns PNG by default; use `{ type: "png" }` explicitly.
- Layout derivation: `gridForKeyCount(keyCount)` from `device/models.ts` (already in Phase 05). Re-export it.
- `BrowserRenderer.start` is async and may take a while (chromium launch). Tests should not await startup synchronously — await the start promise then assert.
- For the mock PNG fixture, a minimal valid 1×1 PNG is `Buffer.from('89504E470D0A1A0A0000000D49484452000000010000000108060000001F15C4890000000D49444154789C63F8FFFF3F0005FE02FED6CCC75E0000000049454E44AE426082', 'hex')`.
- **Hybrid trigger architecture**: both triggers converge on the same internal `_tick()` method. The timer ticks at `intervalMs`; the event debouncer fires after `eventDebounceMs` following the last pub-sub event. Both call `_tick()` → screenshot → crop → hash → write.
- For tests, use a real pub-sub instance from `@/core/pub-sub` (not mocked) — its API is already exercised by Phase 03 tests.
- DO NOT add comments unless user asks.

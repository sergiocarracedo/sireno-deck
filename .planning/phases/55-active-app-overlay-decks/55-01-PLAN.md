**File:** `packages/cli/src/deck/system-buttons/system-buttons.ts`

Current state (48 lines, 4 issues):

  `IMPLICIT_LOCKED_DECK_ID: string` parameters just to splice into a synthetic
  `SirenoConfig`. That's the caller's job.
- No `settings` branch — the comment says `// Settings button` with an empty
  body. **The settings branch goes in 55-02**, but the **structure** of the
  dispatcher (3-branch: overlay / settings / back) can be laid out now.

**Target shape (≤ 30 lines):**

```ts
import { ButtonInstance, DeckConfig, SirenoConfig } from '@/core/schemas'
import { HostContext } from '@/system/host-context'
import {
  getSystemBackButtonInstance,
  shouldInjectSystemBack,
} from '../system-back-injection'

export const OVERLAY_TOGGLE_TYPE = 'overlay-toggle' as const

export interface SystemButtonContext {
  config: SirenoConfig
  hostContext: HostContext
  internalLockedDeckId: string
  overlayDeckId: string | null
}

export function getLastPositionSystemButton(
  lastPosition: number,
  deck: DeckConfig,
  ctx: SystemButtonContext,
): ButtonInstance | null {
  if (ctx.overlayDeckId !== null && ctx.overlayDeckId === deck.id) {
    return {
      config: {},
      id: OVERLAY_TOGGLE_TYPE,
      position: lastPosition,
      type: OVERLAY_TOGGLE_TYPE,
    } as unknown as ButtonInstance
  }

  // 55-02 will add a settings branch for main-deck reserved slot.

  return shouldInjectSystemBack(
    deck,
    ctx.config,
    ctx.hostContext.session.state,
  )
    ? getSystemBackButtonInstance(deck, lastPosition)
    : null
}
```

The runtime builds the context once in `createDeckRuntime` and passes it
through `getDeckButtons`. The locked-deck id is read from
`ctx.config.session?.locked_deck ?? ctx.internalLockedDeckId`.

### Task 5: Wire the active-app monitor in `start.ts`

The `start()` method of the runtime calls
`options.activeAppMonitor?.start(handleActiveAppChange)`, but **no caller in
`start.ts` ever constructs or passes a monitor.** This is a real wiring gap —
active-app overlay is dead in production.

**File:** `packages/cli/src/cli/commands/start.ts`

Add at the top (near the imports of other singletons):

```ts
import { createActiveAppMonitor, getActiveAppProvider } from '@/system/active-app'
```

In each `createDeckRuntime` call (line ~910 and line ~1113), pass
`activeAppMonitor: createActiveAppMonitor({ provider: getActiveAppProvider({ logger }), onChange: () => {} })`.

Wait — the `onChange` is wired by `start()`. The factory pattern is:

- `createActiveAppMonitor` takes a `provider` and a static `onChange` callback.
- The runtime's `start()` calls `provider.start(handleActiveAppChange)`.
- The `createActiveAppMonitor` wraps that into a `start()`/`stop()` monitor.

Looking at `active-app-monitor.ts:11-24`, `createActiveAppMonitor` takes
`{ provider, onChange }` and `start()` calls `provider.start(onChange)`. So
the wiring is:

```ts
const provider = getActiveAppProvider({ logger })
const activeAppMonitor: ActiveAppMonitor = {
  start: () => provider.start(handleActiveAppChange),
  stop: () => provider.stop(),
}
```

We need to expose `handleActiveAppChange` to `start.ts`. Cleanest path:
expose a factory that takes the callback. Simpler: inline a thin wrapper at
each call site.

**Concrete change:** at the top of `start.ts`, define a helper:

```ts
function createWiredActiveAppMonitor(onChange: ActiveAppChangeHandler) {
  const provider = getActiveAppProvider({ logger })
  return {
    start: () => provider.start(onChange),
    stop: () => provider.stop(),
  }
}
```

But `handleActiveAppChange` lives inside the runtime closure, not exported.
The runtime must accept the **provider** and create the monitor inside `start()`.

**Revised approach (simpler):** change the runtime's option from
`activeAppMonitor?: ActiveAppMonitor` to `activeAppProvider?: ActiveAppProvider`
and have `runtime.start()` build the monitor. This puts the wiring where the
callback lives. The double stays available for tests.

**File:** `packages/cli/src/deck/runtime.ts`

- Replace `activeAppMonitor?: ActiveAppMonitor` with
  `activeAppProvider?: ActiveAppProvider` on `DeckRuntimeOptions`.
- In `start()` (around line 1617), build the monitor:
  ```ts
  if (options.activeAppProvider) {
    createActiveAppMonitor({
      provider: options.activeAppProvider,
      onChange: handleActiveAppChange,
    }).start()
  }
  ```
- In `stop()`, no change needed (the provider's `stop()` is bound to the
  monitor's lifecycle; we don't need a reference).

**File:** `packages/cli/src/cli/commands/start.ts`

- Add `import { getActiveAppProvider } from '@/system/active-app'`
- In both `createDeckRuntime` call sites, pass
  `activeAppProvider: getActiveAppProvider({ logger })`.

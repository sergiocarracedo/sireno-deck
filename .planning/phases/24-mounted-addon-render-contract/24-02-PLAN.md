# Plan 24-02: Core-Owned Addon Session Store

<objective>
Deliver the first real user-facing value of the new store seam: buttons from one addon can coordinate through a core-owned session store and keep that coordinated state across normal deck navigation, while button-local isolation remains the default and React remains only the mounted view into runtime-owned state.
</objective>

## Tasks

<task id="24-02-01">
<title>Implement the runtime-owned addon store with button-local and addon-wide scopes</title>
<files>
- packages/cli/src/deck/runtime.ts
- packages/cli/src/addon/api.ts
</files>
<action>
Add the Phase 24 store seam inside `packages/cli/src/deck/runtime.ts` so runtime owns store lifetime, scoping, and mutation. Support button-local state as the primary isolation boundary plus addon-wide coordinated access for buttons that intentionally collaborate. Expose the store through the new render props contract in `packages/cli/src/addon/api.ts` as snapshots plus mutation methods, not as implicit React-owned persistence. Make the lifetime honest: survive ordinary deck changes within one runtime session, reset when runtime state is rebuilt, and keep transient input state such as `pressed` / `frameState` out of the durable store.
</action>
<verify>
`grep -n "button-local\|addon-wide\|pressed\|frameState" packages/cli/src/deck/runtime.ts packages/cli/src/addon/api.ts` shows the scoped store seam and the separation from transient runtime props.
</verify>
<done>
The runtime owns one explicit addon-session store model that matches the Phase 24 context instead of leaking persistence concerns into component-local state.
</done>
</task>

<must_haves>
- Phase 24 is post-roadmap follow-on work and does not claim a new v1.2 requirement ID; this slice must preserve the existing host/session/runtime contracts while changing addon state ownership boundaries.
- Durable session state stays core-owned and runtime-scoped rather than sliding into React local state.
- The proof fixture demonstrates both button-local isolation and intentional addon-wide coordination through one honest runtime seam.
</must_haves>

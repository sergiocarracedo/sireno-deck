# Plan 18-01: First TSX Button on the Browser Deck

<objective>
Build the first true Phase 18 tracer bullet under the corrected contract. This plan introduces the persistent Playwright/Chromium deck page, a `react-dom`-mounted deck host, the real React `buttonFrame`, and one migrated action/change-deck fixture authored as normal React TSX and rendered on the real device path. The goal is to prove the chosen architecture end to end before broader builtin migration and live-state/media work.
</objective>

<title>Add the browser renderer runtime seam</title>
<files>
- packages/cli/package.json
- packages/cli/src/render/browser-renderer.ts
</files>
<action>
Add the Playwright dependency needed for a Chromium-backed renderer host. Create `packages/cli/src/render/browser-renderer.ts` with a long-lived browser/context/page lifecycle that can: start once, keep one active deck page alive, update the rendered deck DOM in place, take a deck screenshot into a buffer, and crop that screenshot into per-key buffers sized for the existing Stream Deck preset. The public API must be explicit enough for the daemon to initialize, update, capture, and close the renderer without rebuilding the browser per render.
</action>

</done>
</task>

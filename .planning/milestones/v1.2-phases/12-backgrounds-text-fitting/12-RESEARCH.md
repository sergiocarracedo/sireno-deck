# Phase 12 Research

**Phase:** 12 - Backgrounds + Text Fitting
**Date:** 2026-05-18
**Status:** complete

## Don't Hand-Roll

- Do not invent a broad background system for Phase 12. The phase context explicitly pins this work to color-only backgrounds with exact precedence `button -> deck -> theme`, and the current theme contract already exposes a single `background` color token. Widening into gradients, images, or asset-backed backgrounds would contradict the agreed phase boundary and create new config/render surface area before the current contract is even explicit. [VERIFIED: .planning/phases/12-backgrounds-text-fitting/12-CONTEXT.md, packages/cli/src/config/theme.ts] [HIGH]
- Do not keep layering new semantics onto the existing `overflow?: "clip"` field. The public render contract currently only models clip-only overflow in `packages/cli/src/render/types.ts` and `packages/cli/src/render/reconciler.ts`, while the phase goal requires explicit named text-fit modes. The smallest correct move is to replace or narrow-evolve that public seam into explicit fit modes rather than accreting more hidden renderer behavior under `overflow`. [VERIFIED: packages/cli/src/render/types.ts, packages/cli/src/render/reconciler.ts, .planning/phases/12-backgrounds-text-fitting/12-CONTEXT.md] [HIGH]
- Do not force bespoke visuals like `analog-clock` and `calendar-sheet` through the first shared text-fitting abstraction unless there is a genuinely low-risk reuse point. Prior art from Phase 8 explicitly shows that bespoke live visuals can stay inside the existing `deck-button` variant seam without widening the renderer into generic primitives, and the Phase 12 context repeats that bespoke variants should only adopt the new contract where natural. [VERIFIED: .planning/solutions/best-practices/bespoke-live-visuals-can-stay-inside-the-deck-button-variant-seam-2026-05-15.md, .planning/phases/12-backgrounds-text-fitting/12-CONTEXT.md, packages/cli/src/render/text-image.ts] [HIGH]
- Do not assume SVG text will wrap or fit intelligently on its own. MDN’s SVG text docs describe basic positioning, clipping, and `textLength`, but not automatic paragraph-style wrapping for the existing hand-positioned `<text>` path; the current renderer already relies on explicit clip rectangles around text nodes. If Phase 12 needs `wrap`, the implementation should make wrapping behavior explicit rather than depending on accidental SVG behavior. [CITED: https://developer.mozilla.org/en-US/docs/Web/SVG/Tutorial/Texts] [VERIFIED: packages/cli/src/render/text-image.ts] [HIGH]
- Do not rely on font-family differences alone to make text-fit or typography review paths observably different. Prior Phase 7 findings show that Sharp/librsvg can collapse configured font families onto the same host fallback font, hiding intended UI differences. Background/text-fit verification should therefore prefer pixel-observable layout effects like wrapping, clipping boundaries, and size changes rather than weak font-family-only distinctions. [VERIFIED: .planning/solutions/ui-bugs/theme-typography-difference-hidden-by-font-fallback-2026-05-15.md, packages/cli/src/render/text-image.test.ts] [HIGH]
- Do not add a user-configurable readable-minimum setting in Phase 12. The phase context explicitly assigns the minimum readable size to the renderer as an implementation-owned floor, and adding theme/config knobs would widen the public contract before the team has learned whether a single floor works well across review paths. [VERIFIED: .planning/phases/12-backgrounds-text-fitting/12-CONTEXT.md] [HIGH]

## Common Pitfalls

- The easiest failure is precedence drift: schema says one thing, reconciler carries another, and `text-image.ts` quietly falls back to something else. Because the phase is specifically about shared render-surface contracts, the precedence chain must be resolved once and then passed through consistently rather than re-decided per branch or variant. [VERIFIED: .planning/REQUIREMENTS.md, .planning/phases/12-backgrounds-text-fitting/12-CONTEXT.md, packages/cli/src/render/text-image.ts] [HIGH]
- It is easy to create a fake `wrap` mode that only works in tests by manually inserting line breaks in fixtures rather than teaching the renderer to choose line breaks. That would satisfy screenshots but not the requirement for an explicit render contract. Plan tasks should make the behavior observable from user-authored strings, not pre-wrapped examples. [ASSUMED] [MEDIUM]
- Background tests can become noisy or meaningless if they only compare whole-image inequality. The existing renderer tests already use region-based pixel diffs to prove specific visual changes, and Phase 12 should keep that pattern so button override, deck fallback, and theme fallback are each tested against the exact region they are supposed to affect. [VERIFIED: packages/cli/src/render/text-image.test.ts] [HIGH]
- Shrink-to-fit can become unreadable if the implementation only compresses font size until text disappears. The phase context already guards against this by requiring a renderer-owned readable minimum floor followed by clean clipping; plans should treat that fallback boundary as a core behavior, not a polish step. [VERIFIED: .planning/phases/12-backgrounds-text-fitting/12-CONTEXT.md] [HIGH]
- The current shared/default renderer path is heavily hand-positioned SVG. That means any attempt to “genericize” every label, subtitle, detail line, metric, and badge into one layout engine in this phase is likely to blow up complexity and destabilize shipped visuals unrelated to the phase goal. [VERIFIED: packages/cli/src/render/text-image.ts] [HIGH]
- The repo currently has no `DECISIONS.md`, so the phase context is the only active source of user design preferences. Planning that ignores `12-CONTEXT.md` will likely re-open already-made scope decisions around gradients, global overrides, or theme-configurable minima. [VERIFIED: .planning/phases/12-backgrounds-text-fitting/12-CONTEXT.md, absence of .planning/DECISIONS.md] [HIGH]

## Existing Patterns in This Codebase

- `packages/cli/src/render/types.ts` and `packages/cli/src/render/reconciler.ts` are the public render-contract seam. They currently thread a narrow set of fields like `label`, `subtitle`, `variant`, `wrapper`, and `overflow?: "clip"`, so Phase 12 should evolve this seam first instead of burying fit/background logic deeper in `text-image.ts`. [VERIFIED: packages/cli/src/render/types.ts, packages/cli/src/render/reconciler.ts] [HIGH]
- `packages/cli/src/render/text-image.ts` is the main implementation seam for the shared/default visual path. It already computes theme-derived colors, clip regions, wrapper decisions, and variant-specific SVG branches, which makes it the natural place to resolve background precedence and implement the first shrink/wrap behavior for shared/default text. [VERIFIED: packages/cli/src/render/text-image.ts] [HIGH]
- `packages/cli/src/render/text-image.test.ts` already verifies renderer behavior via targeted pixel-region diffs rather than snapshots of raw SVG strings. That is the right existing pattern for proving wrap-vs-shrink outcomes, precedence changes, and protecting bespoke variants from unintended regressions. [VERIFIED: packages/cli/src/render/text-image.test.ts] [HIGH]
- Theme fallback is already explicit and validated through `packages/cli/src/config/theme.ts`, which exposes `background`, `foreground`, `primary`, `accent`, `success`, `danger`, and typography roles. This supports the Phase 12 decision to keep backgrounds color-only and use theme background as the final fallback rather than adding a separate visual-token subsystem. [VERIFIED: packages/cli/src/config/theme.ts] [HIGH]
- Config validation already preserves path and line metadata through `packages/cli/src/core/schemas.ts`, and previous project learnings in `STATE.md` treat that as non-negotiable. Any new button/deck background settings or text-fit fields should therefore land in the existing validation path rather than being accepted ad hoc in render-time props only. [VERIFIED: packages/cli/src/core/schemas.ts, .planning/STATE.md] [HIGH]
- Prior solutions and phase history show a strong bias toward keeping bespoke visuals inside the existing `variant` seam instead of introducing broad renderer primitives too early. Phase 12 should preserve that pattern by improving shared/default contracts first while explicitly leaving low-risk escape hatches for custom variants. [VERIFIED: .planning/solutions/best-practices/bespoke-live-visuals-can-stay-inside-the-deck-button-variant-seam-2026-05-15.md, packages/cli/src/render/types.ts] [HIGH]

## Recommended Approach

- Start by making the public render contract explicit. Replace the clip-only `overflow` seam with a named text-fit contract that encodes the two Phase 12 modes: default `shrink` and alternate `wrap`. Keep the contract narrow; do not add extra modes unless implementation proves they are necessary. [VERIFIED: .planning/phases/12-backgrounds-text-fitting/12-CONTEXT.md, packages/cli/src/render/types.ts] [HIGH]
- Add validated background fields at the button and deck config seams first, then thread a resolved background value into the render description. This keeps precedence machine-checkable and observable before SVG generation. The precedence should be applied once as `button background -> deck background -> theme background`, not recomputed per variant branch. [VERIFIED: .planning/REQUIREMENTS.md, .planning/phases/12-backgrounds-text-fitting/12-CONTEXT.md, packages/cli/src/core/schemas.ts, packages/cli/src/render/reconciler.ts] [HIGH]
- Implement shrink/wrap only on the shared/default text path in `packages/cli/src/render/text-image.ts` first. The current code already centralizes clipped label rendering there, so Phase 12 can land a real user-facing improvement without rewriting bespoke branches that are outside the agreed scope. [VERIFIED: packages/cli/src/render/text-image.ts, .planning/phases/12-backgrounds-text-fitting/12-CONTEXT.md] [HIGH]
- Use a renderer-owned minimum readable size and make clipping beyond that point explicit. Sharp’s text rendering constructor docs confirm bounded text generation can be fit into width/height and wrapped, but this codebase mostly uses hand-built SVG text rather than Sharp’s text-image mode. That means the likely Phase 12 implementation should use the existing SVG pipeline with explicit measurement/fallback behavior rather than swapping rendering technologies mid-phase. [CITED: https://sharp.pixelplumbing.com/api-constructor/#parameters] [VERIFIED: packages/cli/src/render/text-image.ts] [MEDIUM]
- Verify with targeted renderer tests and at least one committed fixture path. Tests should prove each precedence tier independently, prove default shrink behavior versus wrap behavior, and protect bespoke variants like `analog-clock` and `calendar-sheet` from regression by showing they remain visually distinct and not forcibly routed through the new shared contract. [VERIFIED: packages/cli/src/render/text-image.test.ts, .planning/phases/12-backgrounds-text-fitting/12-CONTEXT.md] [HIGH]
- Keep the phase sliced as user-visible tracer bullets, not horizontal renderer/schema passes. One plan should deliver observable background precedence through config to real rendering. Another should deliver observable shrink/wrap text behavior end-to-end. Any shared cleanup or fixture/test hardening should attach to those vertical slices instead of becoming its own all-renderer plan. [VERIFIED: .planning/ROADMAP.md, .planning/phases/12-backgrounds-text-fitting/12-CONTEXT.md] [HIGH]

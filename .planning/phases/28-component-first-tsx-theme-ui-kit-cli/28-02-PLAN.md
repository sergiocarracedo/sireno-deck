# Plan 28-02: Migrate Core Buttons And Runtime Fallback UI

<objective>
Make the Phase 28 authoring shift real for the repo's primary built-in interaction path: the shipped core buttons and the runtime-owned temporary/fallback deck must render through the new kit. This slice stays narrow enough to execute in one window while still proving that real built-in behavior, not just fixture addons, now lives on the component-first surface.
</objective>

<title>Migrate shipped core buttons and runtime fallback surfaces onto the new TSX kit</title>

<action>
Refactor the shipped helper-dependent core buttons and the runtime fallback/temporary UI so they render through `Icon`, `Text`, `Chip`, normal TSX composition, and `ButtonSurface` where needed instead of `createDomIcon`, `createDomTextLabel`, `createDomStack`, or `createBaseShape*`. Treat `packages/cli/src/builtin-addons/core-buttons/buttons/action.tsx` as a repair target, not a trustworthy baseline, because research already flagged it as mid-cutover. Keep the mounted `render(props)` contract and runtime-owned transient behavior intact while replacing only the presentation surface. Where core buttons or the runtime error deck previously relied on helper defaults such as text-fit or stacked layout, map those behaviors intentionally onto the new kit rather than recreating implicit helper magic.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/builtin-addons/core-buttons/index.test.ts src/deck/runtime.test.ts src/cli/commands/start.test.ts`.
</verify>
<done>
The shipped core buttons and runtime fallback UI demonstrate the new component-first authoring model on the real runtime surface instead of through retained helper adapters.
</done>
</task>

<must_haves>
- Do not create a long-lived compatibility adapter where helper factories just wrap the new kit; the Phase 28 migration boundary is a hard cut, not a shadow API.
- Keep runtime-owned semantics like invalidation, temporary warnings, navigation, and `ButtonSurface` metadata authoritative.
- Preserve honest browser/runtime proof seams rather than replacing everything with unit-only component tests.
</must_haves>

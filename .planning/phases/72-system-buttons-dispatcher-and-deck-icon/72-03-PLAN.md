# Plan 72-03: Close 3 documentation gaps from Phase 72 UAT

## Context

Phase 72 shipped BUG-03 (2-line SplitActionSurface dispatcher) and BUG-04 (deck icon field) successfully — 3/6 UAT tests passed, the 3 issues are all user confusion about how the feature works, not bugs in the code:

- **Gaps 1+2** (`icon://app-window` renders a static Lucide icon, not a custom deck logo): The user expected that adding `icon: "icon://app-window"` would render a custom logo SVG. In reality, `icon://` is a **Lucide icon name** prefix — it selects a built-in Lucide glyph. For custom images, use `./path/to/image.svg`, `addon://deck-logo`, or `brand://deck-name`.
- **Gap 3** (no 2-line SplitActionSurface visible): The user's config likely had no overlay deck configured, or the active app didn't match `process_names`. The 2-line variant is a **conditional trigger** — it only fires when an overlay deck with `autoShow: false` and matching `process_names` exists. Without this setup, the system back button renders as the standard single-line back button.

The 72-UAT.md diagnosis (root cause sections) already explains all 3 gaps thoroughly. This plan documents those findings in the user-facing README and official spec files so future users don't hit the same confusion.

## Tasks

### Task 1: Document icon path prefix semantics in README

**file:** `README.md`
**action:** Add a new subsection under "Configuration → Decks" (or similar existing section) that documents the icon path resolution:

- `icon://<name>` — Lucide icon name (static glyph, e.g., `icon://app-window`, `icon://settings`). These are built-in icons that ship with the CLI.
- `./<path>` — Relative path to an image file (e.g., `./chrome.svg`). Resolved relative to the config file directory.
- `addon://<name>` — Icon provided by an addon (e.g., `addon://system-status/cpu`). Refer to addon docs for available icons.
- `brand://<name>` — Simple Icons brand icon (e.g., `brand://github`, `brand://slack`).

Also document:
- The n-1 system button (SplitActionSurface when an overlay is pending) shows the **overlay deck's** icon in the secondary slot, not the base deck's icon.
- Decks without an `icon` field fall back to: first emoji in deck name → uppercase first character → `layout-grid` placeholder.

**verify:** `grep -c "icon://" README.md > 0` (at least one reference to the Lucide icon prefix).
**done:** README documents the icon path resolution semantics and the fallback chain.

### Task 2: Document the 2-line SplitActionSurface trigger conditions

**file:** `README.md`
**action:** Add a subsection (or note within the system-buttons documentation) describing when the 2-line variant appears:

- Requires an overlay deck configured with `process_names` matching the active application(s).
- Requires `autoShow: false` on the overlay deck config.
- When conditions are met, the system back button at position n-1 renders as a 2-line `SplitActionSurface`: single-tap = back (primary), double-tap = summon overlay (secondary with overlay deck's icon).
- If no overlay deck matches, the system back button renders as the standard single-line back button.

Include a minimal config example:
```yaml
decks:
  main:
    buttons: []
    icon: "icon://terminal"
  terminal-overlay:
    process_names: ["gnome-terminal", "kitty", "alacritty"]
    autoShow: false
    icon: "icon://terminal"
    buttons: []
```

**verify:** The trigger conditions and example config are visible in README.
**done:** README documents the 2-line variant trigger conditions with a config example.

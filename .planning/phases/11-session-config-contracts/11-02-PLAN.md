# Plan 11-02: Ship Lock-Aware Deck Switching And Full Unlock Restore

<objective>
Finish the Phase 11 user-visible behavior: the runtime becomes honestly lock-aware on the first supported host path, swaps to the right locked surface while the session is locked, and restores the user's exact prior navigation state when the session unlocks. A completed plan should be reviewable through a committed Phase 11 fixture and should degrade explicitly rather than pretending lock support exists everywhere. Timed dimming stays out of scope here because the roadmap already reserves that polish step for Phase 15.
</objective>

## Tasks

- packages/cli/src/core/schemas.ts
- packages/cli/src/config/loader.test.ts

</files>
<action>
Add a dedicated `packages/cli/src/system/session-monitor.ts` abstraction for the first supported lock-aware host path, using the canonical host-context session semantics from 11-01 instead of inventing a separate event model. Update `packages/cli/src/core/schemas.ts` so config can declare the approved top-level runtime/session locked-deck setting that references an ordinary deck. Preserve current validation style and line-number quality when the configured locked deck is missing or malformed. Wire startup in `packages/cli/src/cli/commands/start.ts` so supported hosts install the session monitor, unsupported hosts continue normally, and the logger emits the one-time warning required by context when lock-aware behavior is unavailable.

<task id="11-02-02">
<title>Implement locked-mode activation, implicit fallback surface, and full navigation restore</title>
<files>
- packages/cli/src/deck/controller.ts
- packages/cli/src/deck/runtime.ts
- packages/cli/src/deck/runtime.test.ts
</files>
<action>
Extend `packages/cli/src/deck/controller.ts` and `packages/cli/src/deck/runtime.ts` so lock mode becomes a temporary runtime-owned surface rather than a destructive deck switch. Snapshot the full pre-lock navigation stack before entering lock mode, keep any locked-surface navigation isolated from that saved state, and restore the full snapshot on unlock with a main-deck fallback only when no meaningful pre-lock state exists. Implement both locked-surface sources approved in context: a configured ordinary deck reference and an implicit built-in date/time fallback when config omits one. Expand `packages/cli/src/deck/runtime.test.ts` to cover supported lock/unlock transitions, configured locked deck switching, implicit fallback switching, isolated locked-mode navigation, and exact pre-lock restore.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/deck/runtime.test.ts`.
</verify>
<done>
The runtime can enter and leave lock mode without losing the user's prior deck context, and the default locked fallback remains useful even when no YAML locked deck is configured.
</done>
</task>

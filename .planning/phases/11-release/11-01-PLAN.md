# Phase 11 Plan 01: root README + per-addon READMEs

## Tasks

### Task 1: Repo-root `README.md`

- File: `/works/opensource/sireno-deck-2/README.md` (new)
- Sections:
  1. **Title + 1-paragraph "why"** — what sireno-deck-2 is, the Stream Deck CLI + emulator + addon system.
  2. **Quick start** — `pnpm install`, `pnpm --filter sireno-deck-2 dev start --emulator`, open the URL.
  3. **`config.yml` example** — a real, copy-pasteable 10-15 line snippet showing a deck with 5-6 button types (`core:time`, `core:date`, `core:weather`, `core:action`, `core:system-status`, `core:change-deck`).
  4. **CLI reference** — `sireno run --emulator`, `sireno start`, `sireno stop`, `sireno status`. Include `--help` output intent (the actual flags).
  5. **How it works** — short: `sireno` loads `config.yml`, validates, registers addons, spawns WS bridge + vite frontend, optionally drives emulator or hardware.
  6. **For addon authors** — link to each per-addon README + a pointer to `packages/cli/src/addon/api.ts`.
  7. **License** — MIT.
- Length: ~150-200 lines. No emojis (per repo conventions).

### Task 2: Trim `packages/cli/README.md`

- File: `packages/cli/README.md`
- Replace the "Phase 0 scaffold" stub with CLI-internal details:
  - Dev workflow (`pnpm --filter sireno-deck-2 dev`, `pnpm test`, `pnpm lint`, etc.)
  - Architecture overview (refer to root README for user-facing content).
  - Scripts reference.
- Length: ~30-50 lines. Don't duplicate the root README.

### Task 3: 10 per-addon READMEs

For each of the 10 addons below, create `packages/cli/src/builtin-addons/{addon}/README.md` with:
- **Title** + 1-paragraph "what it does"
- **Buttons** — table mapping `core:type` → description
- **Config** — copy-pasteable YAML example
- **Example** — full `config.yml` snippet using the addon
- **See also** — link to related addons

| Addon              | Buttons (count)                                                        |
| ------------------ | ---------------------------------------------------------------------- |
| core-buttons       | (internal-only — `core:change-deck`, `core:action`)                     |
| internal-settings  | `core:settings-brightness`, `core:settings-media`, `core:settings-volume` |
| session            | (system-managed; the `session:locked` deck)                            |
| date-time          | `core:date-time`, `core:time`, `core:date`, `core:clock`, `core:analog-clock`, `core:locked-time-tile` |
| emoji-selector     | `core:emoji-emoji-button`, `core:emoji-page-nav` (deck-driven)          |
| media-player       | `core:media-player`                                                    |
| system-status      | `core:system-status`                                                   |
| value-display      | `core:value-display`                                                   |
| weather            | `core:weather`                                                         |
| brightness         | `core:brightness`                                                       |

For `core-buttons` and `internal-settings` — mark them as internal-only (not for user config; they're invoked by the runtime or by `core:settings-entry`).

### Task 4: Verify per-addon READMEs against source

- Run `grep -l 'core:' packages/cli/src/builtin-addons/{addon}/index.ts` for each addon.
- Ensure each `core:*` type listed in the addon's `index.ts` appears in the README's Buttons table.
- If the README references a button that isn't in the source, remove it from the README.

### Task 5: Verify root README's `config.yml` example

- Extract the example from the root README.
- Run `pnpm exec tsx -e "import {loadConfig} from './packages/cli/src/config/loader.ts'; console.log(await loadConfig({configPath: '/tmp/test-config.yml'}));"` (or equivalent) with the example as input.

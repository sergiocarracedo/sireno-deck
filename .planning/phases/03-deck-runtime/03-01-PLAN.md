# Phase 03 Plan 01 — Core Primitives

## Context

Phase 03 lays the foundation of the deck runtime. Before we can wire deck navigation, gesture handlers, or any addon behavior, we need four small, pure modules that everything else depends on. This plan builds them.

The legacy (`/works/opensource/sireno-deck`) already has these modules. We port the behavior — but rewrite to fit sireno-deck's shape (smaller files, stricter types, no `react` imports in core/).

Modules:

1. **pub-sub** — typed channel bus. `publish`, `subscribe`, `last`, `snapshot`. Debounced snapshot emission (100ms) for the WS bridge.
2. **gesture-state** — given raw down/up events with timestamps, emit `tap | dbl-tap | hold`. No `press-then-release`. Uses `HOLD_ACTION_DELAY_MS = 600`, `DOUBLE_TAP_DELAY_MS = 200`.
3. **store** — scoped per-button key-value store. Two scopes: `addon` (shared across addon instances) and `button` (per-button instance). Methods: `get`, `set`, `update`, `clear`, `snapshot`.
4. **pagination** — chunk a list of buttons into pages of `keyCount - 2`. Pad with empty slots. Emit next-page metadata for slot `n-2`.

## Notes for executor

- Keep each module ≤ 100 lines. Split into helper files only if needed (e.g., `pagination/chunk.ts`).
- Gesture machine is **pure** — no side effects, no clock reads. Timestamps are inputs.
- Pub-sub's debounce uses `setTimeout` — flush callback must be cleared on `dispose()` to avoid leaks.
- Store scope keys: format `${scopeKind}:${addonName}:${buttonId ?? ''}:${key}`.
- Pagination: don't reuse the legacy `nextPage` button type — we'll register it in Plan 03.
- DO NOT add comments to source files unless they explain non-obvious behavior the user asked about.

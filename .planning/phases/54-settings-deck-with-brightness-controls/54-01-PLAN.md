# Plan 54-01: LogoVersion extraction + main-deck settings affordance

<objective>
This plan extracts the logo+version rendering into a shared `@/ui/LogoVersion` element (the same data and JSX that currently lives in `system-back-button.tsx`), then refactors `system-back-button.tsx` to use the shared element AND to add a new "settings" affordance on the main-deck branch (when an `onNavigateToSettings` prop is provided). The runtime (`packages/cli/src/deck/runtime.ts`) wires the prop. When the user has no `settings` deck (old configs), the prop is omitted and the main-deck reserved slot falls back to the v1.4 logo+version. The settings-deck rendering itself is plan 54-02 (the next wave).
</objective>

```tsx
import { readFileSync } from 'node:fs'
import { fileURLToPath } from 'node:url'
import type { ReactElement } from 'react'

import { Text } from './Text'

const LOGO_DATA_URL = `data:image/png;base64,${readFileSync(
  fileURLToPath(new URL('../assets/logo72x72.png', import.meta.url)),
).toString('base64')}`

const { version: CLI_VERSION } = JSON.parse(
  readFileSync(
    fileURLToPath(new URL('../../package.json', import.meta.url)),
    'utf8',
  ),
)

export { LOGO_DATA_URL, CLI_VERSION }

export function LogoVersion(): ReactElement {
  return (
    <div
      className="flex h-full w-full flex-col items-center justify-center gap-0.5"
      data-sireno-logo-version="true"
    >
      <img
        alt="Sireno Deck"
        className="shrink-0"
        src={LOGO_DATA_URL}
        style={{ height: 48, width: 48 }}
      />
      <Text size="xs" tone="foreground">
        v{CLI_VERSION}
      </Text>
    </div>
  )
}
```

The `../../package.json` path is also relative to `@/ui/` and resolves to `packages/cli/package.json`. Same caveat.

In `packages/cli/src/deck/runtime.ts`:

1. Find the existing `SystemBackButton` instance at the reserved slot. The `render: () => createElement(SystemBackButton, { isMainDeck: deckId === options.deck.id })` is around line 917-920.
2. Determine whether the `settings` deck is configured. The simplest check: the runtime's `options.decks` map has a key with `id === 'settings'`. Add a constant at the top of the file (next to `IMPLICIT_LOCKED_DECK_ID`):
   ```ts
   const SETTINGS_DECK_ID = 'settings'
   ```
   And inside `createDeckRuntime`, add a `hasSettingsDeck` boolean:
   ```ts
   const hasSettingsDeck = SETTINGS_DECK_ID in (options.decks ?? {})
   ```
3. Update the `SystemBackButton` instance:
   ```ts
   render: () =>
     createElement(SystemBackButton, {
       isMainDeck: deckId === options.deck.id,
       onNavigateToSettings: hasSettingsDeck
         ? () => {
             const previousDeckId = getDisplayDeckId()
             deckController.restoreStack([options.deck.id, SETTINGS_DECK_ID])
             void activateDeckSurface(SETTINGS_DECK_ID, previousDeckId).catch(reportRenderError)
           }
         : undefined,
     }),
   ```
   This is the same pattern the runtime uses elsewhere to navigate (compare with the lock-deck-restore code at line 1208). The `restoreStack` call replaces the stack with `[main, settings]` so the user goes back to main when they tap the back button on the settings deck. (Note: plan 54-02 will register the actual `settings` deck in `runtimeDecks`. For now, if a user has explicitly added a `settings` deck to their config, the navigation works; otherwise the affordance isn't shown.)

If `navigateToDeck` is available on the deck-controller or runtime methods (rather than a `restoreStack` + `activateDeckSurface` pattern), use that. Discover the exact API during execution by reading the existing navigation code paths (lines 839, 860, 900, 910, 1062, 1104 are all navigation examples).

Add a small `it("renders the settings affordance on the main deck and navigates to the settings deck when configured", ...)` test in `runtime.test.ts` that constructs a runtime with a `settings` deck in `options.decks`, navigates from main to settings via the affordance (asserting the active deck is `settings` after), and asserts the back button returns to main.

The test fixture may need a new minimal settings-deck file or a hand-constructed `DeckConfig` inline. The latter is simpler.

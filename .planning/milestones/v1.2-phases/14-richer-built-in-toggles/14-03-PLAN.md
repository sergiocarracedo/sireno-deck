<objective>

</objective>

<task id="14-03-02">
<title>Implement write-then-reconcile behavior for `toggle-status` mode</title>
<files>
- builtin-addons/core-buttons/src/index.ts
- builtin-addons/core-buttons/src/index.test.ts
- packages/cli/src/deck/runtime.ts
- packages/cli/src/deck/runtime.test.ts
</files>
<action>
Extend the bundled toggle instance so `toggle-status` mode behaves like a write-only mutation followed by an authoritative re-read. On activation and refresh, use `status_command` to derive the current truth exactly like the `get-set` branch derives truth from `get_state_command`. On tap, run `toggle_command`, mark the button pending, and immediately reconcile by running `status_command`; do not invert the previous runtime value locally. If `toggle_command` fails, preserve the last authoritative state and mark the button errored. If the follow-up status read fails or yields an unmapped token, preserve the last authoritative state but keep the button unavailable or errored until a later successful read. Pin this with focused addon and runtime tests that explicitly guard against local inversion.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/deck/runtime.test.ts ../../builtin-addons/core-buttons/src/index.test.ts`.
</verify>
<done>
The shipped `toggle-status` toggle behaves like an honest externally authoritative control instead of a guessed local flip.
</done>
</task>

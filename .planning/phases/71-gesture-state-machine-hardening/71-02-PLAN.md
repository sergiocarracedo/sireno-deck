# Plan 71-02: Strict double-tap semantics + dispatcher refactor (BUG-02)

## Context

BUG-02 is the user's strict-interpretation report: "When I double-tap a button that has no double-tap callback, it executes the normal tap callback and it should do nothing." The current code at runtime.ts:1735-1757 has an `else` branch on line 1757 that fires `handleTap` immediately when `instance.onDblTap` is undefined — meaning a second press within DOUBLE_TAP_DELAY_MS arrives *after* the first onTap has already fired. Per the user's spec, both presses should be suppressed and onTap should fire 0 times. The fix is to schedule onTap with `setTimeout(DOUBLE_TAP_DELAY_MS)` regardless of whether onDblTap is configured; if a second press arrives within the window, clear the timer and fire nothing. While we're here, we extract a `dispatchGestureEnd(state, callbacks)` helper that handles all three release cases (hold won / dbltap / strict no-dbltap) in one place and encapsulates the Phase 56 spread discipline (`{ ...gs, ...newFields }` on every `Map.set`) — that spread was added in Phase 56 after a regression where `gestureStates.set(key, { pendingDblTapTimer: timer })` dropped `holdTimer` and `holdTriggered`.

## Tasks

### Task 1: Create the gesture-state helper module

**file:** packages/cli/src/deck/gesture-state.ts (new)
**action:**
- Create `packages/cli/src/deck/gesture-state.ts` exporting:
  - `ButtonGestureState` type: `{ pendingDblTapTimer?: NodeJS.Timeout; holdTimer?: NodeJS.Timeout; holdTriggered?: boolean }`.
  - `DispatchGestureEndCallbacks` type: `{ onTap: () => Promise<void> | void; onDblTap?: () => Promise<void> | void; onHold?: () => Promise<void> | void; reportError: (err: unknown) => void; keyIndex: number }`.
  - `DOUBLE_TAP_DELAY_MS` — re-exported from the same constant runtime.ts already imports, so the magic number lives in one place.
  - `dispatchGestureEnd(state: ButtonGestureState | undefined, callbacks: DispatchGestureEndCallbacks, stateKey: string, gestureStates: Map<string, ButtonGestureState>): Promise<void>` — async function.
- Implementation of `dispatchGestureEnd` covers three cases in this order:
  1. **Hold won** (state.holdTriggered === true): delete the stateKey from gestureStates (no spread needed — full state reset), return without firing any callback. Hold has its own consumer flow.
  2. **Dbltap path** (callbacks.onDblTap is set AND state has pendingDblTapTimer): clear the pending timer, delete stateKey, await `callbacks.onDblTap()` wrapped in a try/catch that routes to `callbacks.reportError`.
  3. **Strict no-dbltap** (callbacks.onDblTap is undefined): schedule `callbacks.onTap()` via `setTimeout(DOUBLE_TAP_DELAY_MS)`. Store the timer in `gestureStates.set(stateKey, { ...state, pendingDblTapTimer: timer })` — using the spread. Return immediately (do not await the timer). The next call to `dispatchGestureEnd` for the same stateKey within the window will see `pendingDblTapTimer` and clear it without firing.
  4. **Dbltap debounce path** (callbacks.onDblTap is set AND no pendingDblTapTimer): schedule onTap with setTimeout, store timer with spread, return immediately.
- All `gestureStates.set` calls use `{ ...state, ...newFields }` to preserve the Phase 56 invariant.
**verify:** TypeScript compiles. Helper is importable from runtime.ts and the test file.
**done:** Helper module created with the 3 release cases + spread discipline.

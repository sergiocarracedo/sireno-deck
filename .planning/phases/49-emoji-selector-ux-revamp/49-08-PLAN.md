## Fix: Wayland-compatible simulatePaste in clipboard.ts

### Problem

`clipboard.ts simulatePaste()` always calls `xdotool key ctrl+v` on Linux.
`xdotool` only works on X11. On Wayland it silently fails — there's no X11
server to send keystrokes to. `clipboardy.write()` works fine (it auto-detects
wl-copy), but the paste keystroke goes nowhere.

Affected: tests 7 (tap emoji) and 8 (dbl-tap shortcode) on Wayland.

### Solution

1. Add `isWayland(): boolean` — checks `process.env.XDG_SESSION_TYPE === 'wayland'`
2. Add `detectPasteTool(): Promise<boolean>` — check for `ydotool` on Wayland, `xdotool` on X11; remove the hardcoded `xdotool` assumption
3. In `simulatePaste()` — branch on Wayland vs X11:
   - Wayland: `execa('ydotool', ['key', 'ctrl+v'])`
   - X11: `execa('xdotool', ['key', 'ctrl+v'])`
4. `ydotool` is the better default going forward since it works on both X11 and Wayland

### Files to change

- `packages/cli/src/util/clipboard.ts` — add `isWayland()`, branch `simulatePaste()` on session type, update `detectPasteTool()`

### Verification

- Write a new test in `clipboard.test.ts` that mocks `process.env.XDG_SESSION_TYPE = 'wayland'` and asserts `ydotool` is called
- Write a test that mocks X11 and asserts `xdotool` is called
- On a Wayland host: tap emoji → emoji appears in focused window
- On an X11 host: tap emoji → emoji appears in focused window (regression)

### Dependencies

- `ydotool` needs to be installed on Wayland hosts. The error message from `detectPasteTool()` should be updated to say: "ydotool (or xdotool on X11) is required for paste to work on Linux"
- On X11, `ydotool` also works — could simplify to just `ydotool` everywhere on Linux if preferred

### Out of scope

- `wtype` as an alternative (ydotool is the more general solution)
- Changing the clipboard write side (clipboardy already handles Wayland via wl-copy)

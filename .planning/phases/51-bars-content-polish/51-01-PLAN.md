# Plan 51-01: Bars component — in-bar value, negative color, near-gray fallback

<objective>
The shared `Bars` component (packages/cli/src/ui/Bars.tsx) currently renders a bar fill whose color is `item.color ?? 'var(--sireno-color-primary)'` and never renders the value as text. This plan adds three things: (1) a pure `negative-color` helper that computes the visual inverse of a hex color with a near-gray auto-contrast fallback, (2) a new optional `displayValue?: string` field on `BarsItem` for formatted strings, and (3) a value `Text` element rendered inside the bar fill, rotated 90 degrees, using `mix-blend-mode: difference` in the DOM path or a precomputed hex in the sharp path. After this plan, a `Bars` invocation with a `displayValue` shows the value as a rotated in-bar text on both render paths, and bars whose effective color is near gray fall back to a high-contrast color automatically.
</objective>

Create `packages/cli/src/ui/negative-color.ts` with the following exports (all pure functions, no React, no DOM, no imports beyond a type-only import if needed):

```ts
export interface Rgb { r: number; g: number; b: number }

export function parseHex(hex: string): Rgb | null
export function toHex(rgb: Rgb): string
export function luma(rgb: Rgb): number
export function computeNegativeColor(barColor: string, themePrimaryHex: string | null): string
```

Implementation rules:
- `parseHex(hex)` — accepts `'#RGB'` and `'#RRGGBB'` (case-insensitive). Whitespace tolerated via `.trim()`. Returns `Rgb | null`. Reject everything else (including `rgb(...)`, `hsl(...)`, named colors, CSS variables) by returning `null`.
- `toHex({ r, g, b })` — returns `'#RRGGBB'` with each channel padded to two hex digits and clamped to `[0, 255]` (defensive: callers pass computed values; in practice values stay in range).
- `luma({ r, g, b })` — returns `0.2126 * r + 0.7152 * g + 0.0722 * b`.
- `computeNegativeColor(barColor, themePrimaryHex)`:
  1. If `barColor` is empty or fails `parseHex`, AND `themePrimaryHex` is non-null and parses: use `themePrimaryHex` as the effective color.
  2. Otherwise if `barColor` parses: use `barColor`.
  3. Otherwise: return `'#ffffff'` (sharp-path static fallback).
  4. Compute luma of the effective color. If `Math.abs(luma - 128) < 32`: return `luma < 128 ? '#ffffff' : '#000000'`.
  5. Otherwise: return `toHex({ r: 255 - r, g: 255 - g, b: 255 - b })`.

Tests in `negative-color.test.ts` (use `describe` / `it` from vitest):
1. `parseHex('#7dd3fc')` → `{ r: 125, g: 211, b: 252 }`
2. `parseHex('#fff')` → `{ r: 255, g: 255, b: 255 }`
3. `parseHex('not-a-color')` → `null`
4. `parseHex('rgb(0,0,0)')` → `null` (we don't accept rgb syntax)
5. `parseHex('var(--sireno-color-primary)')` → `null` (CSS variable)
6. `luma({ r: 0, g: 0, b: 0 })` → `0`; `luma({ r: 255, g: 255, b: 255 })` → `255`
7. `computeNegativeColor('#7dd3fc', null)` → `'#822c03'` (per-channel complement)
8. `computeNegativeColor('#ffffff', null)` → `'#000000'` (white → black)
9. `computeNegativeColor('#808080', null)` → `'#ffffff'` (near-gray, luma = 128, falls back; bar darker than threshold means luma < 128, so the function returns `#ffffff`; but `#808080` has luma = 128, so `Math.abs(128 - 128) = 0 < 32` triggers the fallback. Edge: luma === 128 exactly, the ternary `luma < 128` is false, so returns `#000000`. Use `#7f7f7f` (luma = 127) instead to assert `#ffffff`; use `#808080` to assert `#000000`.)
10. `computeNegativeColor('#7f7f7f', null)` → `'#ffffff'` (just under threshold)
11. `computeNegativeColor('var(--sireno-color-primary)', '#7dd3fc')` → `'#822c03'` (theme primary fallback)
12. `computeNegativeColor('', '#2563eb')` → complement of `#2563eb` (empty string → fall through to theme)
13. `computeNegativeColor('', null)` → `'#ffffff'` (no resolvable color → static fallback)
14. `computeNegativeColor('not-a-color', null)` → `'#ffffff'`

Verify the luma math edge precisely: the bar color `#7f7f7f` (127, 127, 127) has luma 127, so `Math.abs(127 - 128) = 1 < 32` triggers the fallback, luma < 128 → `#ffffff`. The bar color `#808080` (128, 128, 128) has luma 128, so `Math.abs(128 - 128) = 0 < 32` triggers the fallback, luma < 128 is false → `#000000`. Document this in the test names so the assertion is unambiguous.

# 57-01 — Pipeline profile (RES-01)

> The back button has a perceived ~1s delay. The runtime hop chain is async, mounted-deck React, and goes through the browser capture loop. The Phase 57 research needs real measurements to point Phase 58 at the right fix.

## Context

Phase 57 decision (CONTEXT.md): **instrumented runs only**. Add pino debug logs at runtime.ts hop boundaries, run back-button scenario in emulator + real hardware if available, measure ms per hop. No static analysis, no CPU profile.

**Plan revised mid-execution:** original Task 1 (modify `runtime.ts` with `SIRENO_PROFILE=1` instrumentation) was reverted after the change accidentally broke `renderDeckSurface` default-parameter signature and polluted the test baseline. The plan now uses a **standalone profile script** (`packages/cli/scripts/profile-runtime.ts`) that drives the runtime directly:

- Imports `createDeckRuntime` from the package source
- Builds a minimal back-button scenario (main → sub-deck → back)
- Wraps each gesture hop with `process.hrtime.bigint()` timing
- Mocks `setBrightnessAll`, `keyMacroProvider`, `activeAppProvider` to avoid hardware deps
- Writes per-hop timings to `profile-emulator-back.txt`
- **No changes to `runtime.ts`**, no test regressions, research-grade code lives in a separate file

The runtime hop chain to profile (from CONTEXT.md):
`onKeyEvent` → `handlePress` → `handleRelease` → `handleTap` → `onTap` → `goBack` / `navigateToDeck` → `activateDeckSurface` → `renderDeckSurface` → `renderMountedDeckButtons` → `emitRenderedDeck`

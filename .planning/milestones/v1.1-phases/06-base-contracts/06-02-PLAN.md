# Plan 06-02: Live Digital Date-Time Contract

<objective>
Make the built-in digital `date-time` button behave like a real live widget by wiring validated cadence settings into the existing core runtime scheduler. This plan keeps scheduler ownership in core, honors the new `interval_ms` contract, and gives the date-time addon a default refresh interval so its rendered time actually updates without relying on incidental invalidation.
</objective>

## Tasks

<task id="06-02-01">
<title>Validate the Phase 6 `interval_ms` contract at config load time</title>
<files>
- packages/cli/src/core/schemas.ts
</files>
<action>
Update `packages/cli/src/core/schemas.ts` so `interval_ms` is validated as an explicit runtime contract with a minimum of `500ms`, producing the same path-aware `ConfigValidationError` style used elsewhere in config parsing. Keep this validation compatible with the current addon-backed button parsing flow, and do not bury the policy in runtime clamping or scheduler coercion.
</action>
<verify>

grep -n "500" packages/cli/src/core/schemas.ts
</verify>
<done>
Config validation fails early and explicitly for unsupported `interval_ms` values, preserving truthful configuration and the agreed minimum cadence policy.
</done>
</task>

<action>

<done>

</done>
</task>

# Plan 12-04: Compact logs

<objective>
Make operational logs compact (one line, stable inline context) and keep structured JSON available for system logging. Drop the noisy `buttonsInDeck` follow-up dumps from info; the debug path retains full detail.
</objective>

## Tasks

<task id="12-04-01">
<title>TTY-aware logger with messageFormat</title>
<files>
- packages/cli/src/util/logger.ts
- packages/cli/src/__tests__/logger-format.test.ts (new)
</files>
<action>
1. In `logger.ts`, locate `createLogger` (or equivalent). Add TTY detection: if `process.stdout.isTTY && !process.env.INVOCATION_ID && !process.env.LAUNCH_PATH`, attach `pino-pretty` with options `{ colorize: true, singleLine: true, ignore: 'pid,hostname,time,level', translateTime: 'HH:MM:SS', messageFormat: '{msg} ({context})' }`. Otherwise emit raw ndjson.
2. The `messageFormat` template reads `log.bindings()` (which pino populates with the merged context) and prints `key: value` pairs comma-separated. For zero context, print `''` (no parens).
3. Add a `// ponytail: messageFormat collapses context into one line; structured fields still queryable via ndjson` comment.
4. Add tests in `logger-format.test.ts`:
   - With mocked TTY + no env vars, the transport is `pino-pretty` with the right options.
   - With `INVOCATION_ID` set, no transport; output is raw ndjson (verify by inspecting the pino instance options).
   - Without TTY, no transport.
</action>
<verify>
`pnpm --filter @sireno-deck/cli exec vitest run packages/cli/src/__tests__/logger-format.test.ts` passes.
</verify>
<done>
TTY-aware logger produces the compact one-line format in dev and ndjson in service mode.
</done>
</task>

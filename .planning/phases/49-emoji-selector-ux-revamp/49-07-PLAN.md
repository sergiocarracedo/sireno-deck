## Context

CONTEXT amendment A2 (2026-06-06) calls for an internal core utility that owns the paged-category pattern. The current implementation is emoji-specific:

- `buildPageNavButton(isFirstPage, isLastPage, prevDeckId, nextDeckId, currentDeckId)` lives inline in `packages/cli/src/builtin-addons/emoji-selector/index.ts:28-45` and returns a `change-deck` button config with `meta: 'page-nav'`. The position is hardcoded to `EMOJI_KEY_COUNT - 2`.
- `emojiCategoryButton` in `packages/cli/src/builtin-addons/emoji-selector/buttons/category.tsx` is a thin `defineMountedButton` that calls `navigateToDeck(config.target_deck)` on tap. It is the button that appears in the emoji main deck for each category tile.
- The page-nav render in `packages/cli/src/builtin-addons/core-buttons/buttons/change-deck.tsx:15-41` uses raw `text-[10px] opacity-70` divs for the "Tap" / "Dbl Tap" overlays, NOT the actual `Chip` component (`packages/cli/src/ui/Chip.tsx`) — a fidelity gap that A2's "Chip overlays" wording is calling out.

The new utility sits at `packages/cli/src/core/pagination.ts` (internal, not in the public addon API). It exports three helpers:

- `buildPageNavButton(currentPage, totalPages, prevDeckId, nextDeckId, options?: { keyCount?: number })` — the per-page n-2 button config; tap and double-tap both pass `addToHistory: false` (per A3).
- `definePagedCategoryButton({...config})` — high-level helper returning a `defineMountedButton` for a category tile in the main deck; tap navigates to the first page of the category with `addToHistory: true` (so back from the first page returns to the parent deck).
- `paginateDecks({...})` — generator that produces the per-page deck IDs given a base ID, page size, and total count.

The `Chip` migration (raw divs → actual `Chip` component) stays inside the `change-deck.tsx` seam per the `bespoke-live-visuals-can-stay-inside-the-deck-button-variant-seam-2026-05-15` solution (do not widen the renderer).

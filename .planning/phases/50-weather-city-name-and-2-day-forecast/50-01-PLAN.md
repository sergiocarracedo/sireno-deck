# Plan 50-01: City-name location with geocoding and locating state

<objective>
A weather button configured with `location: "Vigo, Spain"` shows the correct weather data on first render, and a button configured with an unknown city name shows a clear "Location not found" state — no silent fallback to IP geolocation. This plan adds the Open-Meteo Geocoding seam (with bounded LRU cache + single-flight), updates the schema to accept either a string or the existing lat/lon object, and replaces the snapshot's `available: boolean` with a tri-state `status: 'locating' | 'available' | 'unavailable'` so the UI can show a "Locating…" tile during geocoding.
</objective>

Create a new module at `packages/cli/src/builtin-addons/weather/domain/geocoder.ts` exporting:

```ts
export interface GeocoderResult {
  latitude: number
  longitude: number
  name: string       // resolved display name (e.g. "Vigo")
  country: string    // resolved country (e.g. "Spain")
  timezone: string   // IANA timezone from Open-Meteo response
}

export async function searchCity(
  query: string,
  options?: { signal?: AbortSignal },
): Promise<GeocoderResult | null>
```

Implementation:
- Singleton state: `let cache: Map<string, GeocoderResult | null>` and `let inflight: Map<string, Promise<GeocoderResult | null>>`. Normalize the cache key as `query.trim().toLowerCase()`. Both Maps are module-private.
- On `searchCity(query, options)`:
  1. If `query.trim()` is empty, return `null` (synchronously, no fetch).
  2. Normalize key. If `cache.has(key)`, return `cache.get(key)!.` (note: a cached `null` is a valid "not found" hit).
  3. If `inflight.has(key)`, return `inflight.get(key)!.`
  4. Otherwise build the fetch: `https://geocoding-api.open-meteo.com/v1/search?name=${encodeURIComponent(query.trim())}&count=10&language=en&format=json`. Use `AbortSignal.any([options?.signal, AbortSignal.timeout(5000)])` so a passed-in signal and a 5s timeout both work.
  5. POST the fetch and `await response.json()`. On `!response.ok` or any thrown error, return `null` and do NOT cache (the next call retries).
  6. On a 200 with `json.results` non-empty: pick the best result (see smart-match below), build a `GeocoderResult`, store in `cache` and return it.
  7. On a 200 with empty `results` or no `results` field: cache `null` for the key, return `null`.
  8. Delete the inflight entry in a `finally` block.

Smart-match algorithm (handles `Vigo, Spain` style queries):
- Split the query on commas → parts. If exactly 2 parts and the second part has length ≥ 2 (e.g. "Spain", "ES", "Galicia"), treat the second as a country/admin filter.
- For each `r` in `json.results`, compute `matchScore(r, countryFilter)`:
  - `country` exact (case-insensitive) match → 100
  - `admin1` exact (case-insensitive) match → 60
  - `country_code` exact (case-insensitive, trimmed) match → 80
  - otherwise 0
- If a countryFilter is present and any result has score ≥ 60, pick the highest-scoring one. If a countryFilter is present but no result scores ≥ 60, return `null` (the user asked for a specific country/admin, none matched).
- If no countryFilter, pick `json.results[0]`.

Build the `GeocoderResult` from the picked result: `latitude`, `longitude` (rounded to 4 decimals via `Math.round(x * 1e4) / 1e4`), `name` = result.name, `country` = result.country, `timezone` = result.timezone.

Cache cap: keep a separate `insertionOrder: string[]` array. On every successful insert to `cache`, push the key. If `cache.size > 1000`, evict the oldest key: read `insertionOrder[0]`, delete from `cache`, `inflight`, and shift the array.

Expose the following for tests: a `_resetForTests()` named export that clears `cache`, `inflight`, and `insertionOrder`.

Tests (`geocoder.test.ts`) using `vi.fn` for `fetch`:
- Cache miss → fetch called once → result returned
- Cache hit → fetch not called second time
- Concurrent calls for same key → fetch called once, both promises resolve to the same value
- Empty query → returns `null` synchronously, no fetch
- Network 500 → returns `null`, no cache write
- Empty `results` array → returns `null`, caches `null`
- `Vigo, Spain` style query → fetches `?name=Vigo%2C+Spain` and picks the result with `country === 'Spain'`
- `Vigo, ES` style query → picks the result with `country_code === 'ES'`
- `Vigo, Galicia` style query → picks the result with `admin1 === 'Galicia'`
- `Vigo, Mars` (no match) → returns `null` (country filter rejected all results)
- LRU eviction: insert 1001 distinct keys, confirm oldest key is gone
- AbortSignal.timeout fires → fetch rejected, function returns `null`
</action>

async function resolveLocation(
  config: WeatherButtonConfig,
  options?: { signal?: AbortSignal },
): Promise<WeatherLocation | null> {
  if (typeof config.location === 'string') {
    const result = await searchCity(config.location, options)
    if (!result) return null
    return {
      kind: 'name',
      latitude: result.latitude,
      longitude: result.longitude,
      name: result.name,
      country: result.country,
      timezone: result.timezone,
    }
  }
  if (config.location) {
    return {
      kind: 'coords',
      latitude: config.location.latitude,
      longitude: config.location.longitude,
      name: config.location.name ?? '',
    }
  }
  // No location at all and no IP fallback: the CONTEXT decision is to NOT
  // silently fall back to IP geolocation when the user gave us a string.
  return null
}

# Phase 07 Plan 02 — Runtime integration

## Context

The Plan 01 providers are pure data sources. This plan makes them useful: the runtime polls the active-app provider, applies glob matching to each deck's `process_names`, and switches the active overlay deck on match. Also wires the providers into `preflight` so the CLI's `run` command instantiates them with platform dispatch from CONTEXT.md.

The glob matcher is new: it converts `process_names` entries (substr match + `*` wildcards + `|` alternation, case-insensitive) to a regex and tests against the active app's name or window title.

<action>Pure function `matchesPattern(name: string, pattern: string): boolean`. Rules:
- Case-insensitive: lowercase both sides.
- Substring: if pattern has no glob chars, return `name.includes(pattern)`.

- Use `picomatch` for the wildcard handling OR write a small regex translator. Pick whichever is fewer LoC; `picomatch` is a transitive dep already.
- Match against `name` (returns true) OR if the pattern has a `*` suffix, also match against `name + ' ' + windowTitle` (so `chrome*` matches the whole window title).
Export a second helper `compileDeckMatcher(patterns: string[]): (snapshot: ActiveAppSnapshot) => boolean` that returns a predicate.</action>

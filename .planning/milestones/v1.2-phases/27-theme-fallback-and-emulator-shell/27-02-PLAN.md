# Plan 27-02: Gate Shell Chrome To Emulator Mode And Make TSX Runtime Honest

<objective>
Keep one browser-renderer product but stop painting emulator polish everywhere: emulator-served deck HTML keeps the glass/chrome treatment, while non-emulator browser output stays on the same document contract without emulator-specific shell styling. In the same slice, remove manual React-import crutches from runtime-authored TSX files and prove the actual `tsx` execution seams still work.
</objective>

## Tasks

<task id="27-02-01">
<title>Thread explicit emulator render intent through the shared deck renderer and drop unused manual React imports from runtime TSX files</title>
<files>
- packages/cli/src/render/dom-host.tsx
- packages/cli/src/cli/commands/start.ts
- packages/cli/src/themes/default/ButtonFrame.tsx
</files>
<action>
Extend `packages/cli/src/render/dom-host.tsx` so `DomHostRenderOptions` carries an explicit emulator-mode flag and gate the deck-shell gradients, inset shadows, well highlights, and any other emulator-specific chrome off that flag while preserving the same `data-sireno-browser-shell`, key-slot, inline-warning, and layout structure. Update `packages/cli/src/cli/commands/start.ts` so emulator-served deck HTML passes emulator mode and non-emulator browser capture does not, without introducing a second `renderDomDeck(...)` implementation. Remove manual `import React from 'react'` boilerplate from runtime-authored TSX files touched by this slice when the import is otherwise unused, relying on the package's automatic JSX policy instead of compatibility imports.
</action>
<verify>

</verify>
<done>
The shared deck document can render with or without emulator-only chrome based on explicit intent, and the touched TSX runtime files no longer depend on manual React imports for JSX alone.
</done>
</task>

<must_haves>
- Do not move shell-chrome responsibility into theme `buttonFrame`; Phase 27 keeps per-button chrome and deck-document chrome separate.
- Keep the real runtime policy honest: if a touched TSX file still needs a React import, it must be because it uses a real React export, not because JSX would otherwise fail.
- The slice must preserve one shared deck document seam for browser capture and emulator serving.
</must_haves>

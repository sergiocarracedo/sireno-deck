# Plan 16-01: Expand Deck File References Through The Existing Loader Contract

<objective>
Ship the narrow include mechanism first: config authors can replace an inline deck entry with `@path/to/deck.yml`, and the loader resolves that referenced file into the same strict config pipeline the repo already trusts. A completed plan should prove that deck refs feel like ordinary deck config split across files, not like a second-class import system with weaker validation.
</objective>

## Tasks

<task id="16-01-01">
<title>Add deck-only file reference expansion to the config loader</title>
<files>
- packages/cli/src/config/loader.ts
- packages/cli/src/core/schemas.ts
</files>
<action>
Extend the config loader so `decks.<id>` values may be written as `@path/to/deck.yml`. Keep the feature intentionally narrow: only deck map entries participate, referenced files must parse to full ordinary deck objects, absolute paths are allowed, and relative paths resolve from the YAML file that owns the reference. Run this expansion before bootstrap/full schema validation so the existing deck and button contracts stay authoritative instead of being duplicated in a parallel include path.
</action>
<verify>
Run `grep -n "@path\|decks" packages/cli/src/config/loader.ts && grep -n "Main deck\|Deck id" packages/cli/src/core/schemas.ts`.
</verify>
<done>
The loader can expand deck refs into the ordinary config shape without widening config includes beyond the `decks` map.
</done>
</task>

<must_haves>

- Loader errors from referenced files point people at the actual failing file instead of collapsing everything back to the root config.
</must_haves>

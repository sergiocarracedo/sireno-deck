# Plan 62-01 — Overlay autoShow (schema + 2-line back + dbltap summon)

## Goal

When a deck has `autoShow: false` and its `process_names` match the active app, the overlay is **not** auto-displayed. Instead, the system back button in the base deck's last position renders a 2-line variant (line 1: back icon + "Tap", line 2: overlay deck icon + "2xTap"). Double-tapping the back button summons the matching overlay deck.

## CONTEXT decisions honored

- `autoShow` defaults to `false` (breaking change; aligns with REQUIREMENTS.md:16)
- Addons CAN set `autoShow`; two-stage plumbing (RawDeckSchema + AddonGeneratedDeck + both merge sites)
- Dbltap summons the **live-matching** deck (re-call `findActiveAppDeckFor` at dbltap time)
- 2-line variant **tracks live match** (icon + name re-render on active-app change)
- Bespoke layout (clone `OverlayToggleButton` flex-col structure; do NOT extend `MainLabelSurface`)
- Icon size 16, Text size xs, gap-0.5
- `summonOverlay(deckId)` is a private helper
- Phase 62 includes the fix for 5 pre-existing `system-back-injection.test.ts` failures

### Task 5 — Fix `shouldInjectSystemBack` (5 pre-existing broken tests) [REQ: ACTIVEAPP-07a, side-fix]

**Files:** `packages/cli/src/deck/system-back-injection.ts`, `packages/cli/src/deck/__tests__/system-back-injection.test.ts`
**Action:** The current implementation is `deck.id !== 'main' && sessionState !== 'locked'` (line 11). The 5 broken tests require:
- Test 2: `config.allow_reserved_slot_override === true` → return `false` (root-level)
- Test 3: `deck.allow_reserved_slot_override === true` → return `false` (deck-level)
- Test 4: deck is the session's `locked_deck` AND `sessionState === 'locked'` → return `false` (lock-session on subdeck)
- Test 5: a user button at position `deck.keyCount - 1` → return `false` (user claims reserved slot)
- Test 6: `deck.id === 'main'` → return `true` (home indicator renders)

Corrected implementation:
```ts
function shouldInjectSystemBack(
  deck: DeckConfig,
  config: SirenoConfig,
  sessionState: HostSessionState,
): boolean {
  if (config.allow_reserved_slot_override === true) return false
  if (deck.allow_reserved_slot_override === true) return false
  const lockedDeckId = config.session?.locked_deck
  if (lockedDeckId !== undefined && deck.id === lockedDeckId && sessionState === 'locked') return false
  const reservedPosition = (deck.buttons?.length ?? 0) > 0 ? deck.keyCount - 1 : -1
  if (reservedPosition >= 0 && (deck.buttons ?? []).some((b) => b.position === reservedPosition)) {
    return false
  }
  return true
}
```

The `keyCount` and `allow_reserved_slot_override` access requires the type additions from Task 1+2. Tests should pass as-is (their `makeDeck` already sets `keyCount: 15`).
**Verify:** `pnpm vitest run src/deck/__tests__/system-back-injection.test.ts` — all 8 tests pass (5 fixed, 3 already passing).

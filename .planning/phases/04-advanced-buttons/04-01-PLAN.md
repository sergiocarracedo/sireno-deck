# Plan 04-01: Toggle buttons with active-deck polling

<objective>
Deliver the first Phase 4 user-facing behavior end-to-end: toggle buttons that work both with internal state and with authoritative external state. This plan also fixes the current runtime polling lifecycle bug by making polling follow deck activation, because external toggles are not real without that behavior.
</objective>

## Tasks

<task id="04-01-01">
<title>Add shared toggle schema and example config coverage</title>
<files>
- config.yml
- packages/cli/src/core/schemas.ts
</files>
<action>
Extend `packages/cli/src/core/schemas.ts` with a built-in `toggle` button schema that supports the locked Phase 4 contract: a shared `states[]` array, explicit `key` per state, per-state display fields, per-state `command`, and optional `status_command` for external-state toggles. Validate that internal toggles have at least two states, that state keys are unique within a button, and that external toggles can only resolve to declared state keys. Update `config.yml` with at least one internal toggle example and one external toggle example that matches the approved command-output contract.
</action>
<verify>
grep 'type: z.literal("toggle")' packages/cli/src/core/schemas.ts && grep 'status_command' packages/cli/src/core/schemas.ts && grep 'type: toggle' config.yml
</verify>
<done>
The config layer accepts the full toggle shape needed for BTN-04 and BTN-05, and the example config demonstrates both internal and external toggle variants.
</done>
</task>

<task id="04-01-02">
<title>Implement toggle runtime behavior and active-deck-aware polling</title>
<files>
- packages/cli/src/deck/runtime.ts
- packages/cli/src/render/reconciler.ts
- packages/cli/src/render/text-image.ts
</files>
<action>
Refactor `packages/cli/src/deck/runtime.ts` so polling lifecycle is tied to the active deck instead of startup-only initialization. Add the smallest runtime state expansion needed to support toggle state keys, external status refresh, and per-state render data. Internal toggles must advance to the next state first and then run the newly active state's command. External toggles must show transient tap feedback if needed but keep display state authoritative from `status_command` polling. Update `packages/cli/src/render/reconciler.ts` and `packages/cli/src/render/text-image.ts` only as needed so toggles can render per-state visuals without encoding everything into one label string.
</action>
<verify>
grep 'status_command' packages/cli/src/deck/runtime.ts && grep 'activateCurrentDeck' packages/cli/src/deck/runtime.ts && grep 'toggle' packages/cli/src/render/text-image.ts
</verify>
<done>
Toggle buttons work end-to-end, and the runtime now polls only the active deck so external-state buttons stay accurate after deck navigation.
</done>
</task>

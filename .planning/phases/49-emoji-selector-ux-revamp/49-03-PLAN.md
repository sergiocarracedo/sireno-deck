## Context

CONTEXT.md locked:
- Single `n-2` button reusing `change-deck` with `commands.tap` (next) + `commands.double-tap` (prev)
- Two `Chip` overlays: "Tap" (top-left) and "Dbl Tap" (bottom-right)
- Layout: 12 emojis (0-11) + empty 12 + n-2 page nav (13) + system back (14)
- Addon-decorated system back: new optional `system_back_tap_command` and `system_back_hold_command` deck config fields
- Runtime honors the decoration by reading the active deck's config and routing tap/hold through `runCommand` when present, default behavior unchanged otherwise

This plan extends `change-deck` to accept the `commands` field, adds the page-nav button render, adds the new deck config fields, and wires the system back to honor them.

### 49-03-01: Extend change-deck to accept the commands field

- **file**: `packages/cli/src/builtin-addons/core-buttons/buttons/change-deck.tsx`
- **action**: Add an optional `commands: z.object({ tap: z.string().min(1).optional(), hold: z.string().min(1).optional(), 'double-tap': z.string().min(1).optional() }).optional()` field to `BuiltinChangeDeckButtonSchema`. The `onTap` handler is unchanged for the simple case (navigates to `target_deck`).   - `commands.hold` runs on hold (≥600ms); the default hold behavior is a no-op.

- **done**: `change-deck` schema accepts `commands`; runtime wires the three gestures.

# Plan 55-02: Runtime overlay state + dismiss gestures + system-buttons dispatcher unification + duplicate warnings

<objective>
On top of the foundation from 55-01 (the `system: true` flag, the `INTERNAL_DECKS` map, the clean dispatcher, and the `ActiveAppMonitor` / `ActiveAppProvider`), this plan delivers the actual user-facing active-app overlay behavior:

1. The runtime subscribes to the active-app monitor at startup and reacts to owner-name changes.
2. When a process matches a declared `process_names` entry, the matching deck is shown overlaid; the overlay has its own page history and never touches the base stack.
3. The reserved-slot button on an overlay deck is the "Base" dismiss toggle.
4. Double-tapping the system back button on a base deck dismisses the overlay.
5. The settings deck (already an internal deck) is reachable from the main deck; hold-back from settings while an overlay is active returns to the overlay.
6. The `Esc`/`q` keyboard escape still works while an overlay is active.
7. Two addons declaring the same `process_name` log a startup warning (first match wins).
8. The dispatcher is extended so the main deck's reserved slot is a settings button (not a back button — main decks never get a back button anyway), the overlay deck's reserved slot is a dismiss toggle, and other internal/user sub-decks get the standard back button.

This is the user-facing delivery plan — when 55-02 is done, all 6 ACTIVEAPP-* requirements are satisfied and the v1.5 active-app feature is demoable end-to-end.
</objective>

```ts
function buildActiveAppDeckIndex(
  addonDecks: ReadonlyMap<string, AddonGeneratedDeck>,
  logger: Logger,
): Map<string, string> {
  const index = new Map<string, string>()
  for (const [addonName, deck] of addonDecks) {
    for (const name of deck.process_names ?? []) {
      const key = name.toLowerCase().trim()
      if (!key) continue
      if (index.has(key)) {
        logger.warn(
          { process: key, addon: addonName, winner: index.get(key) },
          `process '${key}' is declared by both '${addonName}' and '${index.get(key)}'; using '${index.get(key)}'`,
        )
        continue
      }
      index.set(key, deck.id)
    }
  }
  return index
}
```

(The addon decks come from the addon registry — pass them in as an option like `options.addonDecks: Map<string, AddonGeneratedDeck>`; the start command will populate this in a later task.)

4. In the runtime, after addon decks are loaded and the deck controller is up, subscribe to the monitor:
```ts
async function startActiveAppMonitor() {
  const provider = await getActiveAppProvider()
  const monitor = createActiveAppMonitor({
    provider,
    onChange: (snapshot) => {
      const ownerName = snapshot?.ownerName ?? ''
      const match = findMatchingProcess(ownerName, activeAppDecksByProcess)
      if (match && match !== overlayDeckId) {
        activateOverlay(match)
      } else if (!match && overlayDeckId !== null) {
        dismissOverlay()
      }
    },
  })
  monitor.start()
  activeAppMonitor = monitor
}

function findMatchingProcess(
  ownerName: string,
  index: Map<string, string>,
): string | null {
  const normalized = ownerName.toLowerCase()
  for (const [key, deckId] of index) {
    if (normalized.includes(key)) return deckId
  }
  return null
}
```

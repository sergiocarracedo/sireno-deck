# Plan 20-02: Shared Asset Pipeline for Theme and Addon Packages

<objective>
Carry Phase 20 past the theme-frame tracer bullet and fix the broader asset contract that the phase explicitly scoped. This slice introduces one package-root-aware asset pipeline for theme CSS/fonts and addon/config-authored images, preserving normal CSS-relative `url(...)` behavior and proving the result on a shipped browser/device fixture instead of hiding the fix inside emoji-selector alone.
</objective>

## Tasks

<task id="20-02-01">
<title>Introduce package-root-aware asset registries for themes and addons</title>
<files>
- packages/cli/src/config/theme.ts
- packages/cli/src/config/theme.test.ts
- packages/cli/src/addon/registry.ts
- packages/cli/src/addon/registry.test.ts
- packages/cli/src/addon/loader.ts
- packages/cli/src/addon/loader.test.ts
- packages/cli/src/core/schemas.ts
- packages/cli/src/config/loader.ts
</files>
<action>
Extend the existing addon registry and config/theme loader seams so both addons and themes can register assets relative to their package roots with explicit manifest ownership. Preserve the current `addon://...` config resolution path, but refactor it so the same underlying resolver can support manifest-declared theme assets and return path-aware failures when assets are missing. Keep config-authored asset expansion in the validation/load path rather than deferring unresolved strings into rendering.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/addon/registry.test.ts src/addon/loader.test.ts src/config/theme.test.ts src/config/loader.test.ts` and confirm missing asset references fail explicitly instead of silently returning raw unresolved strings where the new contract should resolve them.
</verify>
<done>
Theme and addon packages share one explicit asset-resolution model rooted at package manifests, and config-time asset expansion still happens before rendering begins.
</done>
</task>

<task id="20-02-02">
<title>Preserve CSS-relative asset and font behavior on the browser host</title>
<files>
- packages/cli/src/config/theme.ts
- packages/cli/src/render/dom-host.tsx
- packages/cli/src/render/dom-host.test.tsx
</files>
<action>
Teach the theme loader/browser host path to ingest manifest-declared CSS assets and rewrite their `url(...)` references relative to the CSS file location before injecting styles into the browser deck document. Support bundled font files through normal `@font-face` CSS so theme-owned typography does not rely on host-installed fonts for visible differences. If a CSS-relative asset target cannot be resolved, raise a clear path-aware error instead of silently rendering degraded browser output.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/config/theme.test.ts src/render/dom-host.test.tsx` and confirm the rendered deck HTML contains rewritten/injected theme CSS plus font-face-backed typography assets sourced from the theme package.
</verify>
<done>
Packaged theme CSS and fonts survive browser-host injection with correct relative asset resolution, and broken references fail loudly.
</done>
</task>

# Plan 14-01: Ship Internal Toggle Mode End-To-End

<objective>
Deliver the first Phase 14 tracer bullet as one demoable user-facing behavior: a user can declare one built-in `toggle` button in `internal` mode, tap it to switch between on/off states, navigate away and back or survive reconnect without losing that runtime-owned state, and visually distinguish that mode on the real shipped toggle card path.
</objective>

## Tasks

<task id="14-01-01">
<title>Add the single-type toggle config contract and bundled internal-mode definition</title>
<files>
- packages/cli/src/core/schemas.ts
- packages/cli/src/config/loader.test.ts
- builtin-addons/core-buttons/src/index.ts
- builtin-addons/core-buttons/src/index.test.ts
</files>
<action>
Add one built-in `toggle` button contract to `packages/cli/src/core/schemas.ts` using a discriminated `mode` branch instead of separate button types. For this plan, implement the `internal` branch with these exact fields: required `mode: "internal"`, optional `initial_state: "on" | "off"` defaulting to `"off"`, optional shared presentation fields, and optional `on` / `off` override objects containing `label`, `subtitle`, and `icon`. Reject command-only fields on the internal branch so bad config fails with the existing path-aware loader diagnostics. Then add the bundled `toggle` definition to `builtin-addons/core-buttons/src/index.ts` and pin the public-contract surface in loader and addon tests.
</action>
<verify>
Run `pnpm --filter sireno-deck-cli exec vitest run src/config/loader.test.ts ../../builtin-addons/core-buttons/src/index.test.ts`.
</verify>
<done>
The repo loads a bundled `toggle` button definition and validates `internal` toggle config through one explicit discriminated schema branch.
</done>
</task>

<action>
Implement the bundled internal toggle instance so it owns its current on/off state in-process, flips on `onTap`, renders through `deck-button` with `variant: "toggle"`, and emits a narrow mode signal such as `toggle_mode: "internal"` so the renderer can apply an internal-mode accent while staying inside the existing toggle card family. Keep the visual difference restrained: shared base layout, mode-specific badge/chrome treatment only. In runtime tests, pin the Phase 14 lifecycle rule explicitly: navigating away from the active deck, re-activating it, and reconnecting the device within the same daemon must not clear internal toggle state. Do not add durable persistence across fresh process restarts.
</action>

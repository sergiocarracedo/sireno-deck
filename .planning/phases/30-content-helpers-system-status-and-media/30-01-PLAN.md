# Plan 30-01: Publish The Shared Helper Components

<objective>
Start Phase 30 by landing the smallest end-to-end proof the user asked for: shared content helpers that bundled and external addons can import and render directly. This slice matters first because both later built-in addon families depend on these layouts, and the phase discussion explicitly locked them to a public component-first TSX surface rather than helper factories or a config registry.
</objective>

## Tasks

<task id="30-01-01">
<title>Add bounded public `Bars` and `LabelValueList` components to the shared UI surface</title>
<files>
- packages/cli/src/ui/Bars.tsx
- packages/cli/src/ui/LabelValueList.tsx
- packages/cli/src/ui/index.ts
- packages/cli/src/index.ts
</files>
<action>
Create `packages/cli/src/ui/Bars.tsx` and `packages/cli/src/ui/LabelValueList.tsx` as public TSX helpers that deepen the existing shared component surface next to `Text`, `Icon`, and `Chip`. Keep them bounded to the locked Phase 30 contract: `Bars` supports exactly 1-3 items with title, color, value, and max value inputs; `LabelValueList` supports exactly 1-4 lines with icon, label, formatted value string, units, and color inputs, and it must choose the one-line, two-line, or three-to-four-line presentation automatically from `lines.length`. Do not add formatting logic, layout override props, or a helper factory seam. Export both helpers and their public prop types from `packages/cli/src/ui/index.ts` and `packages/cli/src/index.ts` so external addons can import them from the main package surface.
</action>
<verify>
Run `grep -n "export .*Bars\|export .*LabelValueList" packages/cli/src/ui/index.ts packages/cli/src/index.ts && grep -n "1-3\|1-4\|length" packages/cli/src/ui/Bars.tsx packages/cli/src/ui/LabelValueList.tsx`.
</verify>
<done>
Addon authors have a truthful public import path for the two helper components, and the helpers stay within the count/layout boundaries locked in Phase 30 context.
</done>
</task>

<must_haves>
- Do not hide value formatting inside the helpers; callers and built-ins own formatting policy.
- Do not add an explicit layout-override prop that bypasses the locked auto-layout decision for `LabelValueList`.
- Keep the helper surface reviewable as normal TSX components rather than introducing a helper registry or renderer primitive.
</must_haves>

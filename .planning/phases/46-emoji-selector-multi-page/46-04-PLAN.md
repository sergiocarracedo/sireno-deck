## Context

UAT test 2 reported that position 14 on category decks (subdecks) is empty — no back button visible. Investigation confirmed this is a **pre-existing SRB system gap**, NOT introduced by Phase 46:

- `packages/cli/src/deck/system-back-injection.ts` exports `shouldInjectSystemBack` and `getSystemBackButtonInstance`, but they are **never imported by `runtime.ts`**. They are referenced only in their own unit tests.
- `packages/cli/src/deck/system-back-button.tsx` exports a `SystemBackButton` React component, also **only used in its own unit tests**.
- `runtime.ts:364` defines `getDeckButtons(deck)` as `return deck.buttons` — a pure pass-through with no injection at the reserved slot. `reservedBackKeyIndex` (line 277) is computed and exposed via `getReservedBackKeyIndex()` (line 1219), but never used to inject a button.

So SRB-03 (subdecks have a core-owned back button at the reserved slot) is half-wired: validation rejects addon-claimed reserved slots, but the injection half is missing. The reserved slot is just empty.

**Scope note:** This is a pre-existing bug from the SRB phase, not a Phase 46 regression. We're fixing it now because the emoji-selector UAT surfaced it, and the v1.4 milestone ships incomplete without it.
